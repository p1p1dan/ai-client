预览：DSH 全自动档的审核模型，各状态在界面上的样子

对应 决策 192。管理员在登录服务里指定了审核模型后，全自动档下原本要弹卡的调用（删除、强推、工作区外路径、run_code 这类程序工具）先交给审核模型：放行就执行；不放行或审核失败就拒绝，并把理由告诉模型，让它换办法；连续 3 次或累计 20 次没放行后，下一次改为弹卡问你。

  • 每一节上方的单选切换方案，推荐的标在名字后面；切换后下面的界面和取舍说明一起变。
  • 用的是应用里的真实颜色、字号和圆角；对话内容是举例。看完告诉我每节选哪个（或要改哪里）。

1　审核中（通常几秒，最长 120 秒）

场景：你让模型「修一下打包脚本」，它要运行 rm -rf dist/。这条命令先交给审核模型，审核期间还没有执行。

A：看得出这条命令在等审核、还没执行，也看得出等了多久；代价是工具行多一种状态。 B：工具行等审核完才出现，界面更干净；但几秒到两分钟里只看到顶部一行，看不出在审哪条命令。 C：完全不用改界面；但「运行中」是错的——命令其实还没执行，审核不放行时会显得像「跑了又被拒」。
修一下打包脚本，输出目录不对

输出目录写成了 dist/，应当是 out/。我先把旧的产物清掉再改脚本。

  • 审核中rm -rf dist/· 3s
  • 运行中rm -rf dist/· 3s
✻ 审核中 3 秒
✻ 运行中 3 秒

2　审核放行

场景：模型删的是本回合自己刚建的临时文件 tmp-build.log，审核放行，命令照常执行。

A：沿用现有「· 自动：本会话已授权」那个位置和灰色，一眼看出「这条本来要问，是审核替你放的」；事后翻记录能找到。 B：最安静，Claude Code 也是放行时不标；但删了东西事后翻记录，分不出是普通放行还是审核放的。 C：多带模型名，排查审核误放时有用；但行尾更长，模型名对日常没意义。
  • 已运行rm tmp-build.log· 自动：审核放行· 自动：审核放行（deepseek-v4-flash）
  • 已编辑package.mjs scripts/+3 −3

脚本已改成输出到 out/，临时日志也清掉了。

3　审核不放行

场景：接第 1 节，dist/ 是本会话之前就有的目录，你也没说要删它，审核不放行。命令没有执行，模型收到理由后换了办法。

A：理由完整可读，你能马上判断要不要明确授权；代价是每次被拒多占一行。 B：一行搞定；但理由通常一句话十几到几十个字，窄窗口下基本只剩前几个字。 C：最省地方；但被拒正是你最想知道原因的时候，多点一下。模型自己的回复通常也会转述理由。
  • 运行rm -rf dist/· 已拒绝· 自动：审核没放行· 审核没放行：要删除本会话之前就有的 dist/，你没有点名要删它
  • 要删除本会话之前就有的 dist/，你没有点名要删它
  • 已编辑package.mjs scripts/+3 −3

删除 dist/ 没有通过自动审核，我没有删它，只把脚本改成输出到 out/。旧的 dist/ 还在；如果要清掉，请直接告诉我「删掉 dist/」。

4　审核没能完成（超时、网关报错、审核模型回了看不懂的话）

场景：模型要运行 git reset --hard，审核请求超时。这不是判定不安全，命令同样没有执行，模型被告知可以稍后照原样重试。这类失败不计入「连续 3 次」。

A：分得清「审核说不行」和「审核没跑成」，后者往往是网关或审核模型的问题，该找管理员；灰色与「未执行」这类结果同一个调子。 B：少一种样式；但红色会让人以为命令有危险，管理员的审核模型挂了也看不出来。
  • 运行git reset --hard· 未执行· 自动：审核没能完成（超时）
  • 运行git reset --hard· 已拒绝· 自动：审核没能完成（超时）

自动审核这次没能完成（超时），命令没有执行。我先做不依赖它的部分，稍后再试一次。

5　连续 3 次没放行后，改为弹卡问你

场景：审核已连续 3 次没放行，这一次不再直接拒绝，而是在输入框位置弹出权限卡，带上审核的理由，由你决定。危险命令（删除、强推等）只给「直接允许 / 直接拒绝」，工作区外路径这类还有「本会话内允许」。

调用类型：
A：先看审核为什么不放行，再看为什么轮到你决定，两件事各一行；卡片高一行。 B：卡片矮一行；但理由被挤到一句长话的后半段，窄窗口要折两三行。

卡片里原来那行「这条命令会删除文件或丢弃改动，每次都要你确认，不能按本会话允许」在配了审核模型时不再成立（全自动下删除先交给审核），由下面的审核说明取代。
