这版基线在定义什么，不定义什么

D23 边界
中列骨架两态：空态居中 / 会话态沉底
目标栏文件夹 · 分支 · 运行位置（只读）
工具行 / 问答卡v2：形态源改判为 Cursor（D24）
颜色 / 字体Flexoki + 全等宽，零硬编码

定义：中列在「未发消息」与「已有会话」两态下的骨架与呼吸节奏；目标栏三个控件的形态、位置与状态； Composer 卡的边界、圆角、内部分行；三个下拉的宽度、行高、分组方式与文案；侧栏 D21 平铺形态的最简可读样子； （v2 新增）工具行的四种形态与问答卡的四种状态。

v1 → v2 的边界改判（D24）：v1 曾写「时间线内部的工具行 / 问答卡按 T-05 openchamber 口径不变」—— 该句已作废。用户在 Cursor 中专门触发了这两类组件的调用演示并存图（五张），拍板形态源改为 Cursor： 工具行改成动词开头、无图标、无边框的灰阶单行并支持聚合折叠；问答卡改成 折叠条 → 字母选项卡 → Answers 冻结的三段式。 D20 不动——「回答后就地冻结」这条恰好与 Cursor 一致，v2 只是换了它的外形。 连带：T-05 需第二次改写口径，以本页屏⑤⑥ 为准。

仍然不定义（真的不动）：用户气泡与助手正文的排版（A01 已验收）；D19 的三列 + 44px 导轨骨架； 右栏 surface 的任何内容；「点击历史消息重新编辑」——该截图用户标注功能待定，仅归档不立项， 本页只取其中的 Questions skipped 态作参考。

刻意不搬的 Cursor 元素：白底浅灰面板与无衬线字体（D18 撤销 D6 后我们走 Flexoki + 等宽）； Connect Your Repos 黑色 CTA；麦克风/语音按钮；Remote Control 卡片； 运行位置下拉里的 Cloud / Remote Machines 可点项。 理由统一是可行性文档 §6.2 与 T-23 的同一条：没有能力就不摆控件，不做假选项、不做无反馈的可点元素。

颜色纪律（照抄时最容易破的三条）

  • 零硬编码：本页原型内一个十六进制值都没有，全是 var(--*)；唯一的 color-mix 用在用户气泡描边（--primary 8%），沿用 A01 已验收写法。
  • --selection / --hover 不叠 alpha：globals.css 已把上游的半透明预合成成实色，再叠 /N 会二次衰减。本页选中行/悬停一律裸用。
  • --accent-primary 只做填充与圆点：亮色下它对 bg 只有 1.82:1，导轨小圆点可以，文字绝对不行。
  • --status-running 不是 warning：Flexoki 的 warning 与 primary 同值，运行态用 info 系的 --status-running（T-21 已替掉全仓唯一的 bg-amber-500）。

字体纪律

  • D18③：sans / mono / heading 三者同为 ui-monospace，本页原型内没有第二种字族。
  • 中英混排宽度节奏是已登记风险（open-q #10）——本页有意在下拉与侧栏里放了中英混排文案（「新建 worktree…」「本机运行」），验收时请重点看这几行的纵向节拍。
  • 路径与分支名走 13px code 档 + tabular-nums（时间戳），保证右对齐相对时间列不抖动。

需要用户拍的五件事

⑤（v2 新问）工具行还要不要能看到工具输出？

Cursor 的工具行是终点——五张截图里一次都没有展示 Ran / Grepped 的实际输出，展开聚合行看到的只是更多行标题。 我们现有 T-05 口径里 Read/Grep/Bash 的输出体（测试结果、报错栈、diff）是排障主力，照搬等于净损失。

建议：形态照 Cursor，但保留可展开的输出体（屏⑤ E 组）——单行摘要默认收起，只有失败行和显式点开时才展示。 这样既拿到 Cursor 的「旁白感」，又不丢排障信息。若用户要纯净版，删掉 E 组即可，其余不受影响。

另：Permission 卡沿用问答卡外形（外推，非截图证据）

Cursor 演示里只有 AskQuestion，没有 Permission。本基线按「同一套外形，头文案换 Permission、选项换 允许 / 拒绝」外推。 施工时按此执行，若验收后不满意再单独立项——此处只做提示，不需要单独拍。

① 会话 Tab 栏：带（屏③）还是不带（屏②）？

建议：先不带。D21 刚把会话切换入口定在左栏，再加 Tab 栏会有两个入口；且 T-22 要把中列 surface 化，届时 Tab 的语义（会话 vs surface）需重新定义，现在引入等于提前锁死。

若拍「带」，请一并定：Tab 与左栏选中态是否双向同步、关掉最后一个 Tab 时中列显示什么。

② 会话态的目标行要不要也显示「文件夹」？

建议：不显示（照截图，只留分支 + 运行位置）。文件夹在会话已建立后基本不可变（改它等于 fork 新会话），常显是噪音；需要看时鼠标悬停分支即可给出完整路径。

③ 发送键：圆形图标（本基线）还是保留现状带 Send 文字的按钮？

建议：圆形图标 + aria-label。等宽字体下 Send 占位偏宽，会把 Model/Effort 挤到换行；运行中变 Stop（--destructive 实心）同位同尺寸，状态切换零位移。

④ 空态卡下方要不要放「最近会话」快捷入口？

建议：不放。Cursor 没有，openchamber 没有，左栏 Recent 段（D21 保留）已经是这个入口；卡下留白正是空态呼吸感的来源。
