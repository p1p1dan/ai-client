③ 长指令看不到 —— 这是真 bug，不只是截断

  • 根因有两处，叠在一起：
    1. toolCard.ts 的 toolRowArgClass() 返回 min-w-0 truncate——单行截断，且纯文本 arg 连 title 兜底都没有（只有文件链接那种按钮才带 title={link.path}）；
    2. ARG_COVERED_FIELDS.Bash 把 command 列成"已在一行摘要里覆盖"，于是 deriveToolInputBody 不会再为它生成完整输入体。所以展开工具行也照样看不到完整命令。
  • 建议改法：把 command 从 Bash 的 covered 列表里去掉。展开后就有完整输入体。这是最小改动，且只影响 Bash 一行。折中的话，至少让命令允许换行（预览里就是换行显示的）而不是单行截断。
  • 不要用 title 当主解法：触屏和键盘都够不到，而且一行悬停提示读 200 字符的命令是种折磨。

④ 折叠头显著化 —— 我做了三件事

  • 吸顶（position: sticky）。这是"内容多了找不到折叠头"的正面解法：无论滚到哪，头都在视野顶部。仓库已有先例——thoughtFoldHeaderClass() 就是吸顶的（决策 028），而且 chatTimelineLayout.ts 记下了唯一的前提条件：吸顶元素的高度不得随滚动状态变化（F10 的振荡就是因为高度依赖 scroll-state）。折叠头高度固定，所以这条满足。
  • 底色 + 边框 + 圆角。头从"一行灰字"变成一个可辨识的条形控件。用的是 --accent，和用户气泡同一档，不新造颜色。
  • 数量徽标。0 次调用 这种计数放进右侧 badge，滚动中也能一眼看到进度。

② 旁白与终稿同字号

  • 预览里两者都是 --text-chat-body(16px)、同一行高，只差颜色（text-muted-foreground vs text-foreground）。
  • 这比"字号也降一档"更好：字号变化会让中间旁白读起来像"另一种内容"（脚注），而它其实是同一个模型的同一段口吻。颜色降档足够区分主次，且不会让旁白难以阅读。现在仓库的 turnIntermediateToneClass() 本来也只改颜色不改字号，所以这条已经是现状，不用改。

① 缩进节拍

  • 旁白之间：8px 标准档（自然段落）。
  • 操作块 内部：4px 紧凑档 + 12px 左内缩 + 一条极淡引导线。
  • 完整指令块再进一层：在操作块的引导线内侧。所以层次是「旁白 → 操作 → 指令/输出」，三级刚好对应 design-system 的「段落 / 紧凑 / 再次级」。
