过程组结构 · 三形态对照

三种形态共用同一份内容数据（同一轮对话、同样的旁白与工具调用），差异只来自结构。点「重放流式」看每一段在流式期间的行为——重点是：已完成的段头应当冻结，只有最后一段在动。

A 现状：整轮合成一个大组

三个分支到底差在哪

  • A · 现状。整轮只有一个折叠头，所有旁白和工具都在它下面。一轮永远占一行，密度最低；代价是展开后无法定位——40 步的轮里要找到某一步，只能从头滑。
  • B · 每段自己一块。每个「旁白 + 它引发的工具」自成一段，各有自己的头。注意头是那段旁白的第一句，不是「已处理 N 个步骤」——这是它和 2026-09-10 那版被推翻的形态之间唯一的、也是决定性的差别。它拿到「目录」能力，代价是一轮的折叠态从 1 行变成 N 行。
  • C · 大组 + 组内可分跳。折叠态和 A 一样只有一行（保住密度）；展开后在组内是 N 个可单独点开的段（拿到定位能力）。它没有明显代价，但也没有 B 那么强的"目录感"——因为你要先展开大组才看得到段头。
  • 三者共用的两条修正。证据块一律用 4px 紧凑档 + 内缩 + 引导线（设计系统标准档/紧凑档，未新造值）；已完成的段头冻结，只有最后一段在动——这正是上一版预览里那个「一直在动」的 bug 的正确修法。

点「重放流式」会从头模拟一遍：旁白先出现 → 它引发的工具逐条落地 → 该段头冻结 → 下一段开始。观察 A 与 B 在折叠态下的行数差异，以及 C 展开后能不能直接点到某一段。
