这个 demo 在比什么

同一段转录，五个开关各自独立。全关 = 我们现在的形制，全开 ≈ zcode 截图里的形制。建议一个一个开，看哪一项真正在起作用。

  • ① zcode 每行 0 个控件，我们每行 1 个 ›。一屏二十个可点控件是观感差距最大的一项——关掉后行内容会靠点整行展开。
  • ② 「已运行 / 已编辑」（过去时三字）→ 图标 +「终端 / 编辑」（两字类型）。图标承担类型识别，文字预算让给内容。
  • ③ 编辑行从一条长路径变成「文件名 + 弱化目录 + +4 -38」。信息更多，占宽更少。
  • ④ 过程行的灰再压一档（muted-foreground 85% → 62% 混背景），拉开与正文的明度差，扫视时自动跳过。
  • ⑤ 去掉过程组折叠头与聚合行，整轮平铺——zcode 清爽不是因为藏得多，是因为每行都短、都淡、都无控件。代价：长回合没有任何收起手段。

没做进 demo 的

zcode 左侧那列细刻度是消息小地图（滚动定位），与过程行形制无关，属另一个特性。
