# Runtime 测试版交付与回退

本分支只交付内部测试候选，不执行公开发布或默认后端切换。
流程由 [ARD D8/D11/D16](plans/2026-09-08-runtime-evolution-ard.md)和 [P4-6 看板](plantree/plans/runtime-evolution/README.md)约束。

## 交付

1. 记录提交、版本、手动 CI run URL、artifact 与安装包 SHA-256。
2. 完整门禁和各平台打包验证通过后，从 Actions artifacts 下载测试包。
3. 对照源码提交执行 Windows 工具/进程/GUI 检查；企业加密场景在对应驱动和策略下另验。
4. 每项记录通过、失败或未执行。CI 通过不等于现场完成，未满足的 P1/P4 项继续保留。

测试期间出现会话损坏、权限异常放行、串会话、重复写入、启动失败或退出后进程残留时，停止该项测试并保留日志和复现数据。

## 回退

**2026-09-13 起没有后端开关了。**当天先由 P6-1 把默认切到自有 runtime，再由用户决定提前执行 P6-5——旧引擎（`src/agent-host/` 里那套跑 pi-coding-agent 的会话/导入/补全代码）连同 `AICLIENT_RUNTIME_BACKEND` 一起删除。设这个变量现在完全没有效果。

**唯一的回退方式是装回上一个确认可用的安装包。**

回退前后需要知道的：

- **会话文件不会因为回退而读不了**。H/20 让每个会话文件的头一行同时满足两种格式，旧版本的引擎与内嵌终端都能打开本期间产生的对话。反过来，本期间新写入的行用的是 v4 形状，旧版本能读到消息但读不到 v4 独有的分支/压缩细节。
- **内嵌 Pi 终端与插件管理不受影响**：它们跑的是随包的 `pi` 可执行文件，不是被删掉的那层代码。
- 派生的 `models.json` / `auth.json` 仍在写——它们现在服务的是随包 CLI（终端要有模型可用），不再是旧后端。

具体步骤：

1. 退出应用及其 TUI，确认本次 worker/runner 已退出。
2. 保存日志、会话副本与 profile 备份；不要清理或反向覆盖原始会话。
3. 安装上一个确认可用的包。**不要**试图用环境变量切回去——没有那条路了。
4. 新 runtime 写出的会话不承诺被每个旧版本完整解释。用测试前备份或独立新会话验证回退，不直接在唯一的原件上尝试。
5. 记录版本、提交、实际路径、触发操作与错误，交回开发端修复，再对失败项和相关回归重新验收。

不修改 tag、Release 或自动更新频道；无需为本次测试操作公开发布渠道。
