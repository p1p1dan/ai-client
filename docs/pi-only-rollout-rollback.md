# Runtime 测试版交付与回退

本分支只交付内部测试候选，不执行公开发布或默认后端切换。
流程由 [ARD D8/D11/D16](plans/2026-09-08-runtime-evolution-ard.md)和 [P4-6 看板](plantree/plans/runtime-evolution/README.md)约束。

## 交付

1. 记录提交、版本、手动 CI run URL、artifact 与安装包 SHA-256。
2. 完整门禁和各平台打包验证通过后，从 Actions artifacts 下载测试包。
3. 对照源码提交执行 Windows 工具/进程/GUI 检查；企业加密场景在对应驱动和策略下另验。
4. 每项记录通过、失败或未执行。CI 通过不等于现场完成，未满足的 P1/P4 项继续保留。

测试期间出现会话损坏、权限异常放行、串会话、重复写入、启动失败或退出后进程残留时，停止该项测试并保留日志和复现数据。

## 回退

1. 退出测试应用及其 TUI，确认本次 worker/runner 已退出。
2. 保存测试日志、会话副本与 profile 备份；不要清理或反向覆盖原始会话。
3. 移除本次启动环境的 `AICLIENT_RUNTIME_BACKEND=native`，可重新启动默认 legacy 后端；若应用自身启动失败，改用之前确认可用的安装包。
4. 新 runtime 写出的会话不承诺被每个旧版本完整解释。用测试前备份或独立新会话验证回退，不直接在唯一的原件上尝试。
5. 记录版本、提交、实际路径、触发操作与错误，交回开发端修复，再对失败项和相关回归重新验收。

不修改 tag、Release 或自动更新频道；无需为本次测试操作公开发布渠道。
