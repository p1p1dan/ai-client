> 2026-08-10。这份是**动手用的**：每条只写「怎么做 / 看什么 / 算不算过」。

## 第 0 步 · 拿包（在有网的机器上做）

**两条路，任选一条：**

**路 A（推荐，不需要 Windows 机器）**
1. 打开 GitHub 仓库 → 顶部 **Actions** → 左边选 **Build** → 右上 **Run workflow**
2. 分支选 `feat/openchamber-chat-refactor` → 点绿色 Run
3. 等它跑完（20–30 分钟）→ 点进这次运行 → 页面最下方 **Artifacts** 区
4. 下载 **`windows-unpacked`**（这是目录版，解压出来就是整个程序）

**路 B（你自己在 Windows 上出包）**
```powershell
git pull
pnpm install
cd src\agent-host
npm ci
cd ..\..
pnpm build:win
```
产物在 `dist\win-unpacked\`。

**另外还要带一个文件**：仓库里的 `scripts\make-test-claude-config.mjs`（单个文件，拷走）。

## 第 6 步 · 通用功能九项

| # | 怎么做 | 算过的标准 |
|---|---|---|
| 1 | 双击启动 | 不白屏、不弹报错框 |
| 2 | 设置 → Appearance → 打开 **OpenChamber Workspace Shell** 开关 | 界面变成新版（左边栏 + 中间对话 + 右边面板） |
| 3 | 新建一个会话，发这句：`Reply with exactly: PONG. Do not use tools.` | 能看到字一个个流出来，内容里有 PONG |

| 5 | 再让它写一次文件，这次点 **Deny** | 程序不崩，模型收到拒绝后正常把话说完 |
| 6 | 发个长任务（比如 `Count from 1 to 200 slowly`），跑到一半点 **Stop** | 立刻停住，状态回到空闲，**还能接着发下一条** |
| 7 | 关掉整个程序 → 打开任务管理器 → 搜 `node.exe` | 没有残留的进程（关之前先看一眼有几个，做对比） |
| 8 | 用一个全新的、没添加过仓库的状态启动：① 左边栏空的时候有没有"添加本地仓库"的入口；② 从文件资源管理器**拖一个文件夹**到窗口里 | ① 能弹窗添加成功；② 拖进去时窗口出现高亮遮罩，松手弹出的窗口里路径已经填好了 |
| 9 | 顶部那行会话标题，跟正文放一起对比看 | 标题**明显更粗更醒目**。要是粗细看不出差别 → 这是字体问题，截图带回来 |

## 第 7 步 · 上次五个问题的回归（**这次的重点**）

### R1 · 带图片的消息会不会重复

1. 发一条消息，**带一张图片**
2. 等它回完
3. **关掉这个会话，再重新打开它**（或者干脆重启程序再打开）

**看什么**：刚才那条消息**只出现一次**，并且带着图片缩略图。
**不过的样子**：出现两条——一条有缩略图、一条没有。

### R2 · 会不会太早就说超时

发一条**重一点**的消息（带大图，或者让它做点费劲的思考），**掐表**。

**看什么**：3 分钟以内**不应该**弹超时提示。
**不过的样子**：没到 3 分钟就弹超时。

### R3 · 能不能移除仓库

1. 左边栏找到仓库那一行，**鼠标悬停上去**
2. 应该出现一个「文件夹带减号」的图标 → 点它
3. 弹确认框 → 确认 Remove

**看什么**：那个仓库从左边栏消失了，**磁盘上的文件没被删**。

⚠️ **重点**：请**挂两个或以上仓库**再测，然后核对**删掉的是不是你点的那个**。（这个取键逻辑刚从"猜"改成"精确匹配"，这是唯一的现场验证机会。）

### R4 · 侧栏的分支标签（**这项按新方法做，别只看"有没有"**）

先说清楚看哪：左边栏每个会话行，右边有一两个小标签（chip）。其中一个写着 `Claude Code`，另一个应该写着 git 分支名（比如 `main`、`feat/xxx`）。

**⚠️ 上次那个"修复"经复核基本等于没改，所以这次不要按"修好没有"记分。** 按下面三步走，目的是**拿回一个能定位到原因的结论**。

**第一步（先做这个，很可能一步就定案）· 截图**

把某一行会话行**放大截图**，看 `Claude Code` 那个标签和右边的时间之间：

- **能看到一个很小的、空的带边框小方块**（大概比一个字还窄，里面没字或只有一两个字）
  → **数据是好的，问题在宽度不够**。到此为止，不用再查了。
- **两者之间什么都没有**（连边框都看不到）
  → 走下面第二、三步。

（依据：这个标签有 16 像素的硬下限，被挤压时只会变成空方块，**不会整个消失**。所以"空方块"和"什么都没有"是两种完全不同的病。）

**第二步 · 关掉新界面看旧界面**

设置 → Appearance → **关掉** OpenChamber Workspace Shell → 回到旧版左边栏 → 展开那个仓库。

旧界面会把 git 的错误**直接显示成文字**。**看到错误文字，抄下来就是答案**，不用做第三步了。

**第三步 · 开发者工具跑一行**

View → Developer Tools → Console，粘贴这一整段按回车：

```js
(async()=>{const k=p=>p.replace(/\\/g,'/').replace(/[\\/]+$/,'').toLowerCase();
for(const r of JSON.parse(localStorage.getItem('aiclient-repositories')||'[]')){
try{const w=await window.electronAPI.worktree.list(r.path);
console.log('REPO',JSON.stringify(r.path),'key',k(r.path),w.map(x=>({p:x.path,key:k(x.path),b:x.branch,main:x.isMainWorktree})));}
catch(e){console.log('REPO',JSON.stringify(r.path),'THREW',e.message);}}})()
```

**把整段输出截图带回来。** 五种结果，对号入座：

| 输出里出现 | 说明 |
|---|---|
| `THREW` 且带 `ENOENT` / `spawn git` / `不是内部或外部命令` | **程序找不到 git**（它找 git 的路径和你在命令行里的不是同一个） |
| `THREW` 且带 `dubious ownership` / `not a git repository` | **git 拒绝这个仓库**（属主不对，拷贝来的仓库常见） |
| 有正常输出，但 `key` 那两个值**不一样** | **路径对不上**（映射的网络盘 / 快捷方式 / 或者你注册的是仓库的子目录） |
| 有正常输出，`key` 一样，但 `b` 是 `null` | **当前不在任何分支上**（切到某个 tag 上了） |
| 有正常输出，`key` 一样，`b` 有值 | **数据完全正常** → 回到第一步那个"宽度"的结论 |

> ⚠️ **别用程序内置的终端敲 `where git` 来下结论** —— 内置终端用的路径和程序真正跑 git 用的路径**不是一回事**，在终端里能找到不代表程序能找到。

## 第 8 步 · 加密相关六项（这台机器专属）

| # | 怎么做 | 看什么 |
|---|---|---|
| ① | 在文件树里打开一个**已知是加密的**文件 | 是明文还是一堆以 `%TSD-Header-` 开头的乱码 |
| ② | 在真实的加密工作区里跟它对话，让它用 Read 工具读一个加密文件 | 读出明文就算过 |
| ③ | 授权卡点 Allow 让它写一个文件，然后自己打开那个文件看 | 记录是明文还是密文 |
| ④ | 打开一个有**加密历史记录**的会话 | 应该明确报"历史无法读取"，而不是静默显示空白 |
| ⑤ | 第 5 步里 `source` 是 `bundled` 的话，直接做②——能读出明文就证明包里的 node 被白名单认了 | —— |
| ⑥ | 如果①②失败：先分清是"找不到程序"（ENOENT）还是"白名单不认" | **这两个别记混，结论完全不同** |

**万一②③全失败**：用逃生口，**不用改代码**——
```powershell
set AICLIENT_NODE24_PATH=<这台机器上已被白名单的 node.exe 完整路径>
```
然后重启程序再试。**出发前先把这个路径查清楚**，否则一失败整轮作废。
