## §2 契约

### 2.1 Vault 文件与读写

- 路径 `<userData>/credentials/vault.json`，**惰性解析**（见 §1 index.ts）。
- **schema（envelope 版，母规格 §3.C 同步修订为本形状——A 轨 B9 + B 轨 1.4 裁定）**：
  ```jsonc
  {
    "version": 1,
    "enc": "safeStorage" | "none",
    "lastEmail": "x@jcdz.cc",          // 明文层，clear/save 都必须维护（save 同步覆盖）
    "invalidatedAt": null | "ISO",     // 明文层：标失效不需解密（markRejected 落盘位）
    "encReason": "ok" | "unavailable", // 诊断位：明文降级时可归因
    "payload": "<base64 密文>" | { …明文对象… }
  }
  ```
  payload 解后：`{ identity:{email,userId}, cchBaseUrl, claude:{baseUrl,authToken}, codex:{baseUrl,apiKey}, receivedAt }`。
  **落库值口径（A 轨 B7）**：claude/codex baseUrl 存 `buildApiBaseUrl` 归一化值、cchBaseUrl 存 `deriveCchBaseUrl`
  值——与写进 legacy 文件的字节一致（断言见 §3-1g）。`receivedAt` 即 legacy `registeredAt` 的对应物（S6 收编映射注记）。
- **读结果联合（A 轨 B2 + B 轨 1.5 合取）**：
  `{status:'ok', doc} | {status:'absent'} | {status:'locked', lastEmail?} | {status:'unsupported', lastEmail?} | {status:'invalid', reason:'malformed_json'|'schema_invalid'|'decrypt_failed', lastEmail?}`
  - **`enc:'safeStorage'` 且 crypto 不可用 → 必须 `locked`，永不 invalid**（窗前/keyring 未解锁是暂时态）；
  - crypto 可用但 decrypt 抛错 → `invalid/decrypt_failed`；
  - `version > 1` → `unsupported`，**只读、禁止覆盖写**；version 缺失/非数 → `invalid/schema_invalid`（A 轨 B9）。
- **写**：唯一 tmp 名 `vault.json.<pid>.<rand>.tmp` + 写后**显式 `chmodSync(0o600)`**（Node mode 仅创建时生效，
  残留 tmp 会静默继承旧权限——A 轨 B5）+ 目录 mkdir 后显式 `chmodSync(0o700)`；进程内 save/clear 串行化
  （Promise 队列）。**升格前 `save()` 一律拒绝**：`{ok:false, reason:'crypto_not_ready'}` + warn——防密文被静默
  降级明文（A 轨 B3；S1 中 vault 是影子写，拒写零副作用）。
- `clear({keepLastEmail:true})`：**无 flag 门控**（泄漏移除档——A 轨 B8：flag-off 登出必须清 vault，否则密钥
  跨 flag 留盘；母规格 I7 措辞同步改为「flag-off 不得写入/读取 vault，登出清除除外」）。vault 不存在时 no-op
  （**不得**创建只含 lastEmail 的空壳）；失败只记日志，不改 `logout()` 返回值（A 轨 M13）。

### 2.2 crypto 适配器与升格闩

- `VaultCrypto = { available():boolean, encrypt(s):string, decrypt(s):string }`；初始 none 适配器。
- **升格闩（A 轨 B4 + B 轨 2.1 合取）**：`app.on('browser-window-created', once)` 触发
  `promoteVaultCrypto(safeStorageAdapter)`——E6 的硬条件是「窗口已构造」而非 ready（`ready-to-show` 在本仓有
  永不触发实证 `MainWindow.ts:219-224`）。单向（none→safeStorage）、幂等、不降级；升格**只装适配器不调用**
  `isEncryptionAvailable()`——`available()` 在首次 vault 实际用到时惰性调用并缓存。零窗口态是终局
  （`window-all-closed→quit`），单向闩安全。win/mac 未实测（E6 仅 Linux），闩逻辑平台无关，登记不阻断。

### 2.3 IPC 消毒（无 flag，回退靠 revert 不靠 flag——A 轨 M1，母规格 S1 行同步改）

- **判别联合**（A 轨 B6 + B 轨 1.1，两轨独立同结论）：
  ```ts
  type OnboardingRegisterClientResponse =
    | { ok: true;  data: { user: { id: number; name: string } } }
    | { ok: false; error?: OnboardingErrorCode | string; data?: { attemptsLeft?: number } };
  ```
  （`error` 联合保留 `| string`——`describeOnboardingError` 签名依赖，B 轨 m2。）
- `toRendererRegisterResponse(full)`：**白名单显式构造新对象**（非 delete 式——未知新增字段照样滤掉，A 轨 M6），
  成功臂只取 `user.{id,name}`，失败臂只取 `error` + `data.attemptsLeft`。
- 事实钉子：renderer 语义消费点仅两处——失败臂 `attemptsLeft`（`OnboardingView.tsx:322`）、成功臂 `user.name`
  （`:707-711`）；preload 仅透传；**Main 内 `config` 仍是合法消费者**（legacy/vault 写入），裁剪发生在 Main
  写盘完成之后、IPC 返回之前（B 轨 3.1）。

### 2.4 AuthStateService

- 状态联合同 rev.1，`credentials_invalid.reason` 映射：Vault `invalid/malformed_json|schema_invalid` → `corrupt`、
  `invalid/decrypt_failed` → `decrypt_failed`；**Vault `locked`/`unsupported` 不得推 `credentials_invalid`**
  （折算 `signed_out` + 内部诊断，S5 再细化 UI 表达）。
- **重算触发（A 轨 M2）**：`refresh()` 由登录/登出路径显式调用；`getState()` 只读缓存（永不同步 IO）；
  `onChange` 返回退订函数。flag off：`refresh()`/`getState()` 恒 `signed_out` 且零文件 IO（fs spy 断言）。

### 2.5 redact.ts（B 轨 1.6/2.3/2.4 + A 轨 M7 合取）

- 入口 `redactLogArgs(args: unknown[]): unknown[]`——逐参数处理 string / Error（message+stack）/ 可序列化对象。
- 键名对齐母规格 I2 并**补 `cookie`/`set-cookie`/`authorization`**；**删裸 `key`**（误伤 `key=cache` 等），
  用 `api[_-]?key/auth[_-]?token/…` 语义边界名（范式与负控照 `stderrRedaction.ts:35-82` +
  `stderrRedaction.test.ts:95`）；`sk-` 长串形状兜底保留。
- **删 `tokenPreview`**（前六字符也是 secret——B 轨 1.6）：日志一律 `token=<REDACTED>` 或 `tokenPresent=true`。

### 2.6 flag 与 dev.js（两轨分歧合取）

- 生产读法：`resolveManagedCredentialsEnabled(env) => env.AICLIENT_MANAGED_CREDENTIALS === '1'`，纯函数 + 全
  伪真值矩阵测试（`'true'/'yes'/' 1'/'1 '/''` 全 false，照 `agentSupport.test.ts:26-35`）。**只在 Main 读**，
  renderer/preload 零感知。
- dev.js（本片就改，B 轨 1.7）：flag 入 `STRIPPED_KEYS`（剥继承）；`buildChildEnv` **所有返回路径**（含
  `--allow-local-credentials` 早退 `dev.js:184-188`）末端统一：dev.env/shell **显式**给 `'1'` 才保留，否则强制
  `'0'`（A 轨 M8 的「dev 轮可开」+ B 轨的「不被继承环境意外打开」同时满足；S2 全局 CLAUDE_CONFIG_DIR 落地时再评估收紧）。

### 2.7 双写与登出

- `verifyAndRegister` 成功：legacy 写盘（原样）→ flag on 时 `vault.save(...)`；vault 失败仅日志（影子写不阻断）。
- `logout()`：legacy 清理（原样）→ `vault.clear({keepLastEmail:true})`（**无 flag**，§2.1）。
- 崩溃窗（legacy 成、vault 前挂）：S1 零读者故无害，登记已知瞬态，S6 收编收口（A 轨 m8）。

## §4 风险与登记

- Windows/macOS 升格闩与权限位未实测（E6 仅 Linux）——逻辑平台无关，随 test.4 真机轮补。
- `autoStartHapi()` 早于开窗执行（`index.ts:752/757`）——窗前代码路径客观存在；S1 无窗前 vault 读者是设计保障
  （拒写 + IPC 只能窗后发起）而非巧合（A 轨 m11）。
- lastEmail（明文层）/identity.email（payload）/legacy `onboarding.email` 三份同事实——S1 规定 save 同步覆盖
  lastEmail；S5 预填读 vault.lastEmail；S6 收编统一（B 轨 m5/m4）。
