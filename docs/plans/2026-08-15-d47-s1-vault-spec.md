## §1 范围（本片做/不做）

**做**：
1. `src/main/services/auth/CredentialVault.ts` — 凭据唯一权威的读写层。
2. `src/main/services/auth/AuthStateService.ts` — 登录态快照推导（仅服务层，**不接 UI/Root/MainWindow**，那是 S5）。
3. IPC 消毒（**无 flag，纯泄漏移除**）：`verify-and-register` 响应止步 Main，renderer 只收裁剪版。
4. 双写接线：flag on 时 `OnboardingService.verifyAndRegister` 成功后**追加** `vault.save(...)`（legacy 写盘保持原样，先 legacy 后 vault）；`logout()` flag on 时追加 `vault.clear({keepLastEmail:true})`。
5. `src/main/services/auth/redact.ts` — 统一 redactor 工具（本片只建工具+测试+接入 OnboardingService 既有日志点，全面接线后续片推进）。

**不做**：claude-home/codex-home 生成（S2/S4）、终端注入（S3）、Root/MainWindow/UI（S5）、收编迁移（S6）。

## §2 契约

### 2.1 Vault 文件

- 路径：`path.join(app.getPath('userData'), 'credentials', 'vault.json')`；目录 0700、文件 0600；
  写入 = tmp + rename 原子（参照 `SharedSessionState.atomicWriteJson` 但**显式传 mode**——那边不传是已登记的弱点）。
- schema v1（母规格 §3.C）：
  ```jsonc
  { "version": 1, "enc": "safeStorage" | "none",
    "lastEmail": "x@jcdz.cc",                    // 明文，非机密，clear 保留
    "payload": "<base64>" | { …明文对象… } }     // enc=safeStorage 时为密文串，否则内联对象
  ```
  payload 解后：`{ identity:{email,userId}, cchBaseUrl, claude:{baseUrl,authToken}, codex:{baseUrl,apiKey}, receivedAt }`。
- **E6 死锁约束（硬规矩）**：`safeStorage.*` 任何调用**必须在首个 BrowserWindow 创建之后**。实现：Vault 构造时注入
  `crypto: VaultCrypto` 适配器；Main 在 `MainWindow` 首窗 ready 后才把真 safeStorage 适配器**升格**进去（之前的读写走
  `enc:"none"`）。适配器接口 `{ available():boolean, encrypt(s):string, decrypt(s):string }`，单测全用 fake。
- 读到损坏/解密失败：返回 `{status:'corrupt'}`，**不 throw 不崩溃**（母规格 I 系）；由 AuthStateService 折算 `credentials_invalid`。
- `basic_text` 不需显式判 backend——E6 实测 `isEncryptionAvailable()` 此时自返 false，单布尔足够。

### 2.2 AuthStateService

```ts
type AuthState =
  | { kind:'signed_out'; lastEmail?:string }
  | { kind:'authenticated'; email:string; userId:number; remoteHealth:'unknown'|'valid' }
  | { kind:'credentials_invalid'; email?:string; reason:'corrupt'|'decrypt_failed'|'rejected' };
```
- 本片只实现：由 Vault 读取结果推导快照 + `getState()` + `onChange(cb)` 事件；`remoteHealth` 恒 `'unknown'`
  （auth-probe 接线在 S5）；`markRejected()` 预留接口（S5 调用）。
- flag off：服务可实例化但 `getState()` 恒 `signed_out`（不读 vault 文件——off 轮零新 IO）。

### 2.3 IPC 消毒（无 flag）

- 事实：renderer 仅消费 `data.user`（`OnboardingView.tsx:707`）与 `data.attemptsLeft`（`:322`）；
  `apiKey`/`config` 零消费者。
- 改法：shared 类型新增
  `OnboardingRegisterClientResponse = { ok, error?, data?: { user:{id,name}, attemptsLeft?:number } }`；
  `main/ipc/onboarding.ts` 的 `VERIFY_AND_REGISTER` handler 在 `onboardingService.verifyAndRegister(...)` 返回后
  **裁剪再回**；preload 与 `OnboardingView` 改用新类型（编译期钉死）。`OnboardingRegisterResponse`（全量版）
  改注释标注 **Main-only**，renderer import 它即为违规（S11 静态扫描的种子断言，本片先加 lint 级 grep 测试）。
- 错误路径的 `data.attemptsLeft` 形状保留（`describeOnboardingError` 依赖）。

### 2.4 redact.ts

- `redactSecrets(input: string): string`：对已知键名（`authToken/apiKey/OPENAI_API_KEY/ANTHROPIC_AUTH_TOKEN/
  ANTHROPIC_API_KEY/AICLIENT_CODEX_API_KEY/auth-token/key`）的 `"k":"v"`/`k=v` 形态值打码为 `<REDACTED>`；
  外加 `sk-` 前缀长串兜底。接入 `OnboardingService` 现有 console.* 调用点（`tokenPreview` 逻辑保留，双保险）。

## §3 测试与验证

vitest node 环境，新文件 `src/main/services/auth/__tests__/`（**只 import 纯模块**——vitest-node-import-hang 纪律：
Vault 对 `electron.app`/`safeStorage` 的依赖全部走注入，测试不 import electron）：

1. Vault：roundtrip（none/fake-safeStorage 两轮）· clear 留 lastEmail 消 secret · 0600/0700 断言 ·
   corrupt 文件→`corrupt` 不 throw · decrypt 失败→`corrupt` · 适配器升格后新写走加密、旧明文文件仍可读（混态兼容）。
2. AuthState：三态推导表 · onChange 每迁移恰一次 · flag off 恒 signed_out 且零文件读（fs spy）。
3. 消毒：全量响应进 → 裁剪版出（无 `apiKey`/`config` 键，深查）；`user`/`attemptsLeft` 保留；
   **负控**：把 handler 换成透传实现，断言测试变红（变异验证的发射半边先钉）。
4. redact：各键名/形态用例 + `sk-` 兜底 + 无秘密输入原样通过。
5. **off 轮回归**：现有 vitest 全量绿（门禁串行跑）；`~/.aiclient`/`~/.claude` 相关既有测试零改动即过。

变异验证（施工后）：≥6 对——mode 去掉 0600 / clear 不留 lastEmail / 裁剪漏 config / corrupt 时 throw /
flag 判定放宽（`'true'` 也算 on）/ redact 漏 `sk-` 兜底；每对断言先红后绿。

## §4 风险与开放点（本片）

- 首窗前若有代码路径读 vault（S5 前理论上只有双写路径，均在登录后）——以「适配器升格」结构性规避，仍加
  assert 日志（升格前发生 encrypt 请求 → 记 warn 并走 none）。
- `attemptsLeft` 在全量类型里位于 `data` 顶层还是嵌套——施工时以 `OnboardingService.ts` 实际返回为准核对。
- 双写顺序 legacy→vault：legacy 失败则不写 vault（维持今天的失败语义）；vault 失败仅记日志不阻断登录
  （off 轮语义不受 vault 影响——vault 是影子写）。
