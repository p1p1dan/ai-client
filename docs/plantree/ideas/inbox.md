- **⚠️ `node:readline` 在 U+2028/U+2029 上切碎 JSON 帧（真 bug，实测坐实）**（2026-08-18，从 pi `rpc.md` 的客户端警告反查自身发现）：我们**三处**用 `createInterface`——`AgentHostProcess.ts:60`（Main 读 Host stdout，全部 Runtime Event，CC/Codex 两线都过）、`agent-host/index.ts:976`（Host 读 Main stdin，全部命令含用户消息）、**`historyReader.ts:369`（读 CC 会话 JSONL 文件，风险最高：内容全是自然语言，且宽容解析会静默跳过坏行，用户只见历史少一条不报错）**。同仓 `historyReader.ts:1089` 已是正确 LF-split，两法并存证明是疏忽。`codexHistoryReader.ts` 不受影响（纯投影不读文件）。Node readline 除 `\n` 外还在 U+2028/U+2029 切行，而这两个字符在 JSON 字符串值里合法。**实测（node v24.18.0）：含 U+2028 的帧被切成两半，两半均 JSON.parse 失败，整帧丢失**；LF-only 切分正确。触发路径：用户粘贴网页文本 / 模型输出 / 读文件工具结果回传。`crlfDelay: Infinity` 不解决此问题。修法=自建 buffer 累积器只按 `\n` 切并容忍尾部 `\r`，三处对称改 + U+2028/U+2029 变异臂，量级 S。注：pi 自身 `session-manager.ts:697` 也用 readline 读 session 文件，可借鉴的是它 rpc.md 那条**规则**而非实现；与 TSD 加密文件问题**正交**（那是能否读到明文，本 bug 是读到明文后怎么切行）。**【已拍板 2026-08-18】随「线协议完整性小批」立即立项，排打包链前。**见 [调研档 §7.5](../../plans/2026-08-18-deepseek-harness-study.md)。**【已落地 2026-08-18 `55b45b1`】三处对称修 + U+2028/U+2029 测试臂随批落。**
