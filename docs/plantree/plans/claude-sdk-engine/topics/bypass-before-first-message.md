# 开始页的「跳过权限确认」/「完全放行」（2026-10-16）

Role: topic（用户裁决 16 的落地）。上位：[README](../README.md) §1 裁决 16。两个引擎同样处理。

## 0 问题

开始页（还没有对话）的权限菜单里，SDK 会话的「跳过权限确认」与 DSH 会话的「完全放行」是灰的，说明是「需要先有对话才能开启」。用户要在发送第一句话之前就能开。

来历：runtime-hardening 决策 023（用户裁决）只定了两条安全边界：进入前二次确认、开着时持续可见。"只能在已有会话里开、开始页不可选"是 T078 落地时的做法，dsh-rebase 决策 166 照搬，不是用户的裁决。原因写在代码注释里：开始页的选择会存成"新对话的默认"，而完全放行不能是默认（默认没人再看，会悄悄让以后每个新对话都关掉询问），所以干脆不让选。

## 1 决定（自主决定，待审阅）

| # | 决定 | 理由 |
|---|---|---|
| B-1 | 开始页可以选跳过权限确认 / 完全放行，仍要二次确认；确认框多一行「只作用于下一句话新建的对话。」 | 裁决 16；决策 023 的两条边界不变 |
| B-2 | **只给下一个新对话，不存成默认**：选中后只记在内存里（`holdStartScreenPermissions`），芯片变红显示该档；开始页发出的那一句新建对话时，交给这个对话自己的那一行（`adoptStartScreenPermissions`），交出后就清掉；新对话默认（`aiclient:chat:default-permissions`）不写 | 守住"完全放行永远不是默认"：下一个新对话又回到原来的默认档；重启应用也就忘了 |
| B-3 | 交出的时机：首页发送新建对话之后、发出或排队之前（排队的消息也算这个对话）；`runSend` 自己兜底新建的临时对话同样。已有对话发消息不交，哪怕它没存过档位 | 只有"开始页这一句建出来的对话"是用户开它时指的那个对话 |
| B-4 | 在开始页改选别的档：清掉暂存，照旧存成新对话默认 | 用户改主意了 |
| B-5 | 预测走 SDK、实际退回 DSH 的新对话（SDK 宿主起不来）：跳过权限确认也收窄为手动审批，与自动模式、自动编辑一样（S-2 A-11 的扩展） | SDK 的跳过权限确认对少数危险操作仍会问，DSH 的完全放行一个都不问；退回时不能比用户确认过的说法更宽 |

## 2 验证

- 单测：开始页可选、二次确认带范围说明、确认后不调 `setPermissions`、不写默认、芯片变红并在悬停提示里说明范围；重挂载后开始页仍显示暂存、已有对话不显示；改选别的档清掉暂存并写默认；`adoptStartScreenPermissions` 只给没有档位的新对话、只给一次；SDK 的措辞同样；退回 DSH 时跳过权限确认收窄为手动审批。`ChatComposer` 两处交出点用源码扫描钉住。
- 变异检查 5 处都能被抓到：去掉首页交出、`runSend` 对已有对话也交、退回时不收窄、已有档位的对话也被覆盖、开始页芯片不读暂存。
- GUI 点验（隔离 profile，只用本机假网关）：SDK 引擎在开始页选跳过权限确认，确认框的范围说明单独成行；第一句话里的写文件与建目录都不出卡直接执行，新对话芯片为红色「跳过权限确认」；回到开始页仍是手动审批，新对话默认没被写。DSH（glm-fake-1）同样可选、新对话为「完全放行」；假网关的 DSH 回复不调工具，DSH 侧是否按完全放行起 worker 由既有的"按会话那一行起 worker"路径与单测保证。
- DSH 端到端（2026-10-16，S-4 会话在本修复的临时合并上做，未提交）：隔离 profile，本机假网关 `--plan dsh-p0-2`，关掉"Anthropic 协议的模型使用官方 Agent SDK"让 `claude-opus-5-5` 走 DSH。开始页选「完全放行」，确认框带"只作用于下一句话新建的对话。"；第一句话 `P0-FS`（`shell: pwsh`）的 12 次工具调用（读、编辑、写文件、PowerShell 读与写）都不出卡，三个目标文件按预期改写，新对话芯片为红色「完全放行」；回到开始页仍是「改动前确认」，默认没被写。对照：不开完全放行时同一句话停在「edit — 修改工作区文件」卡上，拒绝后什么也没写。
- 安装目录（2026-10-16）：[GUI 清单](gui-checklist.md) 第 3、9 项在打包后的程序上照走一遍，结果同开发版（清单 §2.1）。
- 受影响目录的测试（`src/renderer/components/chat`、WorkerManager）179 个文件全过；根 tsc 与宿主 tsc 无错。
