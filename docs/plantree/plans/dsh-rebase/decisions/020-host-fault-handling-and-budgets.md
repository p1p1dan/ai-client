# 决策 020：宿主级故障：心跳判卡死，只杀确切的子进程，一次重启后批量恢复，两级预算加熔断

日期：2026-09-26。**状态：自主决定，待用户审批。** 依据：[P1-3 方案 §4 D3、D4](../topics/p1-3-shared-host.md#4-需要拍板的决策点)。

## 规则

1. 心跳与判定：
   - 每 5 s 发一次心跳，20 s 内收不到宿主的任何消息，就判定卡死。
   - 两种情况不算卡死：Main 自己的计时器迟到超过 1 s，以及系统刚从休眠中唤醒。
2. 强杀：
   - 只用 `child.kill('SIGKILL')` 杀确切的子进程。不用 `process.kill` 自己算 pid，不杀进程组。
   - 5 s 内等不到退出，就进入 failed，不拉第二个宿主。卡死的宿主会一直持有会话锁，所以任何时候最多只有一个宿主。
3. 恢复：
   - 宿主崩溃后只重启一次。
   - 活着的会话在同一批里按「前台 → 在飞 → 其余」依次恢复。
   - 在飞的回合先收到 `disconnected`，再收到带 `dsh_host_crashed` 的 `session.failed`。
4. 预算：
   - 宿主级：5 min 内最多重启 3 次。
   - 会话级：60 s 内 2 次，只在会话自身原因导致恢复失败时才扣，包括会话缺失、cwd 不符、日志损坏。宿主崩溃不扣会话预算。
5. 熔断：某个会话连续两次出现在崩溃现场，就不再自动恢复它。
6. 宿主预算用完后，所有会话进入同一个 error（`dsh_host_unavailable`）。用户每次打开或重试，都允许再拉起一次宿主。

## 取舍

- 这对应 P0-6 必补清单第 3 条，目的是不让一个坏会话拖垮全部会话。
- 代价：
  - 真卡死时，所有会话最多停顿 20 s。
  - 熔断可能误伤恰好在跑的正常会话，但用户可以手动重试。
