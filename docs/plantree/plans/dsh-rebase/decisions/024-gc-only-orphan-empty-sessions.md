# 决策 024：DSH 日志只清理「索引里没有引用、没有内容、超过 24 小时」的会话

日期：2026-09-26。**状态：用户 2026-09-28 批准（[决策 090](090-user-rulings-2026-09-28.md)）。** 依据：[P1-3 方案 §4 D8](../topics/p1-3-shared-host.md#4-需要拍板的决策点)、[分片 03 §4](../topics/p1-3-shared-host/03-env-and-logs.md)。

## 规则

1. 必须同时满足三个条件才删：
   - 索引里没有引用，归档的行也算引用；
   - 只有 header 或没有事件，例如[决策 007](007-flush-dsh-session-before-stub.md) 留下的、首次发送就失败的会话；
   - 已超过 24 h。
2. 有内容的无主日志一律保留。
3. 执行方式：
   - 引用集合由 Main 从索引计算。2026-09-26 按 P1-4 补充：这个集合是「索引行的桩 → 桩里的 `dshSessionId` 和整条 lineage（[决策 027](027-rewind-and-fork-via-seeded-child-sessions.md)）→ 再加上这些会话的子代理子会话（header 里的 `parentSession`）」。
   - 由宿主在 ready、会话恢复完之后执行 `gc`，每次运行只做一次。
   - 逐个检查 `aiclient-*` 会话：先取写锁，确认没人占用，再删整个会话目录和对应的桩。
   - 绝不单独删锁文件。

## 取舍

- 与 1.0.x 保持一致：1.0.x 从不删会话文件，产品也没有删除入口，归档只是一个标志。本决策只清 DSH 路径带来的空壳，不碰任何有内容的会话。
- 不选「无主的一律宽限后删」或「先进回收站」：那会引入删除用户数据的新行为，需要用户另行决定。
- 代价：被挤出索引、但有内容的日志会一直留在磁盘上。

## 实施补记（2026-09-27，P1-3d `b3b58f2b`，待用户审批）

- 实测：只 bootstrap 未发送的会话不是「只有 header」，而是 header 加 3 个 setup 事件（`permission/preset`、`sandbox/mode`、`approval/policy`），约 308 B；一轮工具回合约 9.5 KB。所以「没有内容」按「header 加这 3 个 setup 事件」判定，出现其他任何事件都算有内容；文件超过 16 KiB 直接算有内容，不读。
- 先不取锁读一遍判空，再取写锁复查（旧格式用写方式打开时会触发迁移）。删除顺序：日志 → 整个目录（含锁）→ 桩。
- 另清孤立的桩：没有对应的会话目录、没有引用、超过 24 h。
- 触发时机：首次用户新建或恢复成功之后、或恢复批次结束之后，延迟 5 s；每次运行只做一次；读索引失败就不发。
- DSH `list()` / `stat()` 的实测字段：已落盘的是 `{header, revision, sizeBytes}`；本进程刚创建、未落盘的是 `{header, revision}`；JSONL 不给 `eventCount`。
