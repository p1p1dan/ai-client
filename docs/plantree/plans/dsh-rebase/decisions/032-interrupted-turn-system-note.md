# 决策 032：中断回合在历史里显示系统注记；崩溃时已流出的半截正文不落盘

日期：2026-09-26。**状态：用户 2026-09-28 批准（[决策 090](090-user-rulings-2026-09-28.md)）。** 依据：[P1-4 方案 §5 D8](../topics/p1-4-bridge-parity.md#5-需要拍板的决策点)、[P0-6 证据](../evidence/p0-6-shared-host-2026-09-26.md)。

## 规则

1. 恢复或冷读时，DSH 会补写 `turn/end interrupted`。投影把它显示为系统注记「本轮在引擎中断时未完成」；同一回合里的工具结果按错误码标记 `outcomeUnknown` 或 `notStarted`（`TOOL_OUTCOME_UNKNOWN`）。
2. 宿主被强杀时，已经流到界面的半截正文，只留在渲染层内存里（现有合并规则会保留没对上的运行期消息），不另行落盘。
3. 用户 Stop 或宿主优雅关停时不同：DSH 会把已流出的前缀以 `assistant/message {interrupted:true}` 落盘，历史里能看到。

## 取舍

- 不选「由 Main 把半截正文落成本地注记」：要新造一种存储，而且和 DSH 日志两处对账。
- 代价：强杀之后重开窗口，半截正文就看不到了。强杀只发生在宿主崩溃或卡死时，很少见。
