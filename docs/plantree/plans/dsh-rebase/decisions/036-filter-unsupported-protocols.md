# 决策 036：DSH 不支持的协议与字段一律过滤，并在菜单和服务设置里说明（用户自建服务有功能倒退，请重点审批）

日期：2026-09-26。**状态：用户 2026-09-28 批准（[决策 090](090-user-rulings-2026-09-28.md)）。** 依据：[P1-5 方案 §5 D4](../topics/p1-5-models-and-credentials.md#5-需要拍板的决策点)。

## 规则

1. DSH 手写路由只支持 `openai-completions`、`openai-responses`、`anthropic-messages` 三种协议。计划翻译时，不受支持的协议、compat 键和字段都丢掉，记进 `dropped` 并写日志。
2. 菜单底部提示「N 个模型在当前引擎下不可用」。用户服务设置里只能选这三种协议，并附上说明。

## 用户可见的变化

- 公司目录全在这三种协议里（随包快照 10 / 10），**托管模式不受影响**。
- 用户自建的 google、mistral、bedrock、vertex、azure、codex、pi-messages 服务，在 DSH 分支里**不可用**。有多少人在用，未知。

## 取舍

- 不选「给 `llm-pi-ai` 打本地补丁，加上这些协议」：要修改钉死版本的 DSH 包，每次升级都得重做。
- 不选「自己写一个 LLM 适配插件」：工作量大，而且与 DSH 生态脱节。如果以后确有用户需要，可以作为独立任务再议，记入想法池。
- 如果用户认为这项倒退不可接受，改走「自写适配插件」，并在 P1-5d 开工前定。
