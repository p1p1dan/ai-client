# 决策 050：旧会话在首次「继续」时迁移，只看不迁（请确认这是决策 004「首次打开」的口径）

日期：2026-09-27。**状态：自主决定，待用户审批。** 依据：[P1-9 方案 §5 D1](../topics/p1-9-migration.md#5-需要拍板的决策点)、[决策 004](004-branch-isolated-dsh-only.md) 第 3 条。

## 规则

1. 预览照旧：点开旧 pi 会话只做只读回放，不迁移。
2. 续聊、fork、回退这类需要引擎的操作，才触发迁移。迁移同步完成，完成后按普通 DSH 会话恢复。
3. 迁移失败时，索引不动，行仍是 pi，预览照常，渲染层显示「无法迁移」卡片（带错误码）。
4. 加密机上 Main 读不到明文，预览会失败并退回恢复，于是那里等价于「点开即迁移」，结果一样。

## 与决策 004 的关系

决策 004 第 3 条写的是「首次打开时复制一份转为 DSH 格式」。本决策把它理解为「首次续聊时」：
- 这仍满足原意：复制转换、原文件不动、用户无感；
- 只看过的会话不产生副本，回装 1.0.x 后更干净。

**如果用户的原意就是「点开即迁」，改为选项 B 即可，实现差别很小。**

## 取舍

- 不选「升级后后台批量迁移」：首次启动时会压满共享宿主，而且大多数旧会话以后不会再用。
- 代价：首次续聊要多等约 0.5～2 s（推断）。
