# 决策 055：迁移时，被 Stop 的半截回复保留为 `interrupted` 助手消息（模型可见）；出错的回复记为 attempt（请重点审批）

日期：2026-09-27。**状态：用户 2026-09-28 批准（[决策 090](090-user-rulings-2026-09-28.md)）。** 依据：[P1-9 方案 §5 D6](../topics/p1-9-migration.md#5-需要拍板的决策点)。

## 规则

1. 1.0.x 里 aborted 且有正文的回复，迁移成 `assistant/message {interrupted:true}`，并去掉其中没派发的工具调用。
2. error 的回复迁移成 `assistant/attempt`（空流），不进模型上下文。

## 与 1.0.x 的差异

- 1.0.x 的模型上下文会过滤掉 aborted 的回复。迁移之后，模型会看到这些半截回复，多用一点 token。
- 这与 DSH 自己的行为一致：DSH 在 Stop 时就是这样落盘的，迁移后新发生的 Stop 也会这样。

## 取舍

- 选 A 的主要理由：界面保留被停回复的半截正文，用户看到的历史与迁移前一致。
- 备选 B「一律记为 attempt」：模型上下文与 1.0.x 完全一致，但半截正文会从界面上消失，用户会以为历史丢了。
- 如果用户更看重模型上下文与 1.0.x 逐字一致，改为 B，实现差别只在转换规则里的一条。
