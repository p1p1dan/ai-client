# 决策 060：首批白名单只有一个试点插件 `dsh-office-tools@1.0.4`，默认关闭；审查通过、用户批准后才随包（请重点审批）

日期：2026-09-27。**状态：用户 2026-09-28 批准（[决策 090](090-user-rulings-2026-09-28.md)）。** 依据：[P1-10 / P1-16 方案 §5 D5](../topics/p1-10-p1-16-extensions.md#5-需要拍板的决策点)、[决策 001](001-route-b-and-scope.md) 第 2 条。

## 规则

1. P1-10d 按审查单（分片 03 §6.2）审查 `dsh-office-tools@1.0.4`，审查记录落库。它在 P0-2 已跑通，没有运行期依赖。
2. 审查通过、并经用户批准后，它作为默认关闭的试点随包，用来走通真实插件的整条链：预装、启用、过闸、审批、打包冒烟。
3. 用户不批准的话，就退到 B：P1 不随包分发任何第三方插件，只用测试夹具插件验证机制。
4. 过闸分类要独立核实：目录里标的是只读，实际会写文件，所以按「写」分类，出审批卡。

## 取舍

- 走通真实插件的整条链，比只用测试夹具更能暴露问题；办公文档也贴近用户场景。
- 插件与宿主同进程同权（决策 019）：能拿网关 key，也能绕过工具闸门直接用 fs、子进程和网络。审查是唯一的硬防线。所以随包分发第三方代码，要用户点头。
- 默认关闭时，插件不参与组合，代码只是躺在安装目录里。

- 已按审查单审查，结论「有条件通过」，以 `internal`、`defaultEnabled: false` 进白名单；审查记录在 `src/dsh-host/plugins/reviews/dsh-office-tools-1.0.4.md`。
