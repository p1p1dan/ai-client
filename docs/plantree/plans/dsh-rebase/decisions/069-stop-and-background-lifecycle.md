# 决策 069：Stop 连带停子代理、不停后台命令；后台完成后的自动唤醒保留，连续唤醒上限 3（行为取舍，请重点审批）

日期：2026-09-27。**状态：用户 2026-09-28 批准（[决策 090](090-user-rulings-2026-09-28.md)）。** 依据：[P1-7 方案 §5 U3](../topics/p1-7-renderer.md#5-需要拍板的决策点)、runtime-hardening 决策 041 第 4 条。

## 规则

1. 用户按 Stop 时：
   - 打断可续跑子代理的当前回合，停掉一次性的后台子代理；
   - 不停后台命令。后台命令在界面上看得见，能单独停。
2. 后台任务或子代理完成后，照 DSH 的做法自动唤醒会话续跑，但设 `maxConsecutiveWakes: 3`，防止自激链。3 这个数没有实测依据，等实验 E6 之后再定。
3. 这保住了用户拍板过的 runtime-hardening 决策 041 第 4 条。

## 取舍

- 不选「都不停，唤醒不设上限」（DSH 原生）：用户离开时可能被一连串自动回合刷屏、弹审批卡。
- 不选「都停，完成后不唤醒、等下次发送再交付」：目标与子代理本来就靠唤醒续跑，全停会让目标模式失效。
- 代价：用户离开时仍可能自动续跑、弹审批卡。
