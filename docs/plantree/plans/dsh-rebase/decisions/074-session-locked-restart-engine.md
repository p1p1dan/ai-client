# 决策 074：`session_locked` 卡片上的「强制接管」改为「重启引擎」，并总是提供（请重点审批）

日期：2026-09-27。**状态：自主决定，待用户审批。** 依据：P1-3c 实现（`613d0568`）、[P1-1 证据](../evidence/p1-1-engine-cutover-2026-09-26.md)「遗留与后续」、[决策 020](020-host-fault-handling-and-budgets.md)、[021](021-stop-escalation-ladder.md)。

## 规则

1. DSH 下，会话恢复遇到 `session_locked` 时，卡片上的按钮从「强制接管」改为「重启引擎」，旁边写明代价：会中断其他会话正在生成的回复，它们会自动重连。
2. 这个按钮总是提供。点击后，Main 在冷恢复前做一次用户发起的宿主重启，这次重启不计入宿主预算。
3. 实现沿用 IPC 里已有的 `forceTakeover` 标志，没有新增 IPC。旧的「强制接管」文案删掉。

## 取舍

- DSH 的锁是内核锁，能释放的只有我们自己宿主里卡住的 agent，所以「接管」这个说法已经不成立，只能重启宿主。
- 不选「只在没有其他会话在跑时才提供」：判断有竞态；而且只要有一个会话在忙，被锁住的会话就没有任何出路。
- 代价：用户点了之后，其他会话正在生成的回复会被中断，再自动重连。

## 遗留

关会话、驱逐、空闲回收时，如果通道关不掉，不会升级到阶梯 B，锁要等下次宿主重启才释放。目前靠这个按钮兜底；P1-3d 考虑自动升级。
