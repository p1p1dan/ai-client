# 决策 076：P1-9b 转换器的六处实现取舍

日期：2026-09-27。**状态：用户 2026-09-28 批准（[决策 090](090-user-rulings-2026-09-28.md)）。** 依据：P1-9b 实现（纯转换器 `src/shared/legacyPiSession/convert/`）、[P1-9 方案 §4.2](../topics/p1-9-migration.md#4-方案)、决策 052～056。

## 规则

1. **压缩**：pi 压缩后只保留用户消息（1.0.x 的做法）。转换时，把压缩区间整段遮掉，再把 pi 保留的那些副本以隐藏来源 `aiclient-pi-retained` 追加在检查点之后。锚点先认 `firstKeptEntryId` / `throughMessageId`，再按（role, timestamp）依次试每条保留消息。原方案写的是「保留锚点起的原件」，那样会把整个活动回合都留在上下文里，与 1.0.x 不一致。
2. **被 Stop 的 `interrupted` 助手消息不带 `replayState`**：DSH 自己停下时也不带；1.0.x 也从没把这段半截签名发给过 provider。
3. 展示行、来源行、委派记录的数据里多带一个 `entryId`，供投影还原 `h:<条目 id>`。
4. 导入会话的 id 用 `imp-<dedupeKey 的 sha256 前 12 位>-<序号>`。原来的 dedupeKey 前 12 位基本都是 `claude-code:`，会撞。
5. SDK 未完成的运行，在末尾补一个空的 `interrupted` 回合，不把最后一个正常结束的回合改成中断。
6. 一条回复的工具结果还没到齐时插进来的输入，留在当前 step 里，避免调用与结果错配。

## 结果

E4 比对：模型上下文与 1.0.x 一致（含 3 份压缩样本），只有两类预期差异：决策 055 的半截回复、崩溃时补写的 unknown 结果。30 份语料里 27 份转换成功，并通过自带的校验器；另外 3 份损坏样本的失败阶段和错误码，与 1.0.x 读不了这些文件时一致。

## 补记（2026-09-29，P1-9c，决策 121）

第 1 条的压缩写法要补一处。P1-9c 开工实验 E1 发现：DSH 读盘时，要求每个替换型检查点都落在一次压缩事务里；种子构造器不查这一条，所以按原写法写进去的会话读不回来（语料里 8 份）。

编排者裁定，转换器从版本 2 起照 DSH 实时压缩的写法，在检查点外面包上 `compaction/start` → `compaction/summary` → 检查点 → `compaction/end`：

- 遮盖区间、保留尾的规则不变；
- 模型上下文与历史投影不变（投影金样本没有差异）；
- 细节见[决策 121](121-p1-9c-seed-session-choices.md) 第 1～4 条，证据见 [p1-9c-seed-experiments-2026-09-28](../evidence/p1-9c-seed-experiments-2026-09-28.md)。
