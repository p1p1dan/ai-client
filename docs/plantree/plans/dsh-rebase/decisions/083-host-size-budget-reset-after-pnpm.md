# 决策 083：去掉 pnpm 后重定宿主体积上限（修订决策 014）

日期：2026-09-28。**状态：用户 2026-09-28 批准（[决策 090](090-user-rulings-2026-09-28.md)）。** 依据：P1-10a 实测（`ad999a0f`），[决策 014](014-host-size-budget.md) 第三条「P1-10 加预装插件时重定」。

## 规则

| 项 | 决策 014 | 现在 |
|---|---|---|
| 每平台解压后硬上限 | 128 MiB | **100 MiB** |
| 文件数硬上限 | 1.2 万 | **1.1 万** |
| 目标（只报告） | 110 MiB | **92 MiB** |
| 单个预装插件（含依赖闭包） | — | **5 MiB / 500 个文件**；超出须在白名单的 `limits` 里登记，并附审查记录 |

## 取舍

- 实测（同一个 HEAD）：
  - linux-x64：82.1 MiB，9,760 个文件；
  - win32-x64 静态预演：84.6 MiB，9,758 个文件；
  - darwin-arm64 静态预演：80.4 MiB，9,760 个文件。
- 新上限给约 3 个默认大小的插件留了余量。下面三种典型的裁剪遗漏，任何一种都会超限：
  - 忘记删 `.map` / `.d.ts`：+55 MiB；
  - 带上 node-pty 其他平台的预编译件：+23 MiB；
  - 带上 sharp 的 musl / wasm32 变体：+27 MiB。
- 上限收紧意味着：试点插件 `dsh-office-tools`（决策 060）或 P1-5 以后新增的宿主文件如果让产物逼近 100 MiB，构建会直接失败，必须重新审批额度，而不是悄悄变大。
