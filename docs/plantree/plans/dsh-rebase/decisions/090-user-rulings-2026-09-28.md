## Q009 的绕行办法（P1-13c 重新定义）

P1-13b 的原始矩阵显示：node.exe 读成密文的 9 类文件里，有 6 类（yml、php、ps1、cmd、sql、scss）**Windows PowerShell 5.1 能读出明文**；rb、docx、pptx 所有读者都读不出。

办法：在宿主的读文件路径上加一层回退（只在 Windows 上）：
- node 读到的内容以 TSD 文件头开头时，改由 `powershell.exe`（5.1）读同一个文件的字节；
- 读出明文就用它；还是密文，就返回明确的错误（「此文件被加密策略保护，无法读取」），不把乱码交给模型。

读写的其他路径不变；写入维持 DSH 的做法（新文件不加密，按 089 的推翻结论）。实现与验证都放在 P1-13c，做完后上加密机验一次。

## 对用户两个问题的答复

- **DSH 默认不用 MCP 吗？** 对。dsh-base 只挂了 `mcp-resources`，也就是 3 个读 MCP 资源的工具，必须另装连接插件注册了服务器才有用；官方的 `dsh-mcp-client` 不在默认依赖里。所以默认装好的 DSH 没有 MCP。
- **DSH 有自己的子代理，「自定义子代理」指什么？** 指用户自己写的子代理定义：1.0.x 允许在 `<agentDir>/subagents/*.md`、`~/.agents/subagents/*.md` 里放 Markdown 文件，定义一个带专属提示词、工具范围、模型的子代理，再加上我方内置的 4 个。DSH 自带的是通用的 `subagent` 工具，不读这些定义文件。决策 062 / 070 原本打算做一个 `delegate` 工具把这些定义接进来，约 1 人周。**按「跟随 DSH」的总原则，建议不做**：只用 DSH 自带的子代理；1.0.x 用户写过的自定义子代理在迁移时给出提示。等用户确认。
