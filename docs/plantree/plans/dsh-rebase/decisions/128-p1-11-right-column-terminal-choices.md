### 二、会话栏按钮

2. **位置与样子照原型**：在「后台任务」「子代理」那一组里排第一个，三者共用一条左分隔线；样子与两个子窗口按钮相同（`h-6`、`px-2`、`text-meta`，按下时 `bg-selection`），图标用 Lucide `Terminal`（原型的 `i-terminal` 就是它）。按钮只在有当前会话时出现，和那两个按钮一样。
3. **收成图标的规则：窗口窄于 `xl`（1280 px，原有规则），或者会话栏自己窄于 42rem（672 px），会话栏所有带文字的按钮都只剩图标**（「会话分支」「审阅」「终端」「后台任务」「子代理」）。会话栏本身是 `@container`，另加 `overflow-hidden` 兜底。
   - 与原型的不同：原型第二轮选了「会话栏止于中栏右边界」这一支，理由是「真实代码只有视口断点，做不到宽屏也收成图标」。这个前提不成立：Tailwind v4 自带容器查询。而按第 7 条的真实列宽，右列打开时聊天列在 1440×900 下是 558 px、1280×720 下是 436 px，带文字的按钮组本身就要约 520 px，只靠「标题先收缩」仍会压到右列标签栏上（就是第二轮打回的那个问题）。所以两条都做：窄栏收图标是真正的修法，`overflow-hidden` 只兜底。
   - 顺带：「会话分支」「审阅」原来在窄窗下也不收，原型 1024、1280 两档截图里它们是图标，这次一起收。
   - 右列关着时，1280 及以上宽度会话栏够宽，文字照常显示。
4. **「没有绑定目录」沿用现有判定 `resolveTerminalWorkspace`**（左栏终端面板一直在用的那条链：当前会话 → 它的工作区 → 非空路径）：
   - 置灰：没有当前会话、会话指向的工作区不在列表里、工作区路径为空。未绑定目录的会话（会话栏标着「临时」的那种）虽然有一个临时目录，但那不是用户选的目录，也置灰，不拿它兜底（126 第 2 条）；
   - 可用：主目录、worktree、「临时会话」功能建的临时工作区（它有真实目录）、远程工作区。远程工作区走现有的远程会话通道（`SessionManager.createRemote`，在远端开 shell），头部显示远端路径（`getDisplayPath`）；
   - 置灰时 `title` 写原因「会话未绑定目录，无法打开终端」。禁用的按钮收不到鼠标事件，外面包一层 `span` 带同样的 `title`（`FailureContinueButton` 的做法）；
   - 备选：远程工作区也置灰。派工说明把「远程路径」列进了「没有绑定目录」的例子，但同一句要求「按现有判定」，而现有判定把远程工作区当有目录。**用户如果希望远程工作区不开终端，改一行即可。**
5. **按钮四种状态**：置灰、未打开、已打开（按下态）、**在后台运行**（没按下，多一个 `bg-status-running` 小圆点，`title` 为「终端（仍在运行）」）。小圆点是原型没有的：终端被收到后面时 shell 还活着，没有标记就成了看不见的进程。
6. **按钮是「显示 / 收起」，标签上的 × 才是「关闭」**。原型里两者是同一个动作；这里分开，因为打开文件时终端必须让位而不能杀掉 shell（第 10 条），这个「收起但还活着」的状态本来就得有；让同一个按钮一会儿收起、一会儿杀进程，误点会把正在跑的 dev server 杀掉。
   - 按钮：已打开 → 收起（shell 继续跑）；未打开 → 起一个 shell 并显示；在后台运行 → 把同一个 shell 放回前面。打开终端时关掉审阅面板，编辑器 / 审阅处于展开覆盖态时先还原；
   - ×「关闭终端」、在 shell 里 `exit`：结束 shell，文件标签露出来。

### 三、右列

7. **列宽完全沿用编辑器列**：同一个 `--shell-editor-w`、同一个 `editorRatio`、同一个聊天列右缘拖拽手柄；终端的最小宽度也用编辑器的 `EDITOR_MIN_WIDTH`（520 px），不用审阅面板的 320 px，这样在文件和终端之间来回切换时手柄不会跳。
   - **默认宽度因此不是 460 px**：默认比例 0.5 下，1440×900 是 558 px，1280×720 是 520 px（编辑器下限），1920 宽是 798 px。原型的 460 px 是静态占位，README 说它「约等于中栏对半分」，按默认侧栏宽度算中栏对半其实是 558 px。126 第 3 条前半句「沿用编辑器列的拖拽宽度机制，不另定一套」与后半句「默认约 460 px」在真实尺寸下不能同时满足，这里按前半句。
   - 备选：终端单独用 320 px 下限，1024 档少溢出约 200 px，但文件和终端切换时手柄会跳；或者单独定默认比例，这就是「另定一套」了。**用户若更在意 460 这个数，请明示。**
8. **三者叠放，谁在上面显示谁**：审阅面板最上，其次是「在前面」的终端，最后是文件。纯函数 `resolveRightColumnOccupant`。
   - 打开审阅：盖住终端（或文件），关掉审阅就露出原来那个；
   - 打开终端：关掉审阅；
   - 打开文件（文件树、工具行里的文件、差异标签、同一工作区里切换活动标签）：关掉审阅，终端退到文件后面（不结束）。沿用原来「打开文件就关审阅」的那个 effect；
   - 审阅面板的「文件」按钮：关审阅，同时让终端退后，保证露出来的是文件；终端头部在有文件标签时也有同样的「文件」按钮（照审阅面板的做法）；
   - 差异标签在前台时聊天列整列让位的规则（D35）只在文件真正显示时生效，审阅或终端盖着时不生效。
9. **头部照原型与编辑器**：`h-10` 的栏里一个 `h-9` 标签（顶部 `h-0.5 bg-primary` 指示条、终端图标、「终端」、× 常显 60% 透明度）；下面一行「会话目录」+ 路径（`Ident` 等宽、单行截断、完整路径在提示里），位置对应编辑器的面包屑。没有「展开」按钮（原型没有）。字号用 `text-ui` / `text-meta`，这两个目录下禁用 `text-xs`。
10. **终端本体**复用 `ShellTerminal` + `useXterm` + `session:*`，工作目录是会话目录；关掉拆分（这一列只有一个 shell，右键菜单与快捷键里的「拆分」都不可用）；底色取终端主题背景（开了背景图时透明），终端四边内缩 8 px，与 `TerminalPanel` 一致；字体、主题、渲染器都走现有的 `terminal*` 设置。整列带 `data-surface-holds-escape`，Esc 留给 vim、less 和终端搜索栏。只有正在显示的那个终端算「活动」（拿焦点、响应 Ctrl+F）。

### 四、生命周期

11. **每个目录一个 shell，不是每个会话一个**：同一目录下的几个会话共用一个终端（键是 `TerminalPanel` 按 worktree 分组时用的同一个规范化路径）。理由：与左栏终端面板按 worktree 分、编辑器按工作区隔离标签的做法一致；按会话分会在同一个仓库里开出一堆 shell。
12. **「在前面」按目录记，切换会话不会自动起 shell**：切到另一个目录的会话，右列显示那个目录自己的状态（它的终端若在前面就显示终端，否则显示它的文件）；切回来，原来的终端还在前面。与浮动子窗口「开关是全局一个」的做法不同（119），因为打开终端会起进程，全局开关会让每次切换会话都在新目录里起一个 shell。
13. **切走不结束**：别的目录的 shell 继续跑，挂在右列里不可见（`invisible`，保留布局盒子，不用 `display: none`，否则 FitAddon 量到 0 宽，pty 被缩到 2 列）；没有东西占右列时，按「右列若打开会有的宽度」留盒子，回来时不用重排。这与左栏终端面板保留别的 worktree 的终端一致。
14. **什么时候结束**（本地 shell 都是 `persistOnDisconnect: false`，视图卸载时 detach 即结束）：
    - 标签上的 ×、在 shell 里退出；
    - 工作区被删：临时工作区删除时的 `closeTerminalSessions`（右列在 `worktreeActivity` 上登记了处理函数，结束该目录及其子目录下的终端）；删 worktree 时 Main 的 `killByWorkdir` 杀掉 pty、发出退出事件；
    - 关窗：Main 的 `detachWindowSessions`；退出：`destroyAllTerminals`；登出：`destroyAllLocalAndWait`，此时整个应用界面也换成欢迎页；
    - 承载它的界面卸载（登出回到欢迎页）：清空右列终端的记录，重新登录后不会在原目录里自动起 shell。副作用：开发时热更新 `WorkspaceShell.tsx` 也会清空并结束这些 shell（只影响开发）。
15. **登录 / 登出确认框的终端数把右列终端算进去**：右列终端单独一个 store（`stores/columnTerminal.ts`），计数时与 `useTerminalStore.sessions` 相加。没有塞进 `useTerminalStore.sessions`，因为左栏的 `TerminalPanel` 每次同步都整体替换那个列表，会把右列的冲掉。
16. **不用 `worktreeActivity.setActivityState`**：它是给侧栏的代理活动状态用的；「终端还在跑」由按钮上的小圆点表示（第 5 条）。127 第 14 条说它「留给右列终端的活动指示」，这里用不上，仍留着无人调用。

### 五、worktree 初始化脚本

17. **保持现状：初始化脚本仍在左栏的终端面板里跑**，`openInitializationTerminal` 与 `pendingScript` 的消费方都不动。理由：
    - 改到右列本身不难（建 worktree 后直接在新目录开一个带 `initialCommand` 的右列终端），但改完左栏终端这一整套（`TerminalSurfaceView`、`TerminalPanel`、`TerminalGroup`、`terminalSurfaceModel`、注册表里的 `terminal` 项、`open-initialization-terminal` 动作、`stores/initScript`）就没有任何入口了，要么顺手删掉约 1.5k 行加测试（超出本任务），要么留一堆死代码；
    - 已知的别扭：同一个目录可能同时有左栏里的初始化终端和右列终端两个 shell；左栏那个一旦切到别的面板就没有入口回去（这是 09-04 撤掉终端入口时就有的）。
    - **建议另开一个小任务**：初始化脚本改在右列终端里跑，同时删掉左栏终端这一套。决策 109 已经不要「左栏面板」这个终端位置，这样改更一致；是否做、何时做请用户定。

### 六、`SessionKind` 与 Main

18. **`SessionKind` 收窄为 `'terminal'`**，`SessionManager.create` 去掉对 `'agent'` 的拒绝分支，改为**每次创建都把 `kind` 盖成 `'terminal'`**（本地与远程都是）。理由：IPC 载荷在运行时没有类型，远程助手看到 `'agent'` 会不经 shell 包装直接跑 `initialCommand`；盖章比拒绝更彻底，也不再留一条专门报错的死分支。`useXterm` 去掉 `kind` 选项（唯一调用方 `ShellTerminal` 从没传过）。
    - 远程助手源码 `RemoteServerSource.ts` 里的 `'agent'` 分支不改：它是部署到远端主机的脚本，改动会让已部署的助手与本地不一致；Main 已保证不会再发 `'agent'` 过去；
    - `spawnGate.ts` 的注释去掉「`SessionManager.create` 的 agent 分支」这个已不存在的调用方。

## 影响

- **用户看得见的**：会话栏多一个「终端」按钮；右列可以在文件、审阅、终端之间切换；右列打开时会话栏按钮变成图标；未绑定目录的会话按钮置灰。
- **没有改**：宿主、bridge、`src/runtime`、`src/agent-host`、远程助手脚本、左栏终端面板与初始化脚本的流程、`package.json` 与锁文件、`implementation-status.md`、`roadmap.md`。
- **没有做 GUI 点验**（本机不启动 Electron）：挂载测试覆盖了行为，外观（容器查询断点、标签栏对齐、小圆点、置灰样式、终端内缩与底色）需要编排者或用户点验，要看的点见交回报告。
