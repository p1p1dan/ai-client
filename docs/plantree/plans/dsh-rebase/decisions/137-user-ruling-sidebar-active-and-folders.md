# 决策 137：侧栏改版——新增「正在活动」、「最近」默认折叠、点工作区只折叠、每个工作区默认只列 8 条

日期：2026-09-29。**状态：用户裁决（2026-09-29）。第 1、2 条与第 3 条的上限由用户提出；「正在活动」的范围与第 4 节的收回方式由编排者建议，用户确认「就按你说的」。**

依据：用户在 P1-7d 第 1 批点验汇报后补充的三条要求：
1. 「侧栏『最近』这一栏很鸡肋。我认为可以默认折叠，然后加一栏『正在活动』，这一栏中列出当前已经启动、正处于活跃的对话。」
2. 「点击工作区文件夹，应该是折叠这个工作区条目。现在的逻辑是先把焦点切到这个工作区，打开里面最近的一条对话，再点一下才是折叠。」
3. 「工作区可显示的条目限制一下，例如 8 条，超过的部分要点击展开或者查看更多才全部列出来。然后怎么收回也要考虑下，是展开后一直显示全部还是就这一次显示全部。」

现状（代码）：
- `src/renderer/components/workspace-shell/LeftNav.tsx`：「最近」一节的折叠状态存在 localStorage；默认展开，最多 7 条，带「显示更多（N）」/「收起」。
- `sidebarTree.ts` 的 `deriveRecentRows`：运行中或 48 小时内动过的会话。
- 工作区标题的点击走 `resolveFolderClickActivation`（旧决策 D29 / open-q #28 A）：点别的工作区时先激活并打开里面最近的一条对话，再点一次才折叠。

## 1. 「正在活动」一节（新增，放在「最近」之上）

- **列哪些对话**：本次运行里已经在宿主上启动了会话的对话，也就是 store 的 `hostBoundSessionIds`，另加任何正在跑回合的对话。只是在侧栏预览过、没有发送过的对话不算。
- **排序**：正在跑回合的排前面，其余按最后活动时间排序。
- **行样式**与工作区里的会话行相同。运行中的行带转圈，等审批或提问的行带提示点。同一个对话在「正在活动」和它所在的工作区里各出现一次，与现在的「最近」一样。
- **没有活动对话时**整节不显示。
- 宿主容量回收（6 个）或宿主重启后，被回收的对话自然离开这一节。
- 顺带修第 1 批点验的问题 3（侧栏乱序）：写会话状态不应刷新 `updatedAt`，否则没碰过的对话会跳到顶部。

## 2. 「最近」默认折叠

- 首次使用、以及 localStorage 里没有记录时，默认折叠；用户展开或折叠过就记住，沿用现有的存储键。
- 其他行为不变：48 小时窗口、最多 7 条、「显示更多」。

## 3. 点工作区标题只折叠 / 展开

- 点工作区标题只切换这个工作区的折叠状态，不切焦点、不打开对话。
- 旧决策 D29 定的「点别的工作区先激活」作废。
- 「新建对话」要落到哪个工作区，仍由当前选中的对话决定；工作区标题行的悬停菜单（配置、移除等）不变。

## 4. 每个工作区默认只列 8 条（收回方式由编排者建议）

- **默认**：每个工作区最多列 8 条对话，超出时最后一行是「查看更多（N）」。
- **展开**：点「查看更多」列出全部，列表末尾换成「收起」。
- **建议：展开只在本次运行内有效，不持久化**。按工作区分别记在内存里：切换对话、折叠再展开这个工作区都保持；重启应用后回到 8 条。理由：
  - 与「最近」一节现有的「显示更多 / 收起」行为一致，用户不用学两套；
  - 持久化会让一个对话很多的工作区永久撑长侧栏，改版的初衷就是控制长度；
  - 「只这一次」（点别处就收回）会在切换对话时反复跳动，列表位置不稳定。
- **当前选中的对话始终可见**：它排在第 8 条之后时，折叠状态下也额外列在末尾（「查看更多」之上），不会出现选中的对话在侧栏找不到的情况。
- 搜索框有输入时不受 8 条限制，照旧列出全部匹配。

## 影响

- 渲染层：`LeftNav.tsx`、`sidebarTree.ts`，以及相关的挂载测试与纯函数测试。旧决策 D29 的测试要随之改写。
- 用户可见的新文案：「正在活动」「查看更多（N）」；「收起」复用现有词条，要进 `src/shared/i18n.ts`。
- 执行时机：P1-7d 三批点验做完后，与第 1 批发现的问题一起修，避免点验期间改渲染层代码，被热更新造成假故障。
