## 规则

### 决策 137 的实现细节

1. **「正在活动」的口径**：`hostBoundSessionIds` 里的对话，加上任何状态为 starting / running / stopping / waiting_permission / waiting_question 的对话。孤儿行的处理与「最近」相同（临时对话保留，找不到工作区的丢掉）。搜索框有字时这一节也按标题过滤，当前打开的对话照 T091 豁免。这一节**不设条数上限**（宿主池只有 6 个，再加上正在跑的，数量天然有限），也**不带折叠按钮**。只在有仓库的正常视图里显示；还没添加仓库时的空状态视图里没有「最近」，也不加这一节。
2. **转圈与提示点用在所有分区的会话行上，不只「正在活动」**：137 说「行样式与工作区里的会话行相同」，行组件是共用的，所以原来的 6px 运行点整体换成：运行中（starting / running / stopping）用 @coss/ui 的 `Spinner`（`size-3`、`text-status-running`，无障碍标签「运行中」）；等审批、等回答用 6px 的 `bg-warning` 提示点，悬停与读屏分别说「等待审批」「等待回答」。代价：转圈比原来的点宽 6px，一行开始或结束运行时标题会左右移 6px。
3. **「最近」的默认值**：只有存储里明确写着 `'false'`（用户展开过）才展开；没有记录、读存储失败、值不认识，一律折叠。存储键不变（`aiclient-sidebar-recent-collapsed`）。
4. **点工作区标题连「新建」的目标也不再改**：以前点标题会顺带把 `focusedProjectId` 指向这个工作区，决定顶部「新建」落在哪里。137 第 3 条说「新建」仍由当前选中的对话决定，所以标题点击里这一句也删了；`focusedProjectId` 现在只由「在侧栏里点开一个对话」写入，解析顺序本身不变。D29 的两个纯函数与它们的 9 个单测一并删除，静态测试改成钉住「标题点击只翻转自己的展开状态」。
5. **8 条上限也用在「临时对话」组**：137 写的是「每个工作区」，临时对话组在侧栏里的形状就是一个文件夹，同样会越积越长，所以一并套用，行为完全相同。
6. **「查看更多」的细节**：
   - 选中的对话排在 8 条之后时补在末尾（「查看更多」之上），**不计入** N；
   - 展开状态按文件夹 id 存在 `LeftNav` 的组件状态里。`LeftDock` 对各面板是常驻挂载，切换面板、切换对话、折叠再展开都保持；重启回到 8 条。与「最近」的「显示更多」同一个存放方式；
   - 全部列出且超过 8 条时末尾是「收起」（复用 `Show less` 词条）；
   - 按钮是 `h-7`、`rounded-sm`，悬停与键盘焦点同一层底色。

### 问题 3：侧栏乱序

7. **`updatedAt` 只记真实活动。** 算活动的：用户消息开始（`message.started` 且 role 为 user，包括引擎自己起的回合，比如目标的下一轮）、回合结束（`session.completed`、`session.failed`、`session.stopped`，但「Stop 时本来就没有回合」的 `no_active_turn` 不算）、首次发送建会话（`session.created`）、改名、新建与「新建」复用、改目标工作区。不算的：一切写状态（`session.status`、审批 / 提问挂起、失败后的收尾 idle）、`session.resumed`、预览与历史回放（历史回放原本就按消息自己的时间，未改）。时间只往前走，不会倒退。
8. **Main 侧同样处理**：`SessionIndexService.commitResumed` 以前每次重开都把索引行的 `updatedAt` 改成当前时间。宿主重启后 Main 会重开所有会话，而渲染层合并索引时取两边较大值，于是下一次刷新索引（比如随便改个名）时，这些没人碰过的对话又会一起跳到顶部。现在重开不改时间。连带影响：索引超出容量时按最旧的 `updatedAt` 淘汰，现在「只被重开过」的对话不再因此算新，这是想要的。

### 问题 26：重命名被抢焦点

9. **是谁调的 `focus()`**：右键菜单自己。Base UI 的菜单关闭时会把焦点还回去。右键菜单锚在鼠标点上，没有 DOM 上的触发元素可还，于是它去查一张**模块级、跨所有弹层共享**的「之前聚焦过的元素」表，取最后一个仍在文档里的。点「重命名」后，这一行被编辑框替换、从文档里移除，表里剩下的最后一个往往就是对话输入框：此前从输入框打开过任何弹层（模型菜单、斜杠菜单、分支对话框等），输入框就会被记进这张表。归还发生在菜单卸载后的微任务里，正好晚于编辑框的 `autoFocus` 1～3 ms，于是编辑框失焦，失焦按原标题提交，编辑结束。这也解释了为什么「同一次运行里做过迁移、分支对话框、发送之后」必现，新启动时不现。挂载测试复现了这个现象：去掉修复后，编辑框一打开就被关掉；只加第 10 条的修复，测试就能通过。
10. **修法**：会话行的右键菜单加 `finalFocus`，重命名进行中时返回 `false`，即不归还焦点。其他方式关闭菜单（Esc、点外面、归档、结束对话）照旧归还。
11. **失焦提交的兜底**：只有用户自己离开编辑框才提交，判据是失焦前 1 秒内有编辑框外的指针按下（捕获阶段监听 `pointerdown` / `mousedown`），或在编辑框里按了 Tab、Ctrl / ⌘ / Alt 组合键。整个窗口失焦（切到别的程序）时不提交，保持编辑，窗口回来时焦点自然回到编辑框。其余失焦算代码抢焦点：把焦点拿回来，不提交；每次编辑最多拿回 2 次，防止与对话框的焦点陷阱无限拉锯，超过后按已键入的内容提交。Enter 提交、Esc 取消不变。

### 问题 34：首条消息前改名悄悄失败

12. **不提前写索引**：没发过消息的对话没有索引行，这是 R5 第二轮 A3 的有意设计（打开又放弃的对话不应在重启后留下来）。如果为了改名先注册索引行，每个改过名但没发送的对话都会永久留在索引里，所以没有这样做。
13. **改名在内存行上生效，首条消息把名字写进索引**：判定为「从未绑定宿主、没有运行身份」的对话（与归档的判定同一个函数），改名直接改侧栏里那一行（同时算一次活动），并记在 `draftSessionTitles` 里。首条消息被接受时，`applyAutoSessionTitle` 不再用消息生成标题，而是把用户起的名字写进刚建好的索引行。写入失败时保留记录，名字仍在内存行上。如果用户把名字又改回占位标题（如 `New chat`），就照常用首条消息命名。
14. **没发送就重启，名字随对话一起消失**：这与所有未发送对话一致，不算回归。
15. **其余失败会提示**：已进索引的对话改名被拒或 IPC 出错时，弹错误提示「重命名失败」，侧栏保留原标题。注意这个提示受问题 11 影响（toast 不会自动消失，归 e3 组）。

### 问题 32：过渡标题的后缀被截掉

16. **悬停早就能看到全名**：会话行本来就带 `title={row.title}`，改动前后都一样。这次的改进是把后缀做成不截断的附注：标题以 `LEGACY_FORK_TITLE_KEY` 的中文或英文后缀结尾时，拆成「前段 + 后缀」两段，前段可截断，后缀 `shrink-0`、用 `text-muted-foreground`，英文形式中间留一个间距。
17. **按文字识别，不按 `forkTitlePending`**：只发图片的首条消息会清掉这个标记，但过渡标题会一直保留，这种情况后缀也必须完整显示。用户自己起的名字恰好以同样的后缀结尾时，显示方式相同，没有副作用。两种后缀从词典里生成，不另写字面量。

### 问题 4：每次启动都新建一个空的「Live Agent Host」对话

18. **来源**：红线 store 的 DEMO 种子（`DEMO_SESSIONS` 里的 `session-live`，标题 `Live Agent Host`，初始 `activeSessionId`），这是 T-01（2026-07-24）为了让开发期的外壳能直接发消息而加的脚手架。每次启动的第一次工作区同步（`useSyncChatWorkspaceTree` 的 `rebindSessionsToTree`）会把它当成没发送过的孤儿草稿，挪到首选工作区，换成新的 `session-live-*` id，时间记为现在。列表为空时，A4 的 `createLiveSession` 也会补一个。未发送的对话不写索引，所以不会越攒越多，但每次启动都有一个。
19. **定性：效果是有意的，载体是遗留的**。它就是应用开屏落脚的地方：一个指向当前选中仓库的空对话，界面上显示欢迎卡。A4 的注释把它称作「首启便利」。U28 之后，没有选中任何对话时发送会建一个临时对话，所以如果直接删掉这个种子，有仓库的用户开屏直接打字时，消息会进临时对话，而不是进当前仓库。
20. **本次做了「复用」**：「新建」的所有入口（顶部「新建」、文件夹的「+」、会话栏的「+」、「新建临时对话」）在当前对话不是空白对话时，先找同一目标下已有的空白对话（无消息、未绑定宿主、空闲、仍是占位标题、没有发送在途），有就打开它，时间记为现在并移到最近列表首位，没有才新建。开屏的那个空对话因此会被复用：用户打开别的对话后再点「新建」，不会在它旁边多出第二个空白对话。用户起过名的、别的工作区的、正在发送中的空白对话都不复用。
21. **没做：去掉「每次启动一个」**。要去掉它，就得改开屏落点，这超出 e1，而且有取舍，**待用户选择**：
    - **甲**：开屏落到当前仓库最近的对话（点验 B4 说的「而不是重载前的对话」就是这个意思），该仓库没有对话时才准备空对话。风险：输入框草稿不分对话（问题 33），开屏就打字的用户会把消息发进旧对话、续上旧上下文；另外需要走带预览的激活路径，否则时间线是空的（与问题 2 同类）。
    - **乙**：开屏什么都不选，显示欢迎卡，首次发送时在当前仓库建对话。需要改 U28 的「无对话发送即建临时对话」和目标条的显示。
    - **丙**：维持现状，即每次开屏是一个新空对话，与多数聊天应用一致；复用规则保证它不会堆积。
    - 实现方建议先按**丙**；如果用户更想「接着上次」，就按**甲**另开任务。另外，标题 `Live Agent Host` 是开发期留下的英文演示名，与「新建」出来的 `New chat` 不一致，属于 e4 的英文残留范围，这次没有改。
