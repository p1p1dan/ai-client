## 1 用户裁决（2026-10-10）

依据：issue #6；预览 v2 看后的三条、v3 看后的一段话、v4 / v4.1 的反馈与 v4 的认可（详见 [README](../evidence/sidebar-regions-2026-10/README.md) 各节），以及 2026-10-10 编排者转达的逐条答复。

1. **首页**：应用启动时（凭据选择屏之后）与没有打开任何对话时显示，模型就是「当前对话为空」（`activeSessionId === null`），不另设开关；正在跑的对话不受影响。取消启动种子（自动建空白「新建对话」）与「自动选一个对话」。
2. **首页内容只有三样**，没有「新建对话」「添加仓库」按钮：
   - 大标题「在 <工作区> 与 PiLab 一起进行创造吧」（英文 `Create with PiLab in <workspace>`）。新字号 token `--text-display`（26px，行高 1.3，字距 `-0.01em`），`@theme` 注册并注册进 tailwind-merge 的字号组。句子 400 `muted-foreground`，工作区名 600 正文色、最长 14em 截断；不加图标、不用品牌色。工作区名取工作栏当前选中的仓库，随切换变化；没有仓库或选「不选仓库（临时对话）」时的文案与样式照原型 v3 / v4。
   - 位置：标题中心在输入框以上区域的 38.2%（黄金分割，用容器查询单位纯 CSS 实现）；最近对话离输入框不到 32px 时整块上移，顶部留白压到 48px 还放不下时上区自己滚动，输入框始终贴底。
   - 「最近对话」：标题下 40px；段头 14px 400 灰色；5 条 +「查看更多（N）」，5 条时不分组，展开后按「今天 / 昨天 / 更早」分组；列全部对话（很多时分批加载或虚拟化，由实现方定）；行 15px 正文色，含状态槽、标题、L4「文件夹 · 分支」、相对时间，悬停三行提示与侧栏一致。
   - 中栏会话栏标题写「首页」。
3. **输入框**：首页与对话页是同一个 `ChatComposer`，几何完全一致（从首页发送进入对话，输入框不跳）；空输入框最少 2 行（17px × 1.5 × 2 = 51px，卡片约 101px），有内容时照旧长到现有上限。
4. **首页工作栏**选仓库与分支，新增「草稿目标」：没有当前对话时选目标只记录、不建对话；发送时才在草稿目标上建对话，工作目录直接取自草稿目标；草稿用输入框现有的「没有会话」槽。默认选最近有活动的仓库（排序后的第一个）。从首页添加仓库后自动选中新仓库。
5. **首页选分支 = 发送时才切**：选了只记下「这次对话用哪个分支」，发送时在建对话之前 checkout，沿用现有两把锁。分支菜单里勾号是这次要用的分支，绿点是仓库当前分支。
   - 同仓库有对话在跑：分支选择器锁住（分支 + 锁图标，悬停提示「<仓库> 有对话正在运行，结束后才能切换分支」），仍可在当前分支发送。
   - 先选了别的分支、发送前才出现锁：不发送、不切分支，在输入框卡片上方出警告提示（照 `ModelMissingNotice` 的 coss `Alert` 形态）「<仓库> 有对话正在运行，现在不能切到 <分支>」，按钮「改在 <当前分支> 上发送」「取消」；取消后消息留在输入框。
   - 发送时 checkout 失败：报错、保留草稿、不建对话。
6. **仓库菜单**：「最近」一组；加「不选仓库（临时对话）」；组名「添加仓库」，底部三个添加按钮改为菜单项（可键盘导航、可搜索）；没有仓库时显示「还没有仓库」+「不选仓库（临时对话）」+ 添加仓库各项（工作栏不再整行不渲染）。临时对话的工作栏画一个「临时对话」标签，让输入框高度一致。菜单里 12px 的中文（coss 组名、「创建新分支...」）提到 14px。
7. **侧栏「＋新建」与文件夹行「＋」**：改为回首页并预选对应仓库，不再立刻建空白对话。
8. **首页入口**：左侧图标导轨最上方（「聊天」之上）加「首页」图标按钮（32×32）；在首页时入口不显示按下态；点它 = 把当前对话置空。

## 2 自主决定（待用户审批）

### 2.1 模型、状态与启动

1. **首页 = `activeSessionId === null`**，红线 store `stores/chatSessions.ts` 的初始值与持久化形状都没改（初始值仍是 DEMO 的 `session-live`）。DEMO 行由树同步那一侧去掉：
   - `useSyncChatWorkspaceTree.ts` 的 `rebindSessionsToTree`：`session-live`、`session-welcome` 两个 DEMO id 一律丢掉（以前 `session-live` 改名成开屏种子）；不再补种子（`createLiveSession`、`allowSeed`、`seeded` 删除）。
   - `resolveTreeSyncPatch`：当前对话还在就保留，不在就是 `null`（首页），**不再兜底取「首选工作区的第一个」或 `sessions[0]`**。
   - 以前存下来的 `session-live-…` 对话（老版本开屏种子发出过消息的）是普通对话，照常保留。
   - 写入改用 `useLayoutEffect`：第一次同步在首帧之前落地，否则每次启动都会闪一帧 DEMO 行的旧开始屏。
2. **临时对话不再被并入仓库**（取消 U22）：`workspaceId` 为空的对话（临时对话，发过没发过都算）原样保留。以前没发出的临时草稿会被并进第一个添加的仓库；现在首页在发送时按用户选的目标建对话，用不着它。顺带修了一个旧问题：一个工作区都没有时，同步曾经把所有对话（包括已经跑过的临时对话）整个丢掉，现在临时对话保留。仓库里的孤儿草稿（工作区没了、从没发过）仍挪到首选工作区，规则不变。
3. **当前对话消失 → 首页**：`ChatWorkspace` 的「当前对话为空或已删就自动选一个」改为「当前对话已不存在就置空」。
4. **从列表移除当前对话（关闭、归档、`/archive`）→ 首页**：`useSessionIndex.ts` 的 `removeSessionRow` 以前把当前对话交给 store 数组里相邻的一行——侧栏不按这个顺序显示，跳到的对话在用户看来是随机的，而且这也是一种「替用户选对话」。现在置空。
5. **草稿目标**：新 store `stores/homeDraft.ts`，只在内存里、本次运行有效：
   - `pick`：`default`（没选过，取默认）/ `unbound`（不选仓库）/ `path`（按**工作区路径**记，不按工作区 id：刚从首页添加的仓库在树同步派生出工作区之前就能被选中，派生出来那一刻就生效）。
   - `branch`：首页上选的分支 `{ workdir, name, create }`，只对选它的那个检出有效；换目标就清掉。
   - `openHome(preselect?)`：把当前对话置空，有预选就写入；没有预选就保留首页上原来的选择。
   - `preselectAddedRepository(path)`：只在首页上（当前对话为空）把新加的仓库设为目标。
6. **解析**（纯函数 `components/chat/homeTarget.ts`）：
   - 默认目标 = 最近有活动的仓库：仓库里最新一个对话最新的那个仓库（worktree 上的对话算它的仓库，临时对话与「临时工作区」不算）；一个对话都没有时取添加顺序的第一个仓库；一个仓库都没有时为空（临时对话）。与侧栏的活动排序第一个一致。
   - 选了的路径解析不到（还没派生出来，或仓库已移除）时退回默认，不退成临时对话。
   - 草稿分支只在工作区路径与 `workdir` 相同时有效；选的就是检出当前分支时视为没选。
   - 标题、工作栏、发送都经 `useHomeTarget` / `readHomeTarget` 读同一个答案，三处不会说出不同的仓库。

### 2.2 首页（`workspace-shell/HomeView.tsx`、`homeViewModel.ts`）

1. 放在 `workspace-shell/`，由 `WorkspaceShell` 以 `home={<HomeView />}` 传给 `ChatWorkspace`：它复用侧栏行的部件（`sidebarRowTooltip` 等），而 `components/chat` 不得引用 `workspace-shell`（`composerTargetGuards` 的边界断言）。`ChatWorkspace` 在当前对话为空时用它代替时间线，`ChatComposer` 照常放在下面——**全程只有一个输入框实例**，从首页发送后它不重挂，焦点不丢。
2. 标题：译文按占位符切开（`Create with PiLab in {{workspace}}` 用一个 NUL 占位求出前后两段），仓库名单独成段加样式，中英文各保留自己的语序；没有仓库时在译文里找 `PiLab` 加粗。没有仓库可选、或选了「不选仓库」时，标题下一行说明（原型 v3 文案）；一个仓库都没有时说明刻意分两行。
3. 「最近对话」= 侧栏列出的全部对话（仓库里的与临时对话，找不到工作区的孤儿不列），最后活动时间降序：
   - 5 条 +「查看更多（N）」；**每按一次多 100 条**，展开后只要多于 5 条就有「收起」（回到 5 条）。对话上千时一次只多画 100 行，没做虚拟化。
   - 5 条时不分组；展开后按本地日历日分「今天 / 昨天 / 更早」。
   - 行的状态槽（转圈、等待点、未读点、后台圈）、告警徽标（`1.0.x`、待审批 N、失败）、三行悬停提示与侧栏相同；「文件夹 · 分支」就是悬停提示的第二行（抽成 `sidebarRowWhere`，提示与行共用）。行是 `<button>`，点了就是 `useActivateSession` 打开它。
   - 状态槽与徽标的 JSX 在 `HomeView` 里另写了一份，没有从侧栏 `SessionRow` 抽出来：侧栏的多条静态断言按源码钉着 `SessionRow` 里这几段（`unreadRowMarkerStatic` 等），抽走就要改写它们。两份用的是同一组类名与词条。
   - 每分钟刷新一次相对时间，与侧栏相同。
4. 位置与滚动纯 CSS：上区 `@container-[size]`；顶部留白 `h-[calc(38.2cqh_-_var(--text-display)*0.65)] min-h-12`；标题与列表 `shrink-0`；底部 `min-h-8 grow`；上区自己是 `ScrollArea scrollFade="bottom"`。

### 2.3 输入框与几何（`middleColumnLayout.ts`）

1. `deriveMiddleColumnMode`：没有对话时给 `session`（以前是 `empty`），首页与对话页同一套几何——卡片在上、工作栏在下（`mt-2 h-6`）、外层 `pb-3.5`。
2. 空输入框最少 2 行：新常量 `COMPOSER_TEXTAREA_MIN_ROWS = 2`，会话模式的输入区 `[&_textarea]:min-h-[calc(var(--text-chat-body)*1.5*2)]`；高度账 `composerFollowHeightBreakdown` 加 `textareaLines`，17px 默认下卡片 2 + 16 + 51 + 8 + 24 = **101px**。`min-h-18.5`（74px）仍是下限，不再起作用。8 行上限不变。
3. 首页的占位是「输入消息…」（有对话才是「继续输入…」）。
4. **会话模式的工作栏一律渲染**（`shouldRenderTargetRow` 删去了 `showBranchSelect` / `hasRunLocation` 两个入参）：第一列总有东西——首页的仓库下拉、对话的锁定仓库标签，或临时对话的「临时对话」标签（新组件 `TemporaryChatLabel`）。以前没有分支下拉也没有运行位置的对话整行不渲染，卡片低 32px。
5. **`empty` 几何（空白对话的开始屏）保留**：现在没有任何「新建」入口会建出空白对话（§2.7），正常操作到不了；代码与测试留着，见 §2.9。

### 2.4 首页发送（`ChatComposer.tsx` 的 `sendFromHome`）

1. 发送时读最新的草稿目标与草稿分支（`readHomeTarget`），先处理分支（§2.5），再**用 `runSend` 自己的守卫预先检查一遍**（能不能发、有没有在途的发送、是否在停止中），通过了才建对话：被跳过的发送不会留下一个选中的空对话（那会把输入框里的字从首页的草稿槽带走）。
2. 建对话：有目标仓库就 `createChatSessionOnWorkspace(工作区)`，否则 `createUnboundChatSession()`；然后**同一个同步段**里调 `runSend(..., { home: { sessionId, workspacePath } })`。`runSend` 用传进来的会话 id 与目录，不再用渲染时的 `activeSessionId` / `cwd`——那是上一帧「没有对话」时的空值，以前对话会因此落到临时目录（README 现状核实第 4 条说的坑）。临时对话的目录照旧在握手里分配。
3. 输入框在 `runSend` 的提交点同步清空，React 渲染新对话时，首页的草稿槽里什么也没留下；第一条消息照旧给对话起名。
4. 另一个对话的发送占着输入框唯一的发送槽时（`decideSendAction` 给 `enqueue`）：同样在目标上建对话，把消息放进它的队列，等槽空出来再发——与在新对话里按 Enter 排队相同。建之前先在空队列上预检，过不了（附件超额）就提示、不建。
5. 发送失败（建会话被拒、超时、发送被拒）与 Stop：对话行已经建好，留在那个对话里，文字按原规则放回它的输入框——与 dsh.8 开始屏首次发送失败相同（README 风险第 2 条；没有做「自动删掉空对话回到首页」）。没发出去的对话不写索引，重启后消失；`createSession` 已经成功的会留在列表里。
6. `@` 文件搜索在首页上搜草稿目标的仓库目录。

### 2.5 首页选的分支（发送时才切）

1. 分支列在首页上是**草稿模式**（`BranchColumn` 的 `draft`）：选一个分支只写 `homeDraft.branch`，不调 `checkout`；选回检出当前的分支就清掉草稿。触发器与勾号显示草稿分支，绿点是 git 的当前分支（`branch.current`，颜色换成 `bg-success` token）。
2. 「创建新分支...」在首页上记成 `create: true` 的草稿，**发送时才创建**（`createBranch` 本身会 checkout）。分支名不合法等错误在发送时报。
3. 发送时：`planHomeBranchSwitch` 用分支列同一个锁（`buildBranchColumn(...).lock`，首页上只会是 `checkout-busy`）判断：
   - 没有草稿：不切，直接发（锁着也能在当前分支发）。
   - 有草稿且锁着：不发、不切，卡片上方出提示条（新组件 `HomeSendBlockedNotice`：coss `Alert` warning、锁图标、`mb-2`，按钮 `Button size="xs"` + `h-6 sm:text-meta`）。「改在 <当前分支> 上发送」清掉草稿分支后照常发送；「取消」只关提示。提示条在离开首页、换仓库或换分支时自动消失。
   - 有草稿、没锁：`runHomeBranchSwitch`（新模块 `homeBranchSwitch.ts`）调 `git.checkout` / `git.createBranch`，成功后清掉草稿分支，刷新分支相关的查询（不等刷新完成，发送不被它拖慢）。
   - 切换失败：错误提示「无法切换到 <分支>，消息没有发送」+ git 的原话；不建对话、文字留在输入框、草稿分支保留，可以再试。
   - git 运行期间用户离开了首页、或改了输入框里的字 / 附件：这次发送到此为止，下一次 Enter 发送框里的内容（分支已经切好）。期间重复按 Enter 不会再发一次（同步闩 `homeSendPendingRef`），工作栏锁住、分支触发器转圈。
4. 锁在首页上的说法换成以仓库为主语：「<仓库> 有对话正在运行，结束后才能切换分支」；对话页的两句不变。悬停提示 14px（coss 的 Tooltip 是 12px）。
5. `components/chat` 里会 checkout 的地方从一处（`BranchColumn`）变成两处，`composerTargetGuards` 的守卫随之改为「`BranchColumn.tsx` 与 `homeBranchSwitch.ts`」，并加一条：首页的切换只接受 `planHomeBranchSwitch` 产出的 `switch` 计划，且在它之后调用。

## 3 与原型的偏差

1. **「添加仓库」组在列表里、随列表滚动**，不是原型那块固定在底部的区：Base UI 的 combobox 只给自己集合里的项做键盘导航和搜索过滤，项必须在列表里（用户裁决要求可键盘导航、可搜索）。仓库很多时要滚到列表底部才看到这一组。
2. **「查看更多」分批**：原型的数据只有 60 条，一按全出；实现每按一次多 100 条，展开后一直有「收起」（原型只在全部展开后有）。
3. **首页的 Git / 文件 / 终端面板跟随草稿仓库**（§2.8）：原型没有画面板。
4. **没有仓库、或临时对话时，工作栏不显示「本机」**：运行位置只在有仓库路径时可知（`runLocationLabel` 的既有规则）。原型这两种情况也画了「本机」。行高不受影响。
5. 首页的行是 `<button>`（原型是 `div role="button"`），点、回车、空格都能打开。
6. 导轨分隔线写成 `my-1 h-0 w-6 shrink-0 border-t`（与原型的 `.rail-sep` 等值）；首页按钮用导轨现成的 `RailIconButton`（悬停提示在右侧，与设置、能力按钮相同）。
7. 文案按原型；英文版是新拟的：`Create with PiLab in {{workspace}}`、`Create with PiLab` 与几句说明。
8. **没有出实机截图，也没有重跑原型的硬判据**：开发机不跑 Electron GUI；像素级核对放到第 7 节的现场清单。

## 6 风险

1. **启动后先看到首页**：凭据选择屏之后是首页，不再直接是上次仓库里的空白对话；打字直接发送，落在默认仓库（最近有活动的）。与以前「上次选中的仓库」（`aiclient-selected-repo`）可能不同。
2. **移除当前对话后回首页**（§2.1 第 4 条）：以前会跳到相邻的对话。
3. **`/new` 在临时对话里**不再沿用同一个临时目录（§2.7）。
4. **首次发送失败留下的对话**：与 dsh.8 相同，对话行留着、文字放回；没有做「删掉空对话回首页」。
5. **分支锁挡不住的情况仍在**（README 现状核实第 3 条）：别的对话正在发送握手、主进程、Git 面板的分支切换都不看这两把锁；首页的草稿分支在发送那一刻按当时的状态判断。
6. **侧面板跟随草稿仓库**（§2.8）：在首页上换仓库，文件树、Git 面板、编辑器标签都会换；编辑器标签按仓库停放与取回，与切换对话时一样。
7. **「添加仓库」组要滚到列表底部**（§3 第 1 条）：仓库很多时不如原型醒目。
8. **`/compact`、`/archive` 在首页上**会作为普通消息发出（§2.8 末行）。
9. **对话很多时**「最近对话」每次多画 100 行，没做虚拟化；上千条全部展开时要多按几次，画面上的行数也随之增多。
10. **字号**：首页标题 26px 是界面里最大的字；`BranchSwitcher` 的 14px 改动同时作用于 Git 面板的分支切换器。

## 7 Windows 现场清单（下一个测试包起）

1. **启动**：凭据选择屏之后是首页——标题「在 <仓库> 与 PiLab 一起进行创造吧」（仓库是最近有对话活动的那个），会话栏写「首页」，侧栏没有空白「新建对话」行，也没有选中任何对话；首帧不闪「开始对话」卡片。
2. **标题**（Segoe UI Variable + Microsoft YaHei UI）：句子 26px 常规、灰色，仓库名加粗、正文色，很长时截断、悬停显示全名；标题大致在输入框以上区域的上 38% 处。1280×720 或 150% 缩放时整块上移、上区可以滚动，输入框一直贴底。
3. **最近对话**：标题下约 40px；5 行 +「查看更多（N）」；展开后按今天 / 昨天 / 更早分组，末尾「收起」；行 15px，右侧是「文件夹 · 分支」和相对时间，悬停三行提示；点一行打开该对话。
4. **输入框**：首页与对话里都是 2 行高（约 101px 的卡片），打字后长高到 8 行；从首页发出第一条后，卡片和下面的工作栏一像素不动，焦点还在输入框里。
5. **工作栏**：首页上换仓库，标题跟着变；选「不选仓库（临时对话）」，标题变成「与 PiLab 一起进行创造吧」加一行说明，发送后是临时对话；临时对话的工作栏写「临时对话」，卡片高度与别的对话一样。
6. **仓库菜单**：「最近」「本机」（「远程仓库」）、「不选仓库（临时对话）」、组「添加仓库」下的几项，方向键能走到，输入「克隆」能搜到；组名 14px。没有仓库时：「未选仓库」、菜单里「还没有仓库」和添加仓库各项。
7. **从首页添加仓库**：加完后工作栏和标题都是新仓库。
8. **首页选分支**：选一个别的分支，仓库的分支**没有立刻变**（Git 面板里看）；发送后才切过去，新对话在新分支上。选「创建新分支...」输入名字，发送时才创建。
9. **锁**：让同一仓库的一个对话跑着长命令，回首页：分支选择器带锁，悬停「<仓库> 有对话正在运行，结束后才能切换分支」，仍能在当前分支发送。先选好别的分支、再让那个对话跑起来后发送：不发送，卡片上方出黄色提示条，「改在 <当前分支> 上发送」能发出、「取消」后字还在。
10. **checkout 失败**：工作区有会冲突的改动时，首页选别的分支发送：报错、字还在、没有新对话。
11. **入口**：导轨最上方的「首页」按钮（在「聊天」之上，下面一条短线），在首页时不显示按下态；侧栏「＋新建」、文件夹的「＋」、空文件夹的「新建对话」、会话栏「＋」、`/new` 都回首页并选好对应仓库，侧栏里不出现空白对话；「临时对话」区右键「新建临时对话」回首页并选好「不选仓库」。
12. **移除**：归档或从列表移除当前对话后回到首页。
13. **面板**：在首页上打开文件、Git、终端面板，显示的是首页选中的仓库；换仓库时跟着换。
14. **暗色、同步终端主题**下首页标题、行、提示条都清楚可读。
