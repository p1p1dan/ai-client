# 决策 187：issue #15 第二期 —— 「按分组」的自定义分组与归类（右键「移到分组 ▸」，不做拖动）

日期：2026-10-13。**状态：第 1 节为用户裁决（2026-10-13 对话中问答，含两轮原型预览）；第 2 节为自主决定，待用户审批。**

来源：GitHub issue #15（`p1p1dan/ai-client`）的「自定义 Group」部分，第一期见[决策 186](186-github-issues-10-16-first-batch.md) 第 20～27 条。决策 186 第 3 节把第二期的难点与备选做法写了下来，本决策是它的落实。

原型：[`evidence/sidebar-groups-2026-10/prototype.html`](../evidence/sidebar-groups-2026-10/prototype.html)（v1，2026-10-13；用户在浏览器里看过两轮后定稿）。

## 1. 用户裁决（2026-10-13）

1. **第二期用右键「移到分组 ▸」，不做拖动。** 用户在看到决策 186 第 3 节与本次原型后选「按推荐方案」。拖动与组内手动排序一并推后。
2. **新建分组用行内输入**：菜单里选「新建分组…」后，列表顶部出现一个可编辑的标题，敲名字回车即建，Esc 取消。不用弹对话框。
3. **删除分组时，组里的对话回到「未分组」**，不跟着删除。
4. **「未分组」固定在列表最下面**（在所有用户分组之后）。
5. **用户分组的标题保留「＋」**（与仓库分组一致），点击是「回首页、不预选仓库」。
6. **一个对话只能在一个分组里**，移动即转移，不是多归属标签。
7. **组的标记用竖线**（2px 圆角细线），**「未分组」也用同一条竖线**——不再用收件托盘图标。理由：分组不是磁盘上的目录（那是仓库分组），文件夹图标会让两类标题说同一句假话；竖线是最小的「这里开始一节」的标记，且不自带颜色，层级由标签的灰字承担。
8. **归档方式切换按钮的图标用「标签」（`Tag`）**，取代原来的 `Layers`（方块/层叠）。「按工作目录」一侧仍是文件夹树（`FolderTree`）。
9. **列表空白处右键可以新建分组**（「按分组」模式下菜单是「新建分组…」+「新建对话」；「按工作目录」下是「新建对话」+「添加仓库」）。

## 2. 自主决定（待用户审批）

### 数据与存储（`src/renderer/stores/sidebarArchive.ts`）

1. **分组与归属都放进 `sidebarArchive` store**。决策 186 里写的第一期注释就说了「this store is where that name will live so the persisted shape does not have to change again」——本决策兑现它，而不是另开一个 store。
2. **`SidebarGroup = { id, name, createdAt }`**，`createdAt` 用来排序（新的在上），与仓库的 `addedAt` 同向。组的生成 id 形如 `group-<base36 时间戳>-<随机>`，与 `project-*` 不会撞。
3. **归属用 `Record<会话 id, 分组 id>`，缺席即「未分组」**。这是本次最关键的一个取舍：把「未分组」表达成**没有条目**，而不是存一个 `UNGROUPED_GROUP_ID`。于是（a）用户从未归类的对话不需要任何存储，（b）删除分组时**删掉那个键就是退回未分组**，不需要遍历改写值，（c）「用户从没归类过」与「用户把它移出分组」是同一个状态，不会有两种写法互相漂移。`assignSession(id, null)` 与 `assignSession(id, UNGROUPED_GROUP_ID)` 都落到删除键这一条路。
4. **持久化版本升到 2**（v1 只存 `archiveMode`）。v1 的载荷清洗后就是「没有分组、全部在未分组」——用户升级后看到的是他原本的那张列表。
5. **清洗时丢掉分不清、不能用的东西**：没有 id 或名字为空的组不保留（组会变得无法寻址或无法阅读）；指向一个没有存活下来的组的归属条目直接丢弃。理由写在代码注释里：否则每个读这个映射的地方都要自己再问一遍「那个组还在吗」。
6. **`renameGroup` 拒绝空名字**（trim 后为空则整个操作不生效）。一个没有名字的组无法阅读；让它改名后消失比拒绝更糟。

### 派生与渲染（`sidebarTree.ts` / `LeftNav.tsx`）

7. **`buildUnassignedFolder` 与 `UNASSIGNED_FOLDER_ID` 删除，换成 `buildGroupFolder`**。第一期的「未分组」组和新加的用户分组现在是**同一个函数、同一种形状**（同一个标题、折叠、8 条上限、「查看更多」、搜索行为）。这是决策 186 第 23 条就写明的目标：第二期替换成用户分组时不必换一种东西。
8. **`buildGroupFolder` 在空组时返回一个空 `SidebarFolder`，不再返回 `null`**。空组是组：它的「暂无对话」、重命名和删除都在标题行上，而一个「最后一个对话离开就消失」的组会被读成「已经被删了」。
9. **`SidebarFolder.synthetic` 的取值由 `'unassigned'` 改为 `'group'`**，用户分组与「未分组」共用同一个值——两者渲染路径已经完全相同。
10. **`buildGroupFolder` 只管形状，不管归属**：调用方（`LeftNav`）用 store 里的映射筛好会话再传进来，派生层保持纯函数、可测，不依赖 store。这也让它在 vitest 的 node 环境里能直接测。
11. **「未分组」在 `LeftNav` 里是 `groupFolders` 的最后一个元素**，用户分组按 `createdAt` 降序排在前面。组顺序只在建组/删组时变化，不随活动时间重排。
12. **搜索时空分组隐藏**（`visibleGroupFolders`），与仓库树的 `visibleFolders` 同一规则：搜索已经把列表缩小了，再摆一排空标题会像是「没有匹配」。无查询时每个组都留着，否则标题行的「＋」和菜单就够不着了。
13. **`toggleGroupIds` 在分组模式下改为 `groupFolderIds`**（用户分组 + 未分组），不再只看单一桶。

### 交互

14. **「＋」在用户分组上是「回首页、不预选仓库」**。分组没有仓库，所以「在此分组新建对话」没有可预选的目标；与「临时对话」分组的「＋」是同一个动作，也是唯一诚实的动作。
15. **行内重命名与行内新建共用同一个输入框外观与键盘行为**（回车提交、Esc 取消、失焦取消），两者都用 `text-group-label`，所以标签变成输入框时字号不跳。
16. **`autoFocus` 保留**（两处，带 `biome-ignore lint/a11y/noAutofocus` 的同一行理由）：打开这个输入框的菜单项问的就是「叫什么名字」，再要求一次点击才能打字是多余的一步。`biome-ignore` 的说明必须写在**同一行**，跨行会失效——这一点是本轮踩过的坑。
17. **删除分组有确认对话框**，并写明「里面的对话会保留，回到「未分组」」。「删除分组」四个字看不出对话去哪了，而对话框是唯一能在此之前讲清楚的地方。
18. **右键菜单的树也是两组入口共用一份定义**（`groupMenuItems`），仓库分组当年就是这么做的（S2/H-18）：标题行的「···」与右键必须是同一份菜单，两份拷贝会在任一侧加菜单项时立刻分叉。
19. **「移到分组 ▸」子菜单里当前所在的组带勾**，所以这个子菜单同时回答「这条对话现在归在哪」。子菜单末尾有「新建分组…」，它建完组会把这个对话直接移进去（`pendingMoveSessionId`）——用一个 ref 而不是 state，因为没有任何东西从它渲染。
20. **列表空白处的右键菜单在分组模式下多一项「新建分组…」**，不改变已有「添加仓库」的位置；「新建对话」是新加的，与顶部导航的第一项同一个动作。
21. **「未分组」的标题行右键只有「新建分组…」一项**，没有重命名和删除。它是所有对话的兜底去处，删掉它那些对话就无处可去；一个能改名的兜底，其身份会变成每次安装的偶然。

## 4. 已知取舍与不做的事

1. **一次归类是三次点击**（右键 → 移到分组 → 选组），拖动是一次。这是选右键路线的真实代价；换来的是不用拖拽层、不用跨 `ScrollArea` 自动滚动、不用判定落点，最要紧的是不必把「拖动」与「单击打开对话」区分开（做错就是误拖被读成误点）。
2. **组内手动排序不做**，它与拖动共用同一套机制。组内现在按最近运行时间降序。
3. **拖动归类不做**，理由同上。数据形状已经就位：真要补拖动，是叠加一个入口，不是重做分组。
4. **批量移到分组不做**。现有「批量归档」只管归档；要不要加「批量移到分组」，等用户先用一轮右键路径再定。
5. **组的颜色、图标、嵌套不做。**
6. **一个对话只在一个组**（用户裁决 6）。多归属（像标签）会让「归档方式」变成筛选器，改动面大得多，本次明确不做。
