## 2 参照

本机能核对的两个现成实现（2026-10-18 查）：

| 要点 | Claude Code 2.1.302 自动模式 | Codex 0.162 自动审核（Guardian） |
|---|---|---|
| 审什么 | 只审本来要问的调用；只读工具、工作区内编辑直接放行 | 只审本来要问的请求 |
| 模型 | 默认 Sonnet（中档，不是最便宜的），可覆盖 | 专用审核模型低思考档，没有时用主模型低档 |
| 送给审核的 | 用户的话 + 之前的工具调用 + 这次调用；**不送助手的话**（"好的"不能让模型自问自答地放行） | 对话摘要（含助手的话）+ 最近的工具调用与结果 + 这次调用 |
| 输出 | `<block>yes/no</block><reason>一句话</reason>` | JSON：风险等级、用户授权程度、allow/deny、理由 |
| 超时 | 每次 60 秒起，长对话最多 120 秒 | 90 秒，最多 3 次 |
| 审核失败 | 拒绝，并告诉模型"不是判定不安全，稍后照原样重试" | 拒绝，同样说明 |
| 连续被拒 | 连续 3 次或累计 20 次后改为问用户 | 每回合连续 3 次或 50 条内 10 次后中断回合 |
| 授权范围 | 只管这一次 | 只管这一次 |

Claude Code 的规则（`claude auto-mode defaults` 打出来的，17 条放行例外、72 条默认拦、1 条永远拦）里与删除和 git 有关的：

- 放行：删工作区里的文件、删本会话自己建的东西、推送到本仓库任何分支。
- 默认拦，用户原话点名了操作和目标才放行：
  - 不可逆地删除或覆盖本会话之前就有的文件（`rm -rf`、`git reset --hard`、`git clean -fd`、`git checkout -- .`、`git stash drop`、截断文件）；通配符不算点名；
  - 删除目标是对话里看不到取值的变量；
  - 强推、删远端分支或 tag、改写别人的提交历史（`main`、`master`、`release-*` 这类共享分支默认有别人的提交）；`amend`、`rebase`、强推只含自己提交的个人分支不算。
- 永远拦：把敏感数据送出信任边界。
- 用户的意思：要明确点名操作和目标；"继续""可以"什么也没点名；授权只管那一次。

另外两个参照没有可用的东西：DSH 的实验包 `dsh-experimental-auto-review` 只在启动包里列了名字，没装、没有说明；PI-Desktop 的全自动是静态规则表，没有模型审核。

## 3 方案

### 3.1 何时审核

- 只在 DSH 会话的**全自动档**，且模型清单里有审核模型时。其余档位、完全放行、没配置审核模型时都与现在一样。
- 审的就是全自动档现在会弹卡的那几类（`gate.ts` 的 `evaluate` 返回 `ask` 时）：
  - 危险命令（`dangerousCommands.ts`：任何删除、强推、hard reset 等）；
  - 写明了工作区外路径的 shell 命令，以及碰工作区外的文件工具；
  - 看不进去的程序工具：`run_code`、`workflow`、`plugin_manager`；
  - DSH 自己的询问（`hostAsk`，只有原因文字，没有参数）。
- 所有 deny 规则照旧先生效，审核放不过 deny。
- 接入点：`PermissionGate.check()` 在 `evaluate` 返回 `ask` 之后、`acquirePrompt` 排队之前（`gate.ts` 约 910 行）。审核不占弹卡队列，120 秒的弹卡计时也不开始。

### 3.2 送给审核模型的内容

照 Claude Code 2.1.302（2026-10-18 核对 CLI 代码与 `claude auto-mode defaults`）：

- **规则**（用户裁决：运行时从随包的 claude.exe 读，每个 CLI 版本读一次）：
  - 读法：运行随包 CLI 的 `auto-mode defaults`，它在标准输出打出一段 JSON（`allow`、`soft_deny`、`hard_deny`、`environment` 四组，2.1.302 约 83 KB、2 万 token），然后退出。规则原文不进仓库，也不在打包时写进安装包。
  - 本机实测（2.1.302，2026-10-18）：不用登录、不用网络，断网时输出逐字节相同；联网时会顺带连 Anthropic 约 0.6 秒，带上 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` 就不连，约 0.13 秒；会在配置目录写 `.claude.json`，所以 `CLAUDE_CONFIG_DIR` 指到 PiLab 自己的目录，不碰用户的 `~/.claude`。
  - 缓存：按 CLI 所在平台包（`claude-agent-sdk-<平台>-<架构>`）的版本号存一份到本机，版本没变直接用存的，只在升级后的第一次读。
  - 由 DSH 宿主自己读和存（随包 node 拉起 claude.exe，与 SDK 宿主拉起它是同一种进程宿主，加密机上已验证过 SDK 宿主这条路）；CLI 路径由 Main 经 `configure` 交给宿主（Main 已有 `claudeSdkCliPath`）。缓存文件只由宿主读写，不让 Electron 主进程读，免得加密机上读到密文。宿主拉起 claude.exe 这一步要在加密机上复核。
  - 读不到（CLI 缺失、运行失败、输出不是这四组）就当作没配置审核，回到弹卡，并记日志。
  - 我们自己写的只有外层提示词：说明这四组规则的用法（"默认拦"的条目标着要点名什么才能放行，"永远拦"的用户也放不过，默认放行），以及第 2 节的两段式与输出格式。
  - 代价：每次审核多带约 2 万 token 的规则（快审、细审各一次）。走 Anthropic 协议的模型可以用提示缓存（Claude Code 也给规则加了 `cache_control`）；其他协议看网关与模型自己的缓存。
- **对话**：用户自己的话和之前的工具调用（工具名与参数，不含结果），**不放助手的话**；最后一条是待审的这次调用：工具名、命令或参数、程序原文、工作目录、为什么要问（`askReason`）。
  - 子代理的调用：带上主会话里用户的话；子代理的任务说明标明是模型写的，**不算用户授权**（自主：没在 CLI 代码里查到 Claude Code 的确切做法）。
  - **不截断**。对话超出审核模型的上下文时，这次不放行，告诉模型"没审，不是判定不安全"（Claude Code 新版还会先压缩对话再让模型重试；DSH 宿主能不能代为触发压缩，动工时再查，查不到就只拒）。
- **输出**：`<block>no</block>` 或 `<block>yes</block><reason>一句话理由</reason>`。两个都出现、或都没有，算审核失败。
- **两段**：
  - 快审：最多 64 个 token，要求偏向拦；判为放行就直接放行。（Claude Code 还用了遇到 `</block>` 就停的停止符；DSH 的 pi-ai 模型适配器不接受停止符，实测报 `llm-pi-ai does not support GenerateOptions.stop`，所以只靠 64 个 token 的上限。）
  - 细审：只在快审判为拦时做，先想清楚再给结论，此时才考虑用户的原话授权。

### 3.3 结果

| 审核结果 | 执行 | 告诉模型的 | 用户看到的（第 3.7 节） |
|---|---|---|---|
| 放行 | 照常执行 | 无 | 行尾「· 自动：审核放行」 |
| 不放行 | 不执行 | "自动审核没有放行这次调用：<理由>。不要换个写法再试；不依赖它的事继续做，需要时请用户明确授权" | 红行「· 已拒绝 · 自动：审核没放行」，点开看理由 |
| 失败（超时、网关报错、输出看不懂、对话太长） | 不执行 | "自动审核没能完成，这不是判定不安全；可以稍后照原样重试，不要换个写法绕开" | 灰行「· 未执行 · 自动：审核没能完成（原因）」 |

- 超时照 Claude Code：60 秒起，提示超过 5 万 token 后每多 5 万加 10 秒，最多 120 秒；网关回了要等多久（Retry-After）就照办。
- 审核期间显示「审核中」（第 3.7 节），不然看着像卡住。
- Stop 会立刻中止审核。

### 3.4 连续被拒的上限

照 Claude Code：**每个会话连续 3 次或累计 20 次**没放行后，下一次没放行的调用改为弹卡问用户，卡上带审核的理由。

- 连续计数在审核放行或用户答了卡后清零；累计到 20 次弹过卡后，两个计数都清零。
- **审核失败不计数**（审核不可用、对话太长、被网关安全策略拒）：与 Claude Code 一样，审核模型挂了时每次都拒，模型照原样重试。

### 3.6 与 Claude Code 对不齐的地方

- 审核模型：Claude Code 默认 Sonnet（中档，不是最便宜的）；我们按用户裁决由管理员选，建议也选中档模型。
- 网关上的审核：Claude Code 先请网关在主请求里顺带审（网关支持时），我们没有这条路，只单独发请求。
- 自定义规则：Claude Code 允许用户在设置里加放行、拦截规则和环境说明（信任哪些域名、仓库等），本次不做。
- 规则外层的提示词：Claude Code 的外层提示词（审核员的身份、两段的说明、输出格式）不在 `auto-mode defaults` 的输出里，由我们照第 2 节观察到的行为自己写。
- 子代理：见第 3.2 节。

### 3.5 告诉模型的权限说明

`promptText.ts` 的全自动那句话按有没有审核模型分两种：

- 没有：保持现在的（决策 191 第 6.3 节，"危险命令和工作区外路径仍然每次询问"）。
- 有：改成"本来要问的调用（危险命令、工作区外路径、程序工具）先经自动安全审核；没放行的会返回理由，不要换个写法重试"。

录制样本按没有审核模型录，现有 3 个样本不变；另加一个有审核模型的场景（第 6 节）。权限菜单里「全自动」的说明（`ComposerPermissionTrigger.tsx`、`i18n.ts`）同样分两种。

## 4 契约：模型清单里的审核模型字段

登录服务的 `GET /api/v1/models-config` 多一个顶层字段，**只在管理员指定了、且该模型在清单里启用时才出现**：

```json
{ "version": 1, "updatedAt": "…", "providers": { … }, "autoReview": { "model": "<providerId>/<modelId>" } }
```

- `model` 用客户端现成的模型写法（`parsePiModelRef` 能解析、`piModelOption` 生成的 `provider/modelId`），必须指向同一份清单里的模型。
- 客户端：`configValidation.ts` 保留这个字段；格式不对、或指向的模型不在清单里，就丢掉并记日志（等于不审核）。老客户端会丢掉不认识的顶层字段，不受影响；老服务端不发这个字段，等于不审核。
- 内置快照（`resources/model-catalog/snapshot.json`）照原样带上。
- 模型计划（`src/shared/dshModelPlan/types.ts`）加 `reviewModel?: string`，计入 `revision`。管理员改了审核模型，宿主照现有规则在空闲时重启生效。指向的模型解析不出 completion 路由时，丢掉并记入 `dropped`。
- 审核用的思考档：模型支持 `low` 就用 `low`，否则不带（照 Codex）。

### 8.2 PiLab（本地分支 `claude/claude-sdk-engine-mvp-162021`）

## 补记（2026-10-18，用户提出）

- **快审在思考模型上 64 个 token 不够**：用户在管理页把审核模型设为 Sonnet 5.5。云端目录给它的是自适应思考（`compat.forceAdaptiveThinking`、有 low 档），审核时带 low 档，发出去是「自适应思考 + effort low + max_tokens 64」。模型一思考，64 就先被思考用掉，快审写不出判定，每次都转细审，多一次带约 2 万 token 规则的请求。不会判错，但快审形同虚设。
- **照 Claude Code 改**：随包 CLI 2.1.300 的快审对能关思考的模型关掉思考、上限 64；对关不掉思考的（Sonnet / Opus / Haiku 5.5）不带思考参数、上限加 2048。PiLab 改为：审核模型有思考档（会思考）时，快审上限 64 + 2048 = 2112；不思考的仍是 64。细审 8192 不变。上限只是封顶，判定仍只有十来个 token，按实际输出计费。
- 代码：`shared/permissions/autoReview/prompt.ts` 的 `REVIEW_STAGE1_THINKING_EXTRA_TOKENS`，`autoReviewer.ts` 的 `thinks`，`dshSessionRuntime.ts` 按计划里该模型有没有思考档设它。单测 `autoReview.test.ts` 加两条。真实网关上用 Sonnet 5.5 实测待测试包。
