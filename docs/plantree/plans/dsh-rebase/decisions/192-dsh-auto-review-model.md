# 决策 192：DSH 全自动档剩下的询问先交给审核模型，审核模型由管理员在登录服务的管理页指定

## 2 参照

本机能核对的两个现成实现（2026-10-18 查）：

| 要点 | Claude Code 2.1.302 自动模式 | Codex 0.162 自动审核（Guardian） |
|---|---|---|
| 审什么 | 只审本来要问的调用；只读工具、工作区内编辑直接放行 | 只审本来要问的请求 |
| 模型 | 默认 Sonnet（中档，不是最便宜的），可覆盖 | 专用审核模型低思考档，没有时用主模型低档 |
| 送给审核的 | 用户的话 + 之前的工具调用 + 这次调用；**不送助手的话**（"好的"不能让模型自问自答地放行） | 对话摘要（含助手的话）+ 最近的工具调用与结果 + 这次调用 |
| 输出 | `<block>yes/no</block><reason>一句话</reason>` | JSON：风险等级、用户授权程度、allow/deny、理由 |
| 超时 | 每次 60 秒起，长对话最多 120 秒 | 90 秒，最多 3 次 |
| 审核失败 | 拒绝，并告诉模型"不是判定不安全，稍后照原样重试" | 拒绝，同样说明 |
| 连续被拒 | 连续 3 次或累计 20 次后改为问用户 | 每回合连续 3 次或 50 条内 10 次后中断回合 |
| 授权范围 | 只管这一次 | 只管这一次 |

Claude Code 的规则（`claude auto-mode defaults` 打出来的，17 条放行例外、72 条默认拦、1 条永远拦）里与删除和 git 有关的：

- 放行：删工作区里的文件、删本会话自己建的东西、推送到本仓库任何分支。
- 默认拦，用户原话点名了操作和目标才放行：
  - 不可逆地删除或覆盖本会话之前就有的文件（`rm -rf`、`git reset --hard`、`git clean -fd`、`git checkout -- .`、`git stash drop`、截断文件）；通配符不算点名；
  - 删除目标是对话里看不到取值的变量；
  - 强推、删远端分支或 tag、改写别人的提交历史（`main`、`master`、`release-*` 这类共享分支默认有别人的提交）；`amend`、`rebase`、强推只含自己提交的个人分支不算。
- 永远拦：把敏感数据送出信任边界。
- 用户的意思：要明确点名操作和目标；"继续""可以"什么也没点名；授权只管那一次。

另外两个参照没有可用的东西：DSH 的实验包 `dsh-experimental-auto-review` 只在启动包里列了名字，没装、没有说明；PI-Desktop 的全自动是静态规则表，没有模型审核。

## 3 方案

### 3.1 何时审核

- 只在 DSH 会话的**全自动档**，且模型清单里有审核模型时。其余档位、完全放行、没配置审核模型时都与现在一样。
- 审的就是全自动档现在会弹卡的那几类（`gate.ts` 的 `evaluate` 返回 `ask` 时）：
  - 危险命令（`dangerousCommands.ts`：任何删除、强推、hard reset 等）；
  - 写明了工作区外路径的 shell 命令，以及碰工作区外的文件工具；
  - 看不进去的程序工具：`run_code`、`workflow`、`plugin_manager`；
  - DSH 自己的询问（`hostAsk`，只有原因文字，没有参数）。
- 所有 deny 规则照旧先生效，审核放不过 deny。
- 接入点：`PermissionGate.check()` 在 `evaluate` 返回 `ask` 之后、`acquirePrompt` 排队之前（`gate.ts` 约 910 行）。审核不占弹卡队列，120 秒的弹卡计时也不开始。

### 3.2 送给审核模型的内容（自主）

照 Claude Code：

- **系统提示**：我们自己写的一份精简规则（不照抄 Claude Code 的原文，仓库是公开的），分三档：
  - 默认放行：工作区内的普通操作、删本会话自己建的文件、工作区外的普通读（系统头文件、文档）。
  - 默认拦，用户原话点名操作和目标才放行：删除或覆盖已有文件与丢弃改动的 git 命令、看不到取值的删除目标、强推与删远端分支、读凭据所在的位置（`~/.ssh`、`~/.aws`、`~/.pilab`、浏览器配置等）、写开机启动与 shell 配置这类常驻位置、运行从网上下载的代码、装插件、降低安全设置、改 PiLab 自己的权限配置。
  - 永远拦：把凭据或敏感数据发到外面。
- **对话**：只放用户自己的话和之前的工具调用（工具名与参数，不含结果），**不放助手的话**；最后一条是待审的这次调用：工具名、命令或参数、程序原文、工作目录、为什么要问（`askReason`）。
  - 子代理的调用：带上主会话里用户的话，子代理的任务说明标明是模型写的，**不算用户授权**。
  - 超出预算时从最早的开始截掉，并在开头注明"前面有截断，看不到的不能当作授权"（Codex 的说法）。预算先定 32k 字符（自主，没有参照的数）。
- **输出**：照 Claude Code，`<block>no</block>` 或 `<block>yes</block><reason>一句话理由</reason>`。两个都出现、或都没有，算审核失败。
- 只做一段式（自主）：Claude Code 先用 64 个 token 的快审再细审，是因为它每个非只读调用都要审；我们只审剩下的几类，量小，先不做两段。

### 3.3 结果

| 审核结果 | 执行 | 告诉模型的 | 用户看到的（细节等 HTML 预览定） |
|---|---|---|---|
| 放行 | 照常执行 | 无 | 工具行上一行小字"已由审核模型放行" |
| 不放行 | 不执行 | "自动审核没有放行这次调用：<理由>。不要换个写法再试；不依赖它的事继续做，需要时请用户明确授权" | 工具行显示被拒，带审核的理由 |
| 失败（超时、网关报错、输出看不懂） | 不执行 | "自动审核没能完成，这不是判定不安全；可以稍后照原样重试" | 工具行显示被拒，写明是审核没能完成 |

- 超时 60 秒（照 Claude Code 每次的起点），只试 1 次（自主：模型照原样重试就是重试）。
- 审核期间工具行显示"审核中"，不然看着像卡住（等预览定样子）。
- Stop 会立刻中止审核。

### 3.4 连续被拒的上限

照 Claude Code：**每个会话连续 3 次或累计 20 次**没放行后，下一次没放行的调用改为弹卡问用户，卡上带审核的理由。

- 连续计数在审核放行或用户答了卡后清零；累计到 20 次后，此后每次没放行都弹卡。
- 审核失败也计数（自主：审核模型挂了时，连拒 3 次后回到弹卡，不会一直拒下去）。

### 3.5 告诉模型的权限说明

`promptText.ts` 的全自动那句话按有没有审核模型分两种：

- 没有：保持现在的（决策 191 第 6.3 节，"危险命令和工作区外路径仍然每次询问"）。
- 有：改成"本来要问的调用（危险命令、工作区外路径、程序工具）先经自动安全审核；没放行的会返回理由，不要换个写法重试"。

录制样本按没有审核模型录，现有 3 个样本不变；另加一个有审核模型的场景（第 6 节）。权限菜单里「全自动」的说明（`ComposerPermissionTrigger.tsx`、`i18n.ts`）同样分两种。

## 4 契约：模型清单里的审核模型字段

登录服务的 `GET /api/v1/models-config` 多一个顶层字段，**只在管理员指定了、且该模型在清单里启用时才出现**：

```json
{ "version": 1, "updatedAt": "…", "providers": { … }, "autoReview": { "model": "<providerId>/<modelId>" } }
```

- `model` 用客户端现成的模型写法（`parsePiModelRef` 能解析、`piModelOption` 生成的 `provider/modelId`），必须指向同一份清单里的模型。
- 客户端：`configValidation.ts` 保留这个字段；格式不对、或指向的模型不在清单里，就丢掉并记日志（等于不审核）。老客户端会丢掉不认识的顶层字段，不受影响；老服务端不发这个字段，等于不审核。
- 内置快照（`resources/model-catalog/snapshot.json`）照原样带上。
- 模型计划（`src/shared/dshModelPlan/types.ts`）加 `reviewModel?: string`，计入 `revision`。管理员改了审核模型，宿主照现有规则在空闲时重启生效。指向的模型解析不出 completion 路由时，丢掉并记入 `dropped`。
- 审核用的思考档：模型支持 `low` 就用 `low`，否则不带（照 Codex）。

## 6 验证

- A：`bun test`、`bun run typecheck`、`bun run lint`；本机起登录服务（临时库），经管理接口设审核模型，`/api/v1/models-config` 里出现字段，停用该模型后字段消失。
- B：
  - 单测：审核钩子只在全自动档、配置了审核模型时生效；deny 规则先于审核；放行、不放行、失败三种结果；连续 3 次与累计 20 次后弹卡，卡上带理由；Stop 中止审核；对话整理不含助手的话、截断时注明；结果解析的各种乱码。
  - 现有 `autoGear`、`pwshGate`、`bashGate`、`approvalQueue` 等用例在没有审核钩子时不变。
  - 新录制场景 `auto-review`（计划里带审核模型）：放行后执行、不放行后模型收到理由、审核出错、连拒 3 次后弹卡。全量 `bridge-record.ts --check` 其余 36 个场景不变。
- C：清单校验的单测（字段缺失、格式错、指向不存在的模型）；模型计划的单测；界面的挂载测试。
- 合起来：三套 tsc、`pnpm test` 全量、`bridge-smoke.ts`；本机起登录服务，开发版 PiLab 指向它（`PILAB_MODEL_CONFIG_URL`），在 DSH 全自动会话里用假网关走一遍。
- 模型只用本机假网关，不用真实网关或密钥。
