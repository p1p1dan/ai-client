# 决策 208：对话区两种显示方式，终端式与桌面式，设置里切换

日期：2026-11-03（北京时间）。

**状态**：方向、选项、默认值、配色与英文用词都由用户 2026-11-03 定下（第 2 节）；同日第二轮裁决见第 2a 节。第 4 节标「自主」的各条待用户审批。

**代码**：本地分支 `feat/chat-transcript-style`，基于 origin/main `197e75e1`，未推送。

**证据**：
- 两轮可回放对比稿 [`ui-cohesion/transcript-density-options.html`](../../ui-cohesion/transcript-density-options.html)；
- 本文第 6 节的测试结果。

**修订关系**：
- PiLab R1（2026-10-30，`turnSteps.ts`）的三条：
  - 一段话之内的读文件与搜索合成一步，编辑合成一步：桌面式照旧；终端式改为只合并相邻的（第 2a 节）；
  - 思考从回合末尾的「思考 N 秒」打开：**作废**，思考改画在它发生的位置（第 2a 节）；
  - 运行中的那一行在回合末尾：照旧，终端式的写法改为对比稿 ① 的（第 2a 节）。
- runtime-hardening 的[决策 033](../../runtime-hardening/decisions/033-process-group-expanded-and-visual-hierarchy.md) D1 的「最终输出」分隔线撤掉。
- 折叠头（决策 033 D4 的吸顶头、决策 034 / 037 的头上计时）在 R1 时已不显示；它的遗留代码这次一并删除。

## 1 现象

2026-11-03 的实测截图里，对话区「一眼看过去全是字，完全抓不到重点」：

- 工具行缩成 12px 灰字，和正文交错排列；
- 终端命令下面还有一行「⎿ 末行 · N 行」；
- 同一种命令，跑完叫「终端」，被拒叫「运行」。

用户要求参考 Claude Code 的终端版与桌面版，多出几套方案并做成能看的 HTML。

## 2 用户裁决（2026-11-03）

1. 第一轮四个静态方案（收紧行、时间线、一步一行、进展卡）都不满意。
   - 用户更喜欢 Claude Code 终端版的输出，其次是桌面版。
   - 两者都不在回合结束后折叠过程。
   - 不必照搬，可以有自己的设计。
   - 方案要能看到完整的使用过程，因此第二轮做成可回放。
2. 第二轮看完后：
   - **终端式按 ①（终端原味）做**，只把用户消息从「> …」灰条改回现有气泡；
   - ② 不做，④⑤ 暂不优化。
3. 设置里只放两项：**终端式（①）、桌面式（③）**。现在这套画法不再提供。
4. 默认用终端式。
5. 彩色行内代码只用在终端式。
6. 圆点、被拒的颜色、块间距都按 ①：
   - 正文和工具的点一样大，靠颜色区分；
   - 被拒与失败同为红色，「不要五颜六色」；
   - 块与块之间空一整行。
7. 不翻译的内容：
   - 工具名用英文原名，照终端版的叫法，例如 Bash、Search；编辑类叫 Edit（不用终端版的 Update）；
   - 「show more / 展开」这类小操作词用英文原文。

## 2a 第二轮裁决（2026-11-03，开发版试用之后）

我列出实现与对比稿的五处不同后，用户的回复是：「对齐3，4，5.然后思考为什么是在最后一个按钮中显示。现有的Claude code和桌面版是这样做的？明显不是吧」。据此：

1. **第 3 处，运行中的那一行**：终端式按 ① 写成「✻ 正在做的那一步… (用时 · esc 中断)」。
2. **第 4 处，读与搜的合并**：终端式只合并相邻的，照终端版与 ①；桌面式保留整段合并。
3. **第 5 处，文件路径**：终端式照写路径，例如 `Read(workspace/README.md)`，不再把文件名提到目录前面。
4. **思考**：画在它发生的位置，不再从回合末尾的按钮打开。
5. **思考那一行的字用英文**（用户在收尾的问答里选了 "Switch to English"）：`Thought for 12s`、`Thinking…`，没测到时长写 `Thought`，和工具名一样不翻译。
   - 用户同时确认，点开后的思考正文是模型自己写的，不归我们管：原样显示，不翻译、不改写。用什么语言由模型决定。

第 1、2 处（末 3 行、回合末尾那一行）保持不变。

查证（Claude Code 2.1.273 拆包，与 open-claude-ui 对桌面版的还原）：

- **终端版**：
  - 主界面默认不显示思考原文（`case "thinking"` 在非 transcript、非 verbose 时返回 null）。
  - 思考用的时间并进它所在那一段合并组的标题，作为第一句，例如 "Thought for 4s, read 2 files"。
  - 运行中的提示行里写 thinking / thought for Ns。
  - ctrl+o 进入完整记录后，每段思考在原位置显示：一列暗色斜体 `∴`，加上思考原文。
- **桌面版**：在原位置显示「Thought for Ns ›」折叠条。
- 两者都不把一轮的思考收到回合末尾。10-30 的做法只照搬了终端版主界面「不显示」这一半，原位置这一半没做，结果一轮里几段思考全挤在最后一个按钮里。

## 3 改法

### 3.1 设置

- `chatTranscriptStyle: 'terminal' | 'desktop'`：
  - 类型、默认值与检查函数在 `src/shared/types/chatTranscriptStyle.ts`；
  - store 字段与 setter 在 `stores/settings`；
  - 读取存档时，未知值回落为终端式。
- 界面：外观 → 聊天区 →「对话显示方式」，`ToggleGroup`。
- `MessageTimeline` 用一个 selector 读设置，经 `TranscriptStyleContext` 往下传。
  - 子代理对话窗、侧边对话、权限卡里的单行没有这个 provider，照旧画。

### 3.2 终端式

- **圆点列**：
  - 每块左边 2ch 宽的一列「●」（`TerminalBlock`）。
  - 正文的点用文字色。
  - 步骤的点用 `StatusIcon shape="bullet"`：运行中灰色闪烁，成功绿，失败、被拒或非零退出码红，未执行或已停止灰。
  - 「减少动画」时不闪。
- **步骤行**：
  - 写成 **`Bash`**(说明)。说明仍是模型写的 description（10-30 的裁决）。
  - 工具名查 `stepPresentation.ts` 的英文名表，不经过翻译。
  - 合并步骤保留原有的整句标题。
- **`⎿` 结果行**（`deriveTerminalStepResult`）：
  - 终端命令取末尾最多 3 行；
  - 失败取开头几行，红色；
  - 被拒写「已拒绝 · 原因」，红色，行尾就不再重复「已拒绝」；
  - 结果未知照旧给提示；
  - 多出的行写 `… +N lines`，点开看全部；
  - 运行中的 DSH 命令沿用实时末 3 行。
  - Claude Code 在命令输出末尾自动追加的 `Shell cwd was reset to …` 不算结果，不进预览，经典行的「末行 · N 行」也一样。最早那几张截图里的噪音行就是它。点开后的完整输出里仍保留。
- **字体与间距**：
  - 助手一侧用等宽字体，行内代码用新色 `--inline-code`，不加底色；
  - 块距 20px，提问到首块 24px，轮距 32px。
- **特殊行**：子代理、审查结果、待办照旧画，放在正文列，不加圆点。

### 3.3 桌面式

- 两段正文之间的连续步骤收成一行灰字（`stepRuns.ts`），例如「运行了 3 条命令，读取了 2 个文件，搜索了 1 处」。
  - 只有一条时写「`Bash` 说明」；
  - 被拒、失败的条数用红字跟在行尾；
  - 运行中这一行显示正在跑的那一条，带扫光（`text-shimmer`）。
- 点开后，里面是原来的工具行。
- 用原生 `<details>` 实现，内容始终挂在页面上，聊天搜索与子代理窗的「定位」都能自动展开。
- 展开与收起：
  - 由 `turnWorkGroupOpen` 决定，默认收起；
  - 权限或提问未答时强制展开；
  - 异常结束的回合，最后一段默认展开（沿用 09-24、10-19 的裁决）；
  - 点击记在 `group:<key>`，按会话保存；
  - 点开时暂停「跟随到底部」。

### 3.3a 对话区里其余的工具行

桌面式点开后的行、权限卡留下的单行、终端式里的特殊行，仍用原来的工具行画法。但在对话区里，它们的工具名同样改为英文原名（`EnglishToolLabelsContext`）。这样同一个画面里不会一行写 `Bash`、下一行写「终端」。TodoWrite 记为 `Update Todos`，照终端版。
对话区以外（子代理对话窗等）不变。

### 3.4 撤掉的

- 两种样式都没有「最终输出」分隔线，删除 `'Final output'` 文案。
- 删除折叠头及其遗留代码：
  - `STEPS_INLINE`、`TurnProgressHead`、头上计时的闩锁；
  - `useTurnClockLine` 里结束态那一支；
  - `turnWorkGroupSummaryClass`（时间线从此没有吸顶元素）、`turnFinalAnswerDividerClass`、`turnProcessGroupFolds`。

### 3.5 第二轮的改法（第 2a 节）

- **运行中的那一行（终端式）**：
  - 写成「✻ 正在做的那一步… (12 秒 · esc 中断)」，由 `formatTerminalLiveActivity` 和 `formatTerminalLiveTail` 生成。
  - 正在跑的那一步，用它括号里的话（`formatToolArg`）；审查中写「审查中」；其余按阶段写「正在连接对话引擎…」「思考中…」「回复中…」「工作中…」。
  - 星号用 `StatusIcon shape="star"`：伪元素在 `· ✢ ✳ ✶ ✻ ✽` 之间来回切换（`animate-star`），「减少动画」时停在 ✻。
  - 星号和文字用品牌色，括号部分用弱色，等宽字体。
  - 输入框有焦点时按 Esc 会停止这一轮（开发版实测）。
  - 桌面式这一行不变。
- **合并（终端式）**：`deriveStepRows(rows, t, { merge: 'adjacent' })`。
  - 两个以上相邻的读、搜、列合成一步，编辑同理；中间隔了别的步骤就分开。
  - 夹在两次读之间的思考并进这一步：展开后按原顺序列出，标题写成 `Thought for 3s · 读取了 2 个文件`。
  - 第一次读之前、最后一次读之后的思考，各自单独一行。
- **路径（终端式）**：`ToolRowArg` 加 `asWritten`，终端式的步骤行用它；点击打开文件不变。
- **思考（两种样式）**：
  - `deriveToolGroupRows(…, { thoughts: 'inPlace' })` 给每段连续的思考一行，并记下它测到的时长 `thoughtMs`。
  - 时间线不再滤掉思考：`isThinkingOnlyItem` 与 `withoutThinking` 都不再调用。
  - 字样（`thoughtWords`、`thoughtForText`）：`Thought for 12s`、`Thinking…`、`Thought`，是英文字面量，不经过翻译（第 2a 节第 5 条）。
  - 终端式：`TerminalThoughtRow`，一行暗色斜体 `∴ Thought for 12s`，运行中写 `∴ Thinking…`；默认收起，整行可点开。
  - 桌面式：这段的摘要行以思考时长开头，例如 `Thought for 9s · 运行了 2 条命令 ›`；只有思考的一段写 `Thought for 5s ›`，点开直接是正文。
  - 对话区里其余的思考行（桌面式展开后、合并步骤的展开内容里）也写成 `Thought for 3s`，与摘要行一致（`EnglishToolLabelsContext`）。对话区以外照旧。
  - 回合末尾那一行的「思考 N 秒」改为纯文字的合计，`turn-thinking-toggle` 与面板删除，`TurnWorkZoneRow` 不再接收思考原文。

## 4 自主决定（待审批）

1. ~~编辑类工具叫 Update，照终端版~~。用户 2026-11-03 裁定：叫 **Edit**（工具的原始名），已改（`STEP_LABELS`）。
2. 合并步骤的整句标题（「搜索了 2 处，读取了 5 个文件」）与桌面式的摘要句子，仍用中文。
3. 终端命令的预览取**末尾** 3 行。终端版取开头几行；这里沿用 10-30「测试、构建的结论在最后」的理由。
4. 终端式的字号：
   - 步骤行与正文同档（默认 13px）；
   - `⎿` 行用过程档（默认 12px），都跟随设置。
5. 行内代码色：对比稿里的亮色 `#5769f7` 对画布只有约 4.3:1，达不到 AA，所以加深为 `#4b5de8`（约 5:1）。暗色 `#b1b9f9`。「跟随终端配色」时取终端的 blue / brightBlue。
6. 非零退出码的步骤，圆点画红（照终端版）。行尾「退出码 N」的字不变色。
7. 英文只用在这次新加的工具名与 `… +N lines` 上。已有的「查看全部」「展开」等词这次不动。
8. 桌面式：一段里的命令可以转到后台时，「转到后台」按钮放在摘要行旁边。原来它只在单条工具行上；收起的段落里看不到单条行，所以移到这里。
9. ~~思考的字样用中文~~。用户 2026-11-03 裁定用英文（第 2a 节第 5 条），已改。
10. 思考默认收起，运行中也收起（沿用 2026-09-23 的裁决）。桌面版生成时是展开的，这里没跟；运行中，回合末尾那一行已经写着「思考中…」。
11. 终端式的「只合并相邻」也用在编辑上。用户这一轮说的是读与搜；编辑沿用同一条规则，免得两种合并各有一套。
12. 桌面式：时长没测到的思考（重新打开的会话），在有其他步骤的段落里不写进摘要，展开后仍按原位置列出。
13. 回合末尾那一行保留「思考 N 秒」这一合计，但不能再点开。
14. 发出后、回合还没出现之前的那一行（`PendingTurnHead`，通常不到一秒）仍是原来的写法，没按终端式改。
15. 英文的思考时长后面跟着中文的计数句时，用 ` · ` 隔开（`Thought for 9s · 运行了 2 条命令`），不用逗号连成一句：两种语言连成一句读着别扭。终端版原文是逗号（"Thought for 9s, ran 2 commands"）。
16. 回合运行行里的「思考中…」和回合末尾那一行的「思考 N 秒」仍用中文：它们是整句状态的一部分，不算思考那一行的标签。**用户 2026-11-03 已确认（「保持中文」）。**

## 5 不做的

- ②（界面字体版的终端式）、④ 进展卡、⑤ 实时条（用户：暂不优化）。
