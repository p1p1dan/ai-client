# 决策 208：对话区两种显示方式，终端式与桌面式，设置里切换

日期：2026-11-03（北京时间）。

**状态**：方向、选项、默认值、配色与英文用词都由用户 2026-11-03 定下（第 2 节）。第 4 节标「自主」的各条待用户审批。

**代码**：本地分支 `feat/chat-transcript-style`，基于 origin/main `197e75e1`，未推送。

**证据**：
- 两轮可回放对比稿 [`ui-cohesion/transcript-density-options.html`](../../ui-cohesion/transcript-density-options.html)；

**修订关系**：
- PiLab R1（2026-10-30，`turnSteps.ts`）的三条照旧：
  - 一段话之内的读文件与搜索合成一步，编辑合成一步；
  - 思考从回合末尾的「思考 N 秒」打开；
  - 运行中的那一行在回合末尾。
- runtime-hardening 的[决策 033](../../runtime-hardening/decisions/033-process-group-expanded-and-visual-hierarchy.md) D1 的「最终输出」分隔线撤掉。
- 折叠头（决策 033 D4 的吸顶头、决策 034 / 037 的头上计时）在 R1 时已不显示；它的遗留代码这次一并删除。

## 1 现象

2026-11-03 的实测截图里，对话区「一眼看过去全是字，完全抓不到重点」：

- 工具行缩成 12px 灰字，和正文交错排列；
- 终端命令下面还有一行「⎿ 末行 · N 行」；
- 同一种命令，跑完叫「终端」，被拒叫「运行」。

用户要求参考 Claude Code 的终端版与桌面版，多出几套方案并做成能看的 HTML。

## 2 用户裁决（2026-11-03）

1. 第一轮四个静态方案（收紧行、时间线、一步一行、进展卡）都不满意。
   - 用户更喜欢 Claude Code 终端版的输出，其次是桌面版。
   - 两者都不在回合结束后折叠过程。
   - 不必照搬，可以有自己的设计。
   - 方案要能看到完整的使用过程，因此第二轮做成可回放。
2. 第二轮看完后：
   - **终端式按 ①（终端原味）做**，只把用户消息从「> …」灰条改回现有气泡；
   - ② 不做，④⑤ 暂不优化。
3. 设置里只放两项：**终端式（①）、桌面式（③）**。现在这套画法不再提供。
4. 默认用终端式。
5. 彩色行内代码只用在终端式。
6. 圆点、被拒的颜色、块间距都按 ①：
   - 正文和工具的点一样大，靠颜色区分；
   - 被拒与失败同为红色，「不要五颜六色」；
   - 块与块之间空一整行。
7. 不翻译的内容：
   - 工具名用英文原名，照终端版的叫法，例如 Bash、Search；编辑类叫 Edit（不用终端版的 Update）；
   - 「show more / 展开」这类小操作词用英文原文。

## 3 改法

### 3.1 设置

- `chatTranscriptStyle: 'terminal' | 'desktop'`：
  - 类型、默认值与检查函数在 `src/shared/types/chatTranscriptStyle.ts`；
  - store 字段与 setter 在 `stores/settings`；
  - 读取存档时，未知值回落为终端式。
- 界面：外观 → 聊天区 →「对话显示方式」，`ToggleGroup`。
- `MessageTimeline` 用一个 selector 读设置，经 `TranscriptStyleContext` 往下传。
  - 子代理对话窗、侧边对话、权限卡里的单行没有这个 provider，照旧画。

### 3.2 终端式

- **圆点列**：
  - 每块左边 2ch 宽的一列「●」（`TerminalBlock`）。
  - 正文的点用文字色。
  - 步骤的点用 `StatusIcon shape="bullet"`：运行中灰色闪烁，成功绿，失败、被拒或非零退出码红，未执行或已停止灰。
  - 「减少动画」时不闪。
- **步骤行**：
  - 写成 **`Bash`**(说明)。说明仍是模型写的 description（10-30 的裁决）。
  - 工具名查 `stepPresentation.ts` 的英文名表，不经过翻译。
  - 合并步骤保留原有的整句标题。
- **`⎿` 结果行**（`deriveTerminalStepResult`）：
  - 终端命令取末尾最多 3 行；
  - 失败取开头几行，红色；
  - 被拒写「已拒绝 · 原因」，红色，行尾就不再重复「已拒绝」；
  - 结果未知照旧给提示；
  - 多出的行写 `… +N lines`，点开看全部；
  - 运行中的 DSH 命令沿用实时末 3 行。
  - Claude Code 在命令输出末尾自动追加的 `Shell cwd was reset to …` 不算结果，不进预览，经典行的「末行 · N 行」也一样。最早那几张截图里的噪音行就是它。点开后的完整输出里仍保留。
- **字体与间距**：
  - 助手一侧用等宽字体，行内代码用新色 `--inline-code`，不加底色；
  - 块距 20px，提问到首块 24px，轮距 32px。
- **特殊行**：子代理、审查结果、待办照旧画，放在正文列，不加圆点。

### 3.3 桌面式

- 两段正文之间的连续步骤收成一行灰字（`stepRuns.ts`），例如「运行了 3 条命令，读取了 2 个文件，搜索了 1 处」。
  - 只有一条时写「`Bash` 说明」；
  - 被拒、失败的条数用红字跟在行尾；
  - 运行中这一行显示正在跑的那一条，带扫光（`text-shimmer`）。
- 点开后，里面是原来的工具行。
- 用原生 `<details>` 实现，内容始终挂在页面上，聊天搜索与子代理窗的「定位」都能自动展开。
- 展开与收起：
  - 由 `turnWorkGroupOpen` 决定，默认收起；
  - 权限或提问未答时强制展开；
  - 异常结束的回合，最后一段默认展开（沿用 09-24、10-19 的裁决）；
  - 点击记在 `group:<key>`，按会话保存；
  - 点开时暂停「跟随到底部」。

### 3.3a 对话区里其余的工具行

桌面式点开后的行、权限卡留下的单行、终端式里的特殊行，仍用原来的工具行画法。但在对话区里，它们的工具名同样改为英文原名（`EnglishToolLabelsContext`）。这样同一个画面里不会一行写 `Bash`、下一行写「终端」。TodoWrite 记为 `Update Todos`，照终端版。
对话区以外（子代理对话窗等）不变。

### 3.4 撤掉的

- 两种样式都没有「最终输出」分隔线，删除 `'Final output'` 文案。
- 删除折叠头及其遗留代码：
  - `STEPS_INLINE`、`TurnProgressHead`、头上计时的闩锁；
  - `useTurnClockLine` 里结束态那一支；
  - `turnWorkGroupSummaryClass`（时间线从此没有吸顶元素）、`turnFinalAnswerDividerClass`、`turnProcessGroupFolds`。

## 4 自主决定（待审批）

1. ~~编辑类工具叫 Update，照终端版~~。用户 2026-11-03 裁定：叫 **Edit**（工具的原始名），已改（`STEP_LABELS`）。
2. 合并步骤的整句标题（「搜索了 2 处，读取了 5 个文件」）与桌面式的摘要句子，仍用中文。
3. 终端命令的预览取**末尾** 3 行。终端版取开头几行；这里沿用 10-30「测试、构建的结论在最后」的理由。
4. 终端式的字号：
   - 步骤行与正文同档（默认 13px）；
   - `⎿` 行用过程档（默认 12px），都跟随设置。
5. 行内代码色：对比稿里的亮色 `#5769f7` 对画布只有约 4.3:1，达不到 AA，所以加深为 `#4b5de8`（约 5:1）。暗色 `#b1b9f9`。「跟随终端配色」时取终端的 blue / brightBlue。
6. 非零退出码的步骤，圆点画红（照终端版）。行尾「退出码 N」的字不变色。
7. 英文只用在这次新加的工具名与 `… +N lines` 上。已有的「查看全部」「展开」等词这次不动。
8. 桌面式：一段里的命令可以转到后台时，「转到后台」按钮放在摘要行旁边。原来它只在单条工具行上；收起的段落里看不到单条行，所以移到这里。

## 5 不做的

- ②（界面字体版的终端式）、④ 进展卡、⑤ 实时条（用户：暂不优化）。
- 子代理对话窗不跟随设置。它本来就不走步骤模型，照旧画。
- 一轮里没有正文时，通知排在所有步骤之后（10-30 起就是这样）。桌面式下，这可能让两条摘要行挨在一起。这次先接受。
- 运行中，Claude 引擎没有实时输出，终端式步骤只有闪烁的圆点。
