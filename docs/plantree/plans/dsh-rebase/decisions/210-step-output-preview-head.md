**状态**：方向由用户 2026-11-08 的要求定下（第 1 节），做法照 Claude Code 终端版与桌面版（第 2 节）。第 4 节标「自主」的各条待用户审批。

**代码**：main，在决策 208 合入（`f2a677cd`）之后；2026-11-08 推送，随测试包 `1.2.3-test.1` 出包。

**修订关系**：

- [决策 208](208-chat-transcript-styles.md) §3.2「终端命令取末尾最多 3 行」改为取开头最多 3 行，正好 4 行时 4 行全显示。
- PiLab R1（2026-10-30，`turnSteps.ts` 规则 2）「命令的最后一行 · N 行」撤掉。经典步骤行只在失败、结果未知时留一行。

## 1 现象

用户 2026-11-08 附了一张 1.2.2 的截图，原话：「现在这个终端调用下方的展示内容很鸡肋，很容易有无效信息，看看 claude code 或桌面版是怎么做的，适当优化修改一下」。

截图里，每条终端命令下面都有一行 `⎿ 末行 · N 行`：

- `4168 total · 67 行`
- `vm/ · 76 行`
- `} · 69 行`
- `----`
- `IpcServer.h · 4 行`

这些命令大多是模型在读代码、列目录。输出的最后一行是收尾的括号、分隔线或合计，说明不了这一步做了什么。

决策 208 的终端式取末 3 行，毛病一样：末尾常是 `}`、合计，或者 DSH 自己补的 `[exit code: N]` 标记。

## 2 查证

- **终端版**（Claude Code 2.1.273 拆包）：
  - 工具输出由 `OutputLine` 折叠（`kjn`），取开头 3 行；正好 4 行时 4 行全显示；超出的写 `… +N lines (ctrl+o to expand)`。
  - 长行按终端宽度折行，折出来的行也算进 3 行。
  - Bash 的结果组件把 stdout、stderr 各折一次，stderr 用红色。两者都为空时写 `(No output)`，没有输出是预期时写 `Done`，转到后台时写 `Running in the background`。
  - 末尾的 `Shell cwd was reset to …` 提示单独用暗色显示，不算输出。
- **桌面版**（open-claude-ui 对桌面版的还原，`docs/v1/03` §3.5.2）：执行完只切换状态标记，控制台输出收在折叠里，点开才看。行内没有输出预览。

## 3 改法

### 3.1 终端式（`stepPresentation.ts` 的 `deriveTerminalStepResult`）

- 命令跑完：取输出开头最多 3 行；正好 4 行时 4 行全显示；余下的写 `… +N lines`，点开看全部。
- 保留行首缩进：代码、JSON、目录树要靠缩进才读得懂。只去掉行尾空白，空行照旧不算。
- 下面这些不进预览，点开后的完整输出里仍保留：
  - DSH 的 `[stderr]` 小标题；
  - `[output truncated; full output: …]`：带临时文件路径；
  - `[exit code: N]`：行尾已经写了「退出码 N」；
  - Claude Code 的 `Shell cwd was reset to …`；
  - 占位文字 `(no output)`；
  - DSH 的溢出说明 `(Omitted N bytes …)`。
- DSH 只保留了尾部的长输出：从第一个完整的行开始取，与点开后正文的开头一致（`dshShellOutputHead`）。
- 只回来一条溢出说明时，照旧写「输出较大，点开查看」。
- 失败：取开头几行，红色。原来就是取开头几行，现在改用同一套过滤。
- 退出码不为 0：取开头几行，红色，对应终端版 stderr 的红色。
- 被拒、结果未知、运行中三种情况不变。

### 3.2 经典步骤行（`turnSteps.ts` 的 `deriveStepResult`）

用在桌面式点开后的连续步骤、子代理对话窗和旁问里。

- 命令正常跑完：不再有结果行。输出要点开这一步才看，与桌面版一致。
- 失败：取第一行真正的输出，跳过 DSH 的 `[stderr]` 小标题，红色。Claude 引擎失败时输出以 `Exit code N` 开头，后面还有内容的话，这一行让给后面的报错（第 6 节的实测）。
- 结果未知：照旧给提示。
- 退出码不为 0：不加行，行尾的「退出码 N」已经说明了（见第 4 节第 3 条）。

新的取行函数是 `outputPreviewLines`（`turnSteps.ts`），两种画法共用。

## 4 自主决定（待审批）

1. 终端式里，命令没有输出时不写 `(No output)`。终端版会写，但这行不带信息，绿色圆点已经说明命令跑完了。
2. Claude 引擎的命令失败时，输出第一行是 `Exit code N`（终端版发给模型的文本）。
   - 终端式保留这一行。终端版失败的命令也以它打头，而且这条引擎的行尾不显示退出码，它是唯一说出退出码的地方。
   - 经典步骤行只有一行的位置，红叉已经说明失败了，所以后面还有内容时让给真正的报错；只有这一行时照旧显示它。
   - DSH 的 `[exit code: N]` 两种画法都去掉，因为行尾已经写了「退出码 N」。
3. 经典步骤行在退出码不为 0 时不加行。哪一行能说明原因要看工具：测试的结论在末尾，编译器的第一个错误在开头，猜错的那一行就是噪音。行尾的「退出码 N」加上点开后的完整输出已经够用。终端式则照终端版显示开头几行。
4. 终端版按终端宽度把长行折开，折出来的行也算进 3 行。我们仍是每行最多 400 字，靠 CSS 换行（决策 208 原样）。
5. stdout 与 stderr：终端版分两段，各取 3 行。DSH 把两者拼成一段文本，我们按一段取开头 3 行。

## 6 开发版实测（2026-11-08）

用 `gui-probe.mjs` 起开发版，模型走本地假网关（`--plan claude-sdk`，Agent SDK 引擎），权限设为跳过确认。一轮 `CC-RUN` 依次跑 7 条 Bash：`ls -la`、`cat package.json`、输出正好 4 行的 `printf`、`seq 1 50`、`mkdir -p build`、会失败的 `git log -1 no-such-ref`、`cd .. && echo moved`。

终端式：

- `ls -la`：显示 `total 10` 和两行目录，下面是 `… +3 lines`；
- `package.json`：显示 `{` 和两行带缩进的字段，下面是 `… +5 lines`；
- 正好 4 行的输出：4 行全显示，没有 `… +N lines`；
- `seq 1 50`：显示 `1 2 3`，下面是 `… +47 lines`；
- `mkdir`：没有结果行；
- `git log`：红色，`Exit code 128` 加三行报错；
- `cd ..`：只显示 `moved`，Claude Code 补的 `Shell cwd was reset to …` 没有进预览。

桌面式（设置 → 外观 → 对话显示方式）：

- 一行汇总写「运行了 7 条命令 1 条失败」，点开是 7 行 `Bash 说明`；
- 成功的 6 条下面都没有结果行；
- 失败那条起初显示 `⎿ Exit code 128`，和左边的红叉重复，原因却看不到。于是改成跳过开头的 `Exit code N`（第 3.2 节），热更新后显示 `⎿ fatal: ambiguous argument 'no-such-ref': unknown revision or path not in the working tree.`。
