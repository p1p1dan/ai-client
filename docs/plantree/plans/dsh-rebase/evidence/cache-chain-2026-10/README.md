## 设计要点

1. **放在哪**：独立一组（`border-t`），可折叠，夹在「上一回合」用量组和「本会话」组之间。它是上面那几行的逐步展开：最后一行的读、写，就是上面「缓存读取」「缓存写入」两行的数字。
2. **分组标题**：`h-7` 的触发器，从左到右是箭头、「逐步缓存」（`text-ui`）、有警告时的橙色徽标「N 处异常」、右侧「本回合 N 步」（`text-meta` 灰字）。收起时也能看出有没有异常。
3. **列**：步、提示词、缓存读、缓存写。提示词 = 输入 + 缓存读 + 缓存写，与决策 173 的判定口径一致。
   - 数字 `text-meta tabular-nums`，右对齐，`w-12` 定宽，用现有 `formatTokenTotal` 的 k / M 缩写；
   - 步号 `w-8`，右对齐，灰字；列头 `h-6`，灰字；
   - 数字整组靠右（`ml-auto`），右缘与上方各行的数值对齐；
   - 悬停数字出精确值（「第 15 步：提示词 174,880 · 缓存读 36,848 · 缓存写 138,030」）。
4. **徽标**：每步最多一个，写主因，尺寸 `Badge size="lg"`（桌面 14px，侧栏放中文徽标用的就是这一档）。命中不出徽标。三种颜色：
   - 灰 `secondary`：正常情况的说明（首次写入、新回合）；
   - 蓝 `info`：有本地原因的重建；
   - 橙 `warning`：找不到本地原因。这一行的「缓存写」数字也标橙，方便在长列表里找。
5. **三种宽度**：
   - 280 / 360：徽标叠在数字下面一行，缩进到步号列之后；
   - 500：徽标在同一行，夹在步号和数字之间；
   - 由容器查询判定（`@container` + `@md:`，组宽 ≥ 28rem = 448px），看的是组宽，不是窗口宽。三档组宽是 263 / 343 / 483px；
   - 两种摆法里徽标都能截断（`min-w-0 max-w-full shrink`，文字包 `truncate`），不会溢出。最长的「闲置 1 小时 12 分，缓存已过期」按字宽估算约 200px，280 的叠放行可用 215px，放得下（没有实测）。
6. **会话级提示**：只要有找不到本地原因的步骤就出，位置在面板最上面（标题栏下、状态头上），单独一段（`border-b`）。
   - 形态：`Alert variant="warning"`，图标 `TriangleAlert`；
   - 标题「这个会话的缓存多次被重建」；
   - 正文「有 3 次重建找不到本地原因，共重写约 185k tokens。客户端每次都是在上一个请求的末尾追加（已校验），多半是网关把请求分到了不同的上游。」；
   - 按钮「复制诊断信息」，点后变「已复制」1.5 秒；
   - 「重写」的口径：本来在缓存里、又写了一遍的量，即 min(上一步提示词 − 本步读量, 本步写入)。徽标里的「重写约 133k」也按这个算；
   - 「（已校验）」依据是前缀指纹（决策 173 §4.2）。前缀指纹关掉或校验没过时，这半句要换掉。
7. **复制的内容**（右侧预览）：版本、网关会话 ID、模型与推理档位、汇总、前缀校验结果、回合开始时刻，加逐步表（时刻、提示词、读、写、判定）。
   - 网关会话 ID 就是我们在 `metadata.user_id` 里发的 `session_id`（决策 173 §4.1），网关拿它当会话号，管理员可以凭它查上游链路；
   - 只有数字和 ID，不含提示词、工具内容、路径、账号和网关地址。
8. **现有部分不动**：状态头、占用环、状态 / 上一回合 / 模型 / 工具调用、上一回合用量组、本会话组，都照 `RunSurfaceView.tsx` 现在的样子画。DSH 不算价，所以没有费用行。
9. **只对 anthropic-messages 告警**（决策 173 §4.3）：其他路由（如 GLM）照样列数字，但不出橙色徽标，也不出会话提示。

## 与设计规范

守住的：没有新 token，没有任意值；字号只用 `text-meta` / `text-ui`，徽标、提示、按钮都是 14px；数字全加 `tabular-nums`；行 `h-7`、列头 `h-6`、按钮 `h-6`；`h-7` 的行用 `rounded-sm`；颜色全是语义 token；截断用 `min-w-0 … truncate` 加 `shrink-0` 的定宽部分。

需要注意的几处：

1. **Tooltip 字号**：原语是 `text-xs`（12px），中文提示照 `BranchColumn` 加 `text-meta`。这是全局问题，#6 的 README 已记。
2. **徽标尺寸**：现有面板的耗时 chip 是 `size="sm"`（10px），只装拉丁数字。中文徽标不能用 `sm` / `default`（10 / 12px），统一 `size="lg"`。
3. **容器查询**：Tailwind v4 内置的 `@container` / `@md:`，不算任意值。本仓第一次用宽度容器；首页锚定标题用过尺寸容器（`container-type: size`）。
4. **橙色数字**：信息不只靠颜色传达，同一行有文字徽标；颜色只是让长列表里好找。
5. **字重**：徽标和 `AlertTitle` 自带 `font-medium`（500），中文 Windows 上显示成 400。这是原语自带的，侧栏红线 1 也豁免。勾「CJK / Win10 字重」可以看效果。

## 待用户拍板

1. **「上一回合」的叫法冲突。** 现有用量组的「输入 / 输出 / 缓存命中率（上一回合）」其实是最后一步：每个结算后的 `usage.updated` 是一次模型请求。「回合数（本会话）」其实是步数（`usageSteps`）。新分组写「本回合 22 步」，两处「回合」指的不是一回事。
   - 提议：那三行改成「（最后一步）」，「回合数（本会话）」改成「步数（本会话）」；
   - 原型没改，保持现状。
2. **命中率分母不含写入。** 「缓存命中率（上一回合）」= 读 /（输入 + 读），所以重建的那一步也显示 100%（第 15 步读 36,848、写 138,030，算出来是 100%）。要不要改成「读 / 提示词」，或者把这一行去掉、由逐步视图代替？
3. **会话提示的门槛与去留。** 原型是有 1 处找不到本地原因就出，标题却写「多次」。
   - 是否改成 ≥ 2 处，或合计重写 ≥ 100k 才出；
   - 要不要能关掉（关掉后这个会话不再出）。
4. **长回合怎么收。** issue #9 一个回合 89 步，原型是全列出（状态 3 是 22 行）。备选两种：
   - 超过 30 步时只列最近 20 步，上面加一行「查看更早的 N 步」；
   - 连续命中的步骤折成一行（「第 2～14 步都复用了上一步的缓存」），有徽标的行单独列。
5. **默认展开还是收起**；用户收起后记不记住（按会话还是全局）。
6. **复制内容里有每一步的时刻**，为了让网关管理员对得上日志。时刻、版本号、模型名留不留？
7. **新回合（turn-shrink）** 出灰色徽标，还是像命中一样什么都不出？
8. **一步有几个原因时**（例如重开会话后换了模型，又闲置超过 1 小时），原型只出主因，悬停里也只写主因。要不要在悬停里列全？主因的先后，提议：换模型 > 恢复会话 > 闲置 > 压缩 > 计划模式。
9. **运行中的行。** 一步刚开始，流里的 pending usage 就带着提示词一侧的读、写数，可以当时就出这一行，重建当场可见；也可以等这一步结算后再出。原型只画了已完成。
10. **本会话组没有「缓存写入（本会话累计）」**，这次的问题恰恰出在写入。要不要补这一行？
