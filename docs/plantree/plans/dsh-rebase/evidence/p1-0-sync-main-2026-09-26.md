## v1.0.3 新增、DSH 桥接尚未实现的语义

合并本身不涉及这些，但 P1 必须补上，否则合入 main 时会让 v1.0.3 的功能倒退：

1. **Ctrl+Enter 插话**（v1.0.3 主功能；决策 046 另加了 `WorkerInterjectResult.turnActive`）。`DshSessionRuntime.interject()` 固定返回 `{ interjected: false }`，DSH 下插话不可用。它也不报 `turnActive`，Main 视为「未报告」，所以不会误清 busy。→ P1-4。
2. **失败后「继续」= 重试上一轮**（T135 / 决策 045）：`WorkerSendPayload.mode: 'retry'`，此时 `text` 为空；没有可重跑的回合时，应以 `WORKER_RETRY_UNAVAILABLE` 拒绝。`DshSessionRuntime.send()` 不看 `mode`，会把空文本当成一条新的用户消息发出去。→ P1-4。
3. **Stop 必收尾**（T144）：`WorkerManager` 的 `STOP_WATCHDOG_MS = 10_000` 看门狗，停不下来就 `forceKillNow()` 并以 `stopCause: 'forced'` 重启 worker。目前一个会话一个宿主，这条对 DSH 照样生效。到了共享宿主，强杀的是整个宿主，会连带同宿主的其他会话。→ P1-3 要把它改成先按会话收尾，最后才动宿主。
