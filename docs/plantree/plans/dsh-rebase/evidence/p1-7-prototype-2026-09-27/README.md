## 实测高度（窗口 1400×900）

三条沿用排队消息条的形制：`queueStripWrapperClass()` 是 `mb-2 flex flex-col gap-1`，每条 `h-7 rounded-sm border bg-muted/50 text-meta`。

| 场景 | 出现的条 | 条本身 | 加下方 8 px 间距，输入框上方多占 | 聊天区可视高度 |
|---|---|---|---|---|
| B 三条折叠 | 待办 28 + 目标 28 + 后台 28，条间距 4 × 2 | **92 px** | **100 px** | 711 → 611 px |
| A 三条出现，待办（5 项）与后台（2 项）展开 | 待办 154 + 目标 28 + 后台 90，条间距 4 × 2 | 280 px | **288 px** | 711 → 423 px |
| D 只有后台条，展开并打开一条输出尾部 | 后台 277 | 277 px | 285 px | 711 → 426 px |
| C、E 只有一条 | 28 | 28 px | 36 px | 711 → 675 px |

**决策 068 估的约 84 px 只算了 3 × 28**，没算两道 4 px 条间距和条组下方 8 px 的间距。按现有排队条的形制，三条都折叠时实际多占 **100 px**。

## 各场景要确认的问题

截图里橙色虚线、括号和「新增」小标是原型标注，不属于界面。聊天区与左栏的其余内容（轮次头、工具行、会话列表）只作背景，不在这次确认范围内。

### A · 三条都出现（待办、后台展开，目标一行）→ 决策 068 规则 1

截图：`A-three-strips-expanded-{light,dark}.png`。目标第 3 轮进行中，待办 3/5，后台两个命令在跑。

1. 从上到下「待办 → 目标 → 后台」这个顺序行不行？（与 DSH 的顺序一致，方案 U1）
2. 两张卡同时展开时多占 288 px，聊天区从 711 px 缩到 423 px。要不要给三条整组设一个最大高度，超出后在组内滚动？
3. 目标进行中用蓝色靶心图标，暂停时换成灰色暂停图标。这样够不够醒目？

### B · 三条都折叠（默认态）→ 决策 068 规则 1

截图：`B-three-strips-collapsed-{light,dark}.png`。与 A 同一时刻。

1. 默认全部折叠行不行？还是待办卡默认展开？
2. 三条都折叠时多占 100 px（决策估约 84 px），能不能接受？
3. 折叠后的文案够不够用？待办写「3/5 · 正在：…」，目标写轮次、状态和目标原文（放不下时截断，悬停看全文），后台写「2 运行中」。

### C · 目标运行中插话，目标暂停 → 决策 071

截图：`C-goal-paused-after-interject-{light,dark}.png`。第 3 轮在步边界结束，插话作为下一回合的输入，目标暂停，条上给「继续」。新一轮开始时 DSH 清空了待办，所以这里没有待办卡。

1. 条上只写「目标已暂停」（照方案 §2 的状态表），不写原因。要不要写明「插话后已暂停」？（要写的话，渲染层得自己记住这次暂停是插话引起的，DSH 的暂停状态里没有原因）
2. 「继续」放在条的右侧，和「暂停」同一个位置，样式与其他按钮一样。要不要更醒目？
3. 插话之后要多点一次「继续」，这个代价能不能接受？另一个方案是用 DSH 的 steer 把消息并进当前轮、目标不停，决策 071 把它留作后续增强。

### D · 只有后台条：一个失败、一个完成 → 决策 068 规则 1、决策 069

截图：`D-background-only-done-and-failed-{light,dark}.png`。lint 失败（退出码 1），单测完成（退出码 0），失败那条展开了输出尾部。聊天区里有「后台任务 bash-4 已结束，自动继续」的轮次头（决策 069 的自动唤醒、决策 072 规则 3 的轮次头）和一条回合中途的完成通知。

1. 按方案 §4，非 0 退出码只用中性徽标、不标红。这样行不行，还是失败要标红？
2. 已结束的项留在条里，「移除」只在本机隐藏；最多留 8 项。要不要改成过一段时间自动收起？
3. 输出尾部在条内展开（最高 160 px），展开一条就多占 285 px。这个位置合不合适？
4. 没有运行中的项时，条上不显示「全部停止」。

### E · 子代理：行内泳道 + 左栏「运行」面板清单 → 决策 068 规则 2

截图：`E-subagent-list-in-run-panel-{light,dark}.png`。explore 运行中（泳道展开），分叉已完成，review 失败（拒绝了任务）。

1. 清单放在左栏「运行」面板合不合适？面板收起时就看不到清单（决策 068 已记为代价）。
2. 清单放在状态块下面、上下文环上面。方案没有规定位置，这是原型定的。这个位置行不行？
3. 同一个运行中的子代理会同时出现在三个地方：泳道、清单、后台条（方案 §4 把运行中的可续跑子代理也列进后台条）。这算不算重复，要不要从后台条里拿掉？
4. 左栏只有 280 px 宽，一行放不下线框里的全部字段，所以每个子代理占两行：第一行名称、描述、用时，第二行用量和「打断」「定位」。这样排行不行？

## 原型自己定的细节（方案没写死）

1. 三条的折叠按钮统一放在最右端：折叠时是向上的箭头，展开时是向下的箭头。线框里待办的箭头在右、后台的在左，这里统一了。条组贴着输入框，展开时内容在标题下面，所以标题会往上移。
2. 图标只有两处用颜色：目标进行中的靶心用 `--status-running`，子代理清单的完成 / 失败用 `--success` / `--destructive`。其余都是 `--muted-foreground`。
3. 后台行的列顺序取线框的「状态 → 退出码 → 用时 → 操作」；方案 §4 正文写的是「用时 → 结果」，两处不一致。
4. 目标条的「⋯」菜单是「编辑目标…」「复制目标文本」「清除目标…」，照方案 §2。

## 原型里没有画的

- 问答卡 / 审批卡浮层和排队消息条。它们在三条下面、输入框上面，方案 §1 没有改它们。
- 目标的其余状态：等待下一轮、已挂起、受阻、轮数用完、已完成（方案 §2 的状态表）。
- 窄窗口下按钮只剩图标、文字进 Tooltip 的形态。
- 原型是静态 HTML，没有用 @coss/ui 组件本身；颜色 token 从 `src/renderer/styles/globals.css` 原样抄，字号、圆角、间距按 `docs/design-system.md` 的档位。截图用本机字体（Ubuntu + Noto Sans CJK SC）渲染。
