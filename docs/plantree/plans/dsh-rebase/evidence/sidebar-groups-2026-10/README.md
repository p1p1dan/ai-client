# 对话归类效果预览（#15 第二期，2026-10-13）

**状态：v1 定稿（2026-10-13 用户两轮看过并裁决），作为[决策 187](../../decisions/187-sidebar-groups-phase-2.md) 的验收基准。**

`prototype.html` 单文件、离线可用，数据全部虚构。这是[决策 186](../../decisions/186-github-issues-10-16-first-batch.md) 第 3 节「第二期与已知难点」的落实稿：第二期**不做拖动**，改为右键「移到分组 ▸」。

## 用户裁决（2026-10-13）

1. 按推荐方案——右键「移到分组 ▸」，不做拖动。
2. 新建分组用**行内输入**。
3. 删除分组时对话**回到「未分组」**。
4. 「未分组」**固定最后**。
5. 用户分组标题**保留「＋」**。
6. **一个对话只在一个分组**。
7. 分组标记用**竖线**，「未分组」也用竖线。
8. 切换按钮图标用**标签**（`Tag`）。
9. 列表**空白处右键**可以新建分组。

## 怎么打开

浏览器直接打开 `prototype.html`，无需构建、无需起服务。

## 侧栏里可以真的操作

- 右键任意对话行 →「移到分组 ▸」→ 选一个分组，**真的会移动**；子菜单里当前所在的组带勾，所以它同时回答「这条对话现在在哪」。
- 右键分组标题 →「新建分组…」/「重命名」/「删除分组」。重命名是行内编辑（标题原地变输入框），与对话行的重命名同一做法。
- 右键列表空白处 →「新建分组…」。
- 删除一个有对话的分组：对话回到「未分组」，不跟着消失。
- 工具条的「新建分组」开关切「行内输入」与「弹对话框」两种做法，都能建（**定稿是行内输入**）。
- 「归档方式」切到「按工作目录」，看第一期已实现的那棵树——两边的对话行是同一套，对比它们是不是同一个东西。
- 「用户分组标题」开关看带不带「＋」（**定稿是带**）。
- 「分组图形」开关对比 无 / 圆点 / 竖线 / # / 标签 / 文件夹（**定稿是竖线**，实现见决策 187）。
- 「切换按钮图标」开关对比 层叠 / 标签 / 两栏 / 树 / 方块 / 旧（**定稿是标签**）。

## 与第一期的一致性

分组标题（13px 灰字）、折叠、8 条上限与「查看更多」、搜索时命中组自动展开——全部与仓库分组同一套；对话行也一样，只是行尾的上下文文字从「分支」换成「仓库名」，因为柜台上没有仓库标题行替它说了。

第一期没有用户分组时，「按分组」下只有「未分组」一个组，即是本次改动的起点，两边衔接得上；实现上两者已是同一个 `buildGroupFolder` 与同一个 `renderGroupSection`。

## 本期不做

- **拖动归类**：不用拖拽层、不用跨 `ScrollArea` 自动滚动、不用判定落点，最要紧的是不必把「拖动」与「单击打开对话」区分开（做错就误拖被读成误点）。代价是一次归类要三次点击。
- **组内手动排序**（依赖拖动层）。
- **批量移到分组**（现有批量归档只管归档）。
- 组的颜色、图标、嵌套。

## 迭代

- **v1**（2026-10-13）：首次出稿。右键「移到分组 ▸」+ 分组标题行右键三件事（新建 / 重命名 / 删除）；「未分组」固定最后、不可改名删除；空组保留并显示「暂无对话」。
- **v1 第二版**（同日，用户第一轮裁决后）：工具条加「分组图形」「切换按钮图标」两个候选开关；列表空白处右键加「新建分组…」；「未分组」改用与用户分组相同的标记。
