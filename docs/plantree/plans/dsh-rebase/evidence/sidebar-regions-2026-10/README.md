### 改了什么

- **标题新样式**（默认）。v3 样式留作对照。
  - 字号 26px（提议的 `--text-display` 由 28px 改为 26px），行高 1.3，字距 −0.01em。
  - 句子 400，次级色 `--muted-foreground`；只有仓库名 600、正文色 `--foreground`，最长 14em 截断。
  - 不加图标、不用品牌色、不加下划线。
  - 没选仓库时，句子「与 PiLab 一起进行创造吧」里强调的是 PiLab；说明文案沿用 v3。
- **标题位置**：标题中心放在输入框以上区域高度的 38.2%（黄金分割，默认）或 50%（居中）。
  - 纯 CSS：这块区域设为尺寸容器（`container-type: size`），顶部留白 = 锚点 − 半个标题行高，用 `cqh` 单位，不需要脚本。
- **最近对话**：
  - 5 条 +「查看更多（N）」，在标题下 40px；
  - 段头降为 14px 400 灰色小标签（标题是锚点，列表是次要信息）；
  - 5 条时不分组，每行自带相对时间；点了查看更多后照 v2 分今天 / 昨天 / 更早。
- **放不下时**：
  - 最近对话离输入框不到 32px 时，整块上移，只压缩顶部留白；
  - 顶部留白压到 48px 还放不下，上区滚动。
  - 推算：1440×900 两种位置都放得下，不用上移；1280×720 两种位置会上移到同一处，标题中心约在上区 36%。
- **首页的分支**：选了只记下，发送时才切。分支菜单里，勾号是这次要用的分支，绿点是仓库当前的分支。
- **同仓库有对话在跑**：
  - 分支选择器锁住，显示分支 + 锁，悬停提示「<仓库> 有对话正在运行，结束后才能切换分支」；
  - 仍可在当前分支上发送。
- **先选了别的分支、发送前才出现锁**：不发送，在输入框上方出一条提示。
  - 形态用 coss `Alert` 的 warning 变体，与 `ModelMissingNotice` 同一位置（卡片上方 `mb-2`）、同一形态。
  - 文案「<仓库> 有对话正在运行，现在不能切到 <分支>」，两个按钮「改在 <当前分支> 上发送」「取消」。
  - 取消后消息留在输入框；输入框的位置不变（提示条往上长）。

**v4.1（用户：输入框太小气）**：输入框为空时最少 3 行（17px × 1.5 × 3 = 76.5px），卡片从 75.5px 加高到 126.5px（4 行时 152px）；首页和对话页同时变，发送后仍不跳；有内容时照旧长到 8 行上限；现状（dsh.8）一侧不受影响。工具条「输入框高度」：现状（dsh.8）/ **3 行** / 4 行（`composer=current|3|4`）。上区随之变矮，黄金分割位置由 CSS 自动重算：1440×900、3 行时，标题中心约在会话栏下 252px，5 条列表结束后离输入框约 103px，不挤（4 行时约 87px；居中在 3 行时会上移约 7px）。

### 为什么默认用黄金分割

- 1440×900 时，输入框以上的区域高约 710px。
  - **黄金分割**：标题中心在 271px，5 条最近对话结束后离输入框还有约 134px。整块落在中上部，上下留白都宽松。
  - **居中**：标题中心在 355px，列表结束时离输入框只剩约 50px。整块的重量压在下半部，挤着输入框。
- 只有标题的时候（新用户、没有仓库），38.2% 正好是视觉中心：输入框在下面还压着一块，标题放在几何正中反而显得低。
- 1280×720 时两种位置会退化到同一处，所以只在大窗口上有差别，而大窗口上是黄金分割更匀称。

### 落地增量（相对 v3）

- **`HomeView`**：标题分两段样式（句子 / 仓库名）；最近对话 5 条，段头用小标签，5 条时不分组；`--text-display` 改为 26px（`@theme`、tailwind-merge 注册照 v3）。
- **首页区域的锚定布局**：
  - 区域加 `@container`（尺寸容器）；
  - 顶部留白 `h-[calc(38.2cqh-半个标题行高)] shrink min-h-12`，标题与列表 `shrink-0`，底部 `grow min-h-8`；
  - Tailwind v4 自带容器查询单位。
- **分支改为发送时才切**：
  - 草稿目标加 `branch`；
  - `BranchColumn` 在首页上不调 `checkout.mutate`，只写草稿；
  - 发送握手在 `createSession` 之前 checkout；
  - 锁仍按 `resolveBranchLock`（`composerColumns.ts`）判断，首页上的锁文案换成「<仓库> 有对话正在运行，结束后才能切换分支」。
- **发送被锁拦下**：
  - 发送函数在建对话之前判断「有草稿分支 + 锁」：成立就不建、不发，显示提示条，文字留在草稿（`START_SCREEN_DRAFT_KEY`）；

- **提示条**：复用 coss `Alert`。按钮用 `Button size="xs"` + `sm:text-meta`，因为 `ModelMissingNotice` 自己的按钮是 12px 中文，可以一起提。
- **悬停提示**：coss `Tooltip` 是 `text-xs`（12px），中文提示要提到 14px。这是全局问题，不只这一处。
- **测试增量**：
  - 草稿分支：选了不 checkout、发送时 checkout、锁住时拦下；
  - 提示条的两个按钮；

### 现状核实（dsh.8 @ `6ca5bf42`，只读）

1. **工作栏有什么**（`chat/ComposerTargetBar.tsx`，三列）。
   - 仓库列分两种：
     - 开始屏（空白对话）是下拉 `TargetFolderSelect`。触发器是 `targetTriggerClass`（`middleColumnLayout.ts:580`）：`h-6 px-2 text-ui`，文件夹图标 + 名字（`max-w-40` 截断）+ `ChevronDown`；
     - 对话页换成只读的 `LockedRepoLabel`：文件夹 + 名字 + 锁，悬停写「当前对话已绑定该仓库 —— 要换仓库请新建对话」。
   - 分支列：`BranchColumn` → `BranchSwitcher size="xs"`。
     - 触发器 12px，`GitBranch` + 名字 + `ChevronsUpDown`；
     - 弹出层 `w-56`：搜索、「创建新分支...」、本地分支 / 远程分支。
   - 运行位置：`RunLocationIndicator`，只读，显示「本机」或连接名。
   - 卡片里的工具条（`ChatComposer.tsx:4225-4486`）：
     - 左边是附件「＋」、权限（盾牌 +「改动前确认」）；
     - 右边是模型（「自动」）和圆形发送钮；
     - 回合进行中，发送钮换成停止 + 加入队列。
   - 有两套几何（`middleColumnLayout.ts`）：
     - 开始屏 `empty`：工作栏是卡片**上方**的一块标签（`targetRowClass('empty')` = `mx-3 h-7 rounded-t-md bg-muted px-2`，`:783-788`），卡片顶角收成 4px，输入区 `min-h-14`，外层 `pb-6`；
     - 对话页 `session`：卡片在上（`min-h-18.5`），工作栏在卡片**下方**（`mt-2 h-6`），外层 `pb-3.5`。
   - 弹出层的方向：开始屏向下开，对话页向上开。
2. **空白对话发送前能不能改仓库 / 分支**。
   - **仓库能改。** 走 `useComposerTarget.selectTarget`（`useComposerTarget.ts:184-215`）→ `planTargetChange`（`composerTarget.ts:90`）：
     - 空白对话**原地改绑**（`retargetChatSession`，`chatSessionActions.ts:277`，不走 IPC）；
     - 有消息或已挂上宿主的对话不能改，会**另建一个对话**（fork）；
     - **没有当前对话时也是另建**。也就是说在 dsh.8 里，「选仓库」这一下本身就会建对话。
   - 下拉的内容（`buildFolderMenu`，`composerTarget.ts:297`）：
     - 只列各项目的主工作区；
     - 分组「最近」（有最近对话的前 5 个项目）/「本机」/「远程仓库」；
     - 底部是「使用已有目录… / 克隆… / 添加远程…」三个按钮（`TargetFolderSelect.tsx:148-226`），开着临时工作区设置时再多一个「新建文件夹」。
   - **分支也能改**，但它不是「这次对话用哪个分支」，而是立刻切换仓库的分支，见下一条。
3. **分支选择的语义**。
   - 选了就**立即在该仓库的工作目录执行 `git checkout`**（`BranchColumn.tsx:83` 的 `checkout.mutate({ workdir, branch })`），不会等到发送时再切。
   - 这个工作目录是仓库的主工作区，绑在主工作区上的对话全部共用它。
   - 有两把锁（`composerColumns.ts:157-221`），锁上时画一把锁并写明原因：
     - 当前对话正在运行或正在发送：`session-running`；
     - 同一目录下有别的对话在跑：`checkout-busy`。
   - **这两把锁挡不住的**：
     - 同一目录下闲着、但有历史的对话：它们的下一回合会在新分支上跑；
     - 别的对话正在发送握手：锁只看本输入框自己的 `sending`；
     - 主进程：没有对应的守卫；
     - Git 面板里的分支切换：不看这两把锁。
   - 对首页的影响：在「使用中」场景，nimbus-agent 有对话在跑，首页工作栏的分支是锁着的（44 号）。
4. **「新建对话 + 第一条消息」是怎么建出来的**。
   - 新建对话只是在渲染层的 store 里加一行（`createChatSessionOnWorkspace` / `createUnboundChatSession`，`chatSessionActions.ts:41` / `:138`），不落盘，也不调 IPC。
   - 第一次发送（`ChatComposer.tsx`）依次是：
     1. `activeSessionId ?? createUnboundChatSession()`（`:1826`）：**没有当前对话时只会建临时对话**；
     2. `chat.ensureHost`（`:2711`）；
     3. 没有目录时调 `ensureScratchWorkspace` 分配临时目录（`:2714-2725`）；
     4. `chat.createSession`（`:2426`），主进程先记会话索引；
     5. `chat.send`（`:2509`）；
     6. 用第一条消息自动起标题（`maybeApplyFirstMessageTitle`，`:1114-1128`，走重命名 IPC）。
   - **结论：「发送时才建对话」在结构上可行。** 建行本来就是同步的、只在渲染层，挪到发送的第一步即可。要补的是「建在工作栏选的仓库里」，现在这一步只会建临时对话。
   - **有一个坑**：工作目录取自渲染时的闭包。`:1847` 是 `let workspacePath = cwd ?? …`，`cwd` 是上一帧按当前对话算出来的。发送时现建一个绑定仓库的对话，`cwd` 仍是上一帧的空值，对话就会落到临时目录里。必须改成从草稿目标直接取路径。
   - 输入框草稿已经有「没有会话」的槽：`composerDrafts.ts:31-32` 的 `START_SCREEN_DRAFT_KEY`，首页直接用。权限触发器在没有会话时写「作用于新建的对话。」（`ComposerPermissionTrigger.tsx:205`）。
   - 首次发送失败时，会话行已经建好了，会留下一个空对话（今天也是这样）。
5. **启动时、没有当前对话时**。
   - 有三处会把「没有当前对话」补成「有」：
     - 树同步在没有会话时建一个启动种子（`useSyncChatWorkspaceTree.ts:189-193`）；
     - 当前对话取「该工作区里排在最前的会话」（`:212-213`、`:284-288`）；
     - `ChatWorkspace.tsx:240-249` 在当前对话为空或已删除时自动选一个。
   - 所以今天「没有当前对话」几乎到不了。首页要成为常驻状态，这三处都要改。
   - 另外，还没发出过的临时草稿会被树同步并进第一个添加的仓库（`:155-177`，U22 的行为）。
6. **没有仓库、或只有临时对话时，工作栏有什么**。
   - **什么都没有**：没有可用的工作区时整行不渲染（`shouldRenderTargetRow`，`middleColumnLayout.ts:831`；`ComposerTargetBar` 在它为假时直接 `return null`）。
     - 于是没有仓库下拉，也就没有从输入框添加仓库的路；添加仓库只能走侧栏的空状态卡片或工具条。
     - 这时打字发送，建的是临时对话。
   - 打开一个临时对话时同理，对话页也没有工作栏（没有分支、没有运行位置）。卡片比绑定仓库的对话靠下 32px。
   - 新建临时对话现有三个入口：
     - 「临时对话」区右键「新建临时对话」（`LeftNav.tsx:601`）；
     - 会话栏「＋」（当前是临时对话时，`SessionBar.tsx:128-135`）；
     - 工具条「新建」（没有可用工作区时）。
7. **「添加仓库」能不能放在仓库菜单最后**。已经在了：下拉底部那三个按钮就是添加仓库的三种方式（本地 / 克隆 / SSH，各自打开 `AddRepositoryDialog` 的对应标签）。缺的是三样：
   - 没有组名，看不出它们是「添加仓库」；
   - 它们是普通按钮，不在列表的键盘导航与搜索过滤里；
   - 没有仓库时整个下拉都不出现（见上一条）。
8. **开始屏 → 对话页时输入框会跳**（42 号 + 测量）。
   - dsh.8 的开始屏用 `empty` 几何，发出第一条后换成 `session` 几何。量出来：
     - 卡片顶边下移 6.5px；
     - 卡片高度从 104 缩到 75.5px；
     - 工作栏从卡片上方跳到下方，移了 118px。
   - v3 的首页一开始就用 `session` 几何，所以不跳（41 号）。

### 新 token：`--text-display`

- 取值：`1.75rem`（28px），行高 1.3，字重 600，字距 −0.01em，`font-heading`。只用在首页标题这一处。
- 为什么要新开一档：
  - 现有最大的 UI 字号是 `--text-title` 18px（设置页 L1、对话框标题），撑不起「显著」；
  - 24px 在 1116px 宽的中栏里仍然显小；
  - 28px 是首页标题常见的档，与聊天正文 17px 之比 1.65。
- 合不合规范：
  - 「Letter-spacing」表规定只有 ≥18px 的大标题才能用 −0.01em，28px 满足；
  - 字重只用 600；
  - 中文最小 14px 的规则不受影响。
- 落地时的强制动作：
  - `globals.css` 的 `@theme` 加 `--text-display: 1.75rem` 和 `--text-display--line-height: 1.3`；
  - `src/renderer/lib/utils.ts` 的 `extendTailwindMerge` 在 `font-size` 组里注册 `text-display`，否则 `cn('text-foreground', 'text-display')` 会把颜色吞掉；
  - `design-system.md` 的字号表加一行。同时改掉「`--text-title` 是唯一 >15px 的档」这句：它早就不对了，`--text-chat-body` 是 17px，v1 提议的 `--text-section` 是 16px。

### 输入框与工作栏

- **几何**：首页直接用对话页的 `session` 几何（卡片在上、工作栏在下、外层 `pb-3.5`），不用 dsh.8 开始屏的 `empty` 几何。量出来：

  - 1280×720：卡片在 (442, 598.5)，同样不变。
- **卡片**：同对话页。
  - 输入区占位「输入消息…」，17px；
  - 工具条：附件、权限「改动前确认」（悬停「作用于新建的对话。」）、模型「自动」、发送钮；
  - 不画用量条：首页还没有对话可计量。
- **工作栏**：
  - 首页：仓库下拉（**一直显示**；没有仓库时写「未选仓库」，图标变灰）、分支、运行位置；
  - 对话页：仓库锁标签、分支（回合进行中带锁）、运行位置；
  - **临时对话也画一个「临时对话」标签**（消息气泡图标）：工作栏不消失，卡片不会因此下移 32px。dsh.8 在这种情况下整行不渲染。
- **仓库菜单**（34、43 号）。
  - dsh.8 的分组「最近」/「本机」/「远程仓库」不变。
  - **列表最后加一项「不选仓库（临时对话）」**：有仓库时，这是从首页开临时对话的唯一入口。
  - 底部三个按钮上方加组名「添加仓库」。
  - 没有仓库时列表写「还没有仓库」；「未找到文件夹」留给搜索无结果。
  - 弹出层高度沿用 coss 的上限 `min(可用高度, 23rem)`（`combobox.tsx:181`）。1440×900 时是 368px，「最近」的 5 项之后要滚，底部渐隐提示还有内容。
- **分支菜单**（35 号）：同 dsh.8，搜索、「创建新分支...」、本地 / 远程分支，当前分支打勾 + 绿点。
- **12px 中文改成 14px**：dsh.8 这两个弹出层里有 12px 的中文。
  - 一处是 coss 的组名（`combobox.tsx:259`、`select.tsx:153`，都是 `text-xs`）：「最近」「本机」「远程仓库」「本地分支」「远程分支」；
  - 一处是「创建新分支...」（`BranchSwitcher.tsx:181`，`text-xs`）。
  - 原型里都提到 14px（`text-meta`），组名字重 400。
  - 分支触发器本身仍是 12px（`text-xs`），因为分支名是拉丁字母。只有读不到当前分支时，它会显示一句 12px 的中文「选择分支...」，建议一起提到 14px。
- **当前分支的绿点**：dsh.8 写的是 `bg-green-500`（调色板原色），原型用 `bg-success`。落地时建议换成 token。

### 待用户拍板（v3，每点给推荐项）

1. **首页上的分支下拉是什么意思**。现在是选了就立刻 `git checkout`，同一仓库主工作区上的所有对话都会跟着换分支。
   - **推荐：在首页上改成「这次对话用哪个分支」，发送时再切。** 在发送握手里、`createSession` 之前执行 checkout；失败就停在首页并保留文字；切之前仍按现有的两把锁判断。
   - 备选：保持立即切换，在首页分支菜单顶部加一行说明「切换的是 {仓库} 的工作目录，同一仓库的其他对话会一起换分支」。
2. **首页默认选哪个仓库**。
   - **推荐「最近有活动的仓库」**，也就是仓库列表排序后的第一个，与 v2「新建对话」的目标一致。没有对话时取第一个仓库；没有仓库时是「未选仓库」。
   - 备选：沿用侧栏上次选中的仓库（`aiclient-selected-repo`）。
3. **「新建」和各处「＋」点了去哪**。
   - **推荐都回首页，并预选仓库**：
     - 工具条「新建」→ 首页，仓库按第 2 条；
     - 文件夹行「＋」、空文件夹的「新建对话」→ 首页，预选该文件夹；
     - 会话栏「＋」→ 首页，预选当前对话的仓库（当前是临时对话时用首页默认仓库）。
   - 这样「新建」只有一种样子，侧栏里不会再冒出空白的「新建对话」行。
   - 备选：文件夹「＋」保留「直接建一个空白对话」。
4. **从首页添加仓库之后**。**推荐自动选中新仓库**，标题随之变成新仓库的名字。
5. **标题样式**。
   - **推荐 28px 600，仓库名用品牌色 + 文件夹图标。**
   - 备选：24px；仓库名用正文色加粗；或把标题里的仓库名做成可点的，点了就打开工作栏的仓库菜单。
6. **没选仓库时的标题**。
   - **推荐「与 PiLab 一起进行创造吧」+ 一行说明**（见版式表）。
   - 备选：「在 临时目录 与 PiLab 一起进行创造吧」，保持句式不变。
7. **仓库菜单加「不选仓库（临时对话）」和组名「添加仓库」**。
   - **推荐都加**，并把底部按钮改成菜单项，进键盘导航；搜索时它们仍显示。
   - 不加的话，有仓库时首页开不了临时对话。
8. **临时对话的工作栏**。**推荐画「临时对话」标签**：工作栏不消失，所有对话的输入框高度一致。
9. **菜单里的 12px 中文**（组名、「创建新分支...」、「选择分支...」）。**推荐提到 14px**：这是设计规范的硬规则，与 #6 无关也该改。

1. **应用启动时中栏显示什么。**

### 侧栏「正在活动」

- 1440×900、7 个正在活动时，区高 216px（列表区的 30.3%）：5 行 +「查看更多（2）」全部放得下，不用滚。v1 的「最近」两段要 446px，到了 33% 上限后「48 小时内」只能滚着看，这个问题随「48 小时内」移到首页一起没了。

### 仓库按活动时间排序

- 规则如上表。原型数据的结果：nimbus-agent（now）→ beacon-api（6m）→ atlas-web（25m）→ quartz-search（2h）→ pylon-gateway（9h）→ … → yarrow-bot（4mo）→ zephyr-tools（没有对话）→ 临时工作区（固定最后）。27、28 号截图的品红标注逐个写了依据。

- 真实实现里，活动时间每来一条消息就会变，列表会跟着跳。所以**指针停在仓库列表区内时暂不重排，移出后再排**。原型是静态的，只画结果。建议键盘焦点在区内时也暂不重排，见「待用户拍板」第 8 条。

### 待用户拍板（v2，每点给推荐项）

1. **首页入口放哪**。**推荐 (a) 导轨最上方**：任何面板都能回首页，不挤 280 宽的工具条（(b) 在 280 宽时只剩 28px 余量）。代价是五个面板图标下移 45px。
2. **首页「新建对话」建在哪**。**推荐「最近活动的仓库」**，也就是仓库列表排序后的第一个，悬停提示写出名字。
   - 另两种：沿用侧栏「＋新建」的兜底规则，冷启动时是「添加最早的那个仓库」，与看到的顺序对不上；或一律建临时对话，到输入框的目标栏再选仓库。
3. **首页「最近对话」列哪些、几条**。**推荐列全部对话（含临时对话、含正在活动的），默认 10 条 +「查看更多」，展开后全部**。
   - 对话很多时可以改成每次多 20 条，或只列 30 天内。
4. **首页行的字号和颜色**。**推荐 15px 正文色**：首页的列表是主角，地方也够；侧栏的行是 14px 派生色，因为它在第三级。
   - 若要两处完全一致，可以改成 14px 派生色。
5. **「首页」就是「当前没有打开对话」**。**推荐这样建模**：点入口就是把当前对话设为空。正在跑的对话不受影响，仍在「正在活动」里，点一下就回去。
   - 另一种是另设一个「中栏显示首页」的开关，同时保留当前对话。它会多一个和当前对话不一致的状态，不推荐。
6. **「正在活动」的折叠状态记不记**。**推荐不记、默认展开**，与「临时对话」一致（内存状态），旧键 `aiclient-sidebar-recent-collapsed` 废弃。
   - 若沿用旧键，它的默认值是「折叠」：首次启动的人会看到一个收着的「正在活动」，而这个区正是要一眼看到的。
7. **启动时不再自动建空白「新建对话」**。**推荐不建**：首页取代它；启动时当前对话为空，就停在首页。
   - 要动：树同步里把 DEMO `session-live` 改名成种子那段（`useSyncChatWorkspaceTree.ts:195-207`），以及 `ChatWorkspace.tsx:240-249` 的「为空就自动选一个」。
8. **仓库重排的时机**。**推荐指针或键盘焦点在仓库列表区内时都不重排**，离开后再排，切换回窗口时也排一次。不然正在点的文件夹会从指针下面跑开。
9. **凭据选择屏 + 首页是先后两屏**。**推荐两屏都保留**：凭据选择屏是另一个裁决（2026-08-27「就是启动首屏，每次都出现」），不在 #6 范围。只提醒一下，用户说的「启动页」落地后是第二屏。
10. **在首页时入口按钮要不要显示按下态**。**推荐不显示**，理由见「回到首页的入口」。

### 窗口高度怎么换算成列表区高度

百分比的基准是「列表区」：搜索框下面、页脚上面那一块，也就是 dsh.8 里那个 `ScrollArea` 占的高度。照真实代码从上往下数（Windows / Linux 是无边框窗口，窗口高 = 网页内容高）：

| 从上到下 | 代码 | 高度 |
|---|---|---|
| 窗口标题栏 | `WindowTitleBar`：`h-8` + `border-b`（边框算在 32 里） | 32 |
| 面板标题「聊天」 | `LeftDock` 的 `DockTitle`：`h-9` + `border-b` | 36 |
| 工具条 + 搜索框 | `LeftNav` 顶部：`p-2` + 按钮行 `h-6` + `space-y-2` + 搜索框 `h-7` + `p-2` + `border-b` = 8 + 24 + 8 + 28 + 8 + 1 | 77（实测 77.25） |
| **列表区** | dsh.8 的 `ScrollArea`；方案里的三个区 | **窗口高 − 186** |
| 页脚 | `UserFooterPill`：`border-t` + `p-2` + `h-6` | 41 |

工具条实测 77.25：搜索框 `InputGroup` 是 `inline-flex`，所在行盒带 0.25px 的基线余量；真实应用是同一个写法，Windows 字体下可能略有不同。

| 窗口 | 列表区 | 「最近」上限 33% | 「临时对话」上限 25% | 「仓库列表」至少（42%） |
|---|---|---|---|---|
| 1280×720 | 534（实测 533.75） | 176.1 | 133.4 | 224.2 |
| 1440×900 | 714（实测 713.75） | 235.5 | 178.4 | 299.8 |
| 1920×1080 | 894（实测 893.75） | 294.9 | 223.4 | 375.4 |

几种会让列表区变矮或变高的情况：

- **窗口最大化**时要减去任务栏：Windows 11 任务栏 48px，1920×1080 屏幕最大化后窗口是 1920×1032，列表区 846。
- **系统缩放**按 CSS 像素算：1920×1080 屏幕开 125% 缩放是 1536×864（列表区 678），开 150% 是 1280×720（列表区 534，正好是 720 档）。不少 Windows 笔记本默认 125% / 150%，**720 档并不罕见**。

- macOS 没有自定义标题栏，多 32px；macOS 暂不在范围内（决策 090）。

### 新 token

#### `--text-section`：16px 字号档

- 取值 `1rem`（16px），行高 `--text-section--line-height: 1.5`（与 `--text-meta` / `--text-ui` 一致）。用在 L0 面板标题、L1 板块标题、会话栏标题，工具类 `text-section`。
- **名字**：落在 Tailwind v4 的 `--text-*` 字号命名空间里，生成的是字号工具类 `text-section`；仓库里没有同名的颜色或别的类（已搜过 `src/` 与 `design-system.md`），不冲突。取「section」是因为主要用户是板块标题；L0「聊天」与会话栏标题和它同档。没取的名字：`text-heading`（与 `--font-heading` 和 Markdown 标题混）、`text-base`（Tailwind 自带的 16px，`button` / `input` / `badge` 原语的移动端尺寸在用，语义会缠在一起）、`text-subtitle`（与 18px 的 `text-title` 关系说不清）。
- **强制动作**：`globals.css` 的 `@theme` 里加 `--text-section` 与 `--text-section--line-height`；**同时**把 `text-section` 注册进 `src/renderer/lib/utils.ts` 的 tailwind-merge `font-size` 组——不注册的话 `cn('text-foreground', 'text-section')` 会把它当颜色，静默吞掉前面的颜色类（design-system :475 的工程注记）。

#### `--foreground-soft`：对话标题的颜色

**名字**：`--foreground-soft`，工具类 `text-foreground-soft`。不叫 `--text-*`（那是字号命名空间，Tailwind 会生成字号类）；也不叫 `*-foreground`——按 shadcn 的约定 `X-foreground` 是「`bg-X` 实底上的字」，`--subtle-foreground` 之类会被读成「某个 subtle 底上的反色」，正撞上 design-system「`*-foreground` 只配实底」那一条。`soft` 在仓库里没有别的用法；`subtle` 已经被 Flexoki 的 `surface.subtle`（= `--secondary`）占了。不带 alpha（Alpha 纪律），不许加 `/N`。

**取值**（候选全部是 Flexoki 原色；`foreground` 与 `muted-foreground` 之间，暗色只有 base-300 一档）：

| 候选 | 亮 | 暗 | OKLCH（亮 / 暗） |
|---|---|---|---|
| **A 派工建议（原型默认）** | base-800 `#403E3C` | base-300 `#B7B5AC` | `oklch(0.3651 0.0044 67.69)`（与暗色 `--input` 同值）/ `oklch(0.7721 0.0128 96.47)` |
| **B 备选（我更倾向）** | base-850 `#343331` | base-300 `#B7B5AC` | `oklch(0.3214 0.0038 84.58)` / 同上 |
| B 的派生写法 | `color-mix(in oklab, var(--foreground) 50%, var(--muted-foreground))`，渲染出来亮 `#31302F`、暗 `#B6B5AC`，与 B 的色差 ΔE 亮 0.012、暗 0.001（看不出来） | | 写法同 `--tool-arg`，只在 `:root` 声明一次 |

对比度（WCAG 2.x）。「面板」是聊天面板真实的合成底：`bg-background` 上叠 `LeftDock` 根的 `bg-card/40`（亮 `#FBFAF1`，暗 `#1D1B1B`）；悬停行是 `bg-hover`，选中行是 `bg-selection`（选中行用正文色，列出来只作参考）：

| 文字色 | background | 面板（card/40 合成） | card | hover | selection |
|---|---|---|---|---|---|
| 亮 foreground `#100F0F` | 18.78 | 18.27 | 17.50 | 15.88 | 14.62 |
| 亮 **B** base-850 `#343331` | 12.39 | 12.05 | 11.54 | 10.47 | 9.64 |
| 亮 **A** base-800 `#403E3C` | 10.45 | 10.16 | 9.74 | 8.83 | 8.13 |
| 亮 muted-foreground `#575653` | 7.20 | 7.01 | 6.71 | 6.09 | 5.61 |
| 暗 foreground `#CECDC3` | 11.39 | 10.73 | 9.67 | 8.45 | 7.83 |
| 暗 **A / B** base-300 `#B7B5AC` | 8.85 | 8.34 | 7.52 | 6.57 | 6.09 |
| 暗 muted-foreground `#9F9D96` | 6.70 | 6.32 | 5.69 | 4.97 | 4.61 |

全部高于 4.5:1；亮色两个候选在所有底上都过 7:1（AAA）。

色差（OKLab ΔE，design-system 的可辨阈约 0.02；L 是 OKLab 明度）：

| | foreground → 新颜色（L2 与 L3） | 新颜色 → muted-foreground（L3 与 L4） | 新颜色的 L（两者中点） |
|---|---|---|---|
| 亮 A base-800 | 0.196 | 0.088 | 0.365（中点 0.311） |
| 亮 B base-850 | 0.152 | 0.132 | 0.321（中点 0.311） |
| 暗 base-300 | 0.074 | 0.077 | 0.772（中点 0.771） |

**为什么倾向 B**：

1. 「取在两者之间」：暗色 base-300 正好在 `foreground` 与 `muted-foreground` 的明度中点；亮色 B 也在中点附近，A 则偏向 `muted-foreground`（离正文 0.196、离灰字只有 0.088）。B 让两套主题的层级关系一致。
2. 对话标题与 L4 辅助文字现在**同为 14px**（中文最小 14px），同一行里标题和时间、分支文字只靠颜色区分（见待确认第 3 条）。A 在亮色下这一步只有 0.088，B 是 0.132。
3. B 可以写成派生式，`sync-terminal` 主题下自动跟着终端配色走：`lib/ghosttyTheme.ts` 会把 `--foreground`、`--muted-foreground` 改写在 `documentElement` 上，写死的 Flexoki 值不跟——终端是深色、而 `syncDarkMode` 关闭（不随终端切换 `.dark`）时，写死的亮色 `#403E3C` / `#343331` 会落在终端的深色底上，几乎看不见。派生式没有这个问题（原理同 `--tool-arg`）。A 不对称，没法用一个混合比例同时得到两边的值。

A 的好处是标题与文件夹名的差别更明显（0.196 对 0.152）。**截图 02（A）、17（B）、16（正文色）是同一画面，可以直接对照；浏览器里用「对话标题颜色」切换。**

**强制动作**：`:root` 与 `.dark` 里声明（派生式只在 `:root` 声明一次）；`@theme` 里补 `--color-foreground-soft: var(--foreground-soft)`，否则 Tailwind v4 不生成 `text-foreground-soft`；design-system 的 Theme Variables 表加一行，「逐 token 的 `/N` 许可」表加一行（❌）。它是颜色，**不要**注册进 tailwind-merge 的 `font-size` 组。

### 落地到真实代码时的要点

#### 结构（`LeftNav.tsx`）

`<ScrollArea>` 那一个滚动区换成一个纵向 flex，里面三个区；每个区是「标题 + 自己的 `ScrollArea`」的两行 grid：

```tsx
<div className="flex min-h-0 flex-1 flex-col">
  {/* Recent: content-sized, capped at 33% of the list area */}
  <section className="grid max-h-[33%] min-h-0 shrink-0 grid-cols-1 grid-rows-[auto_minmax(0,1fr)]">
    <SidebarSectionHeader title={t('Recent')}>{/* chevron */}</SidebarSectionHeader>
    <ScrollArea>
      <div className="px-2 pt-0.5 pb-2">{/* the two segments */}</div>
    </ScrollArea>
  </section>
  {/* Repositories: the rest (the partition's context menu renders AS this section) */}
  <section className="grid min-h-0 flex-1 grid-cols-1 grid-rows-[auto_minmax(0,1fr)] border-t">…</section>
  {/* Temporary chats: content-sized, capped at 25% */}
  <section className="grid max-h-[25%] min-h-0 shrink-0 grid-cols-1 grid-rows-[auto_minmax(0,1fr)] border-t">…</section>
</div>
```

- **`ScrollArea` 原语不用改**（`ui/scroll-area.tsx` 已读）。它的根是 `size-full min-h-0`（`height: 100%`），视口是 `h-full`，base-ui 给视口内联 `overflow: scroll`，滚动条与角是 `position: absolute`，不占 grid 格子；根前面那个隐藏原生滚动条的 `<style>` 带 `href` + `precedence`，React 19 会把它提到 `<head>`。根放在 grid 的第二行：内容不到上限时，`1fr` 行按内容的 max-content 定高；超过 `max-h-[33%]` 时，grid 按 CSS Grid 规范把上限当作确定高度重新分配，第二行等于「上限 − 标题」，根的 `height: 100%` 就解析成这个确定值，视口跟着变成定高、开始滚。原型就是用同一套 CSS 在 Chromium 里验证的（`regions` 判据）。
- **`grid-cols-1` 是承重的**（原型第一次跑就踩到）：不写的话隐式列是 `auto`，会被行里不换行的标题撑到 min-content 宽度，280 宽时标题被量成 306px、整行冲出面板右边。`grid-cols-1` 是 `repeat(1, minmax(0, 1fr))`，列宽钉在面板宽度。
- **不要改用 flex 做区**：区若是 `flex flex-col max-h-[33%]`，区本身高度不确定，`ScrollArea` 根的 `height: 100%` 解析不出来，视口退回内容高度、不会滚，除非再用 `*:data-[slot=scroll-area-viewport]:…` 去改视口的类。
- **百分比要能解析**：`max-h-[33%]` 相对的是列表区的高度，它确定的前提是 `aside`（`flex h-full flex-col`，在 `LeftDock` 的 `absolute inset-0` 层里）→ 列表区（`flex-1 min-h-0`）这条链上没有按内容定高的容器。别在列表区外面再包一层不定高的 div。
- 33% 也可以写成 Tailwind 的分数类 `max-h-1/3`（33.33%，1080 高时比 33% 多 3px）；25% 可以写 `max-h-1/4`。
- 板块标题去掉吸顶：`SidebarSectionHeader` 只剩 `flex h-8 items-center px-4` 一层，删 `sticky top-0 z-10 -mx-2 bg-background in-[.bg-image-enabled]:static` 与内层 `bg-card/40`；列表根的 `isolate p-2`、`ScrollArea` 根上的 `*:data-[slot=scroll-area-viewport]:scroll-pt-8`、`sidebarSectionClass` 一并删除。原来的 `p-2` 改成每个区滚动内容上的 `px-2`（另加 `pt-0.5 pb-2`），横坐标不变。
- 右键菜单照旧：「仓库列表」与「临时对话」的 `ContextMenuPrimitive.Trigger render={<section … />}` 直接渲染成这个 grid 区，菜单覆盖标题和区内空白。
- 没有仓库时的空状态分支（`showAddRepositoryEmptyState`）：引导卡片放进一个 `flex-1` 的区（同样「两行 grid + `ScrollArea`」或单个 `ScrollArea`），「临时对话」区照常在底部。
- 每个区的视口在溢出时都可聚焦（base-ui 给 `tabIndex=0`），Tab 会依次落到三个视口上，焦点环沿用原语的 `focus-visible:ring-2`。
