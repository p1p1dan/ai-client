## 5. 工作规则（旧机器上的长期记忆带不过来，这里是要点）

- **只用本地假网关** `src/dsh-host/tools/fake-gateway.mjs`：
  - 禁止调用公司网关、vllmproxy、maxapi、cx2 以及任何私人渠道；
  - 派给代理的提示词里要写明这份禁用清单，并让它在网关不可用时停下来报告，不许自己换渠道。
- **凭据与数据**：不读、不打印真实凭据；不读真实用户数据（`~/.pilab/*`、`~/.pi`）。
- **杀进程**：只按确切 pid 或用 `child.kill`，禁止 `pkill -f`、`kill(-1)`、负 pid；测试里要 mock `process.kill`。
- **跑冒烟或宿主脚本**：命令行里不能带 `vitest` 字样，探针扫进程时看到它会一直等。
- **测试范围**：不跑全量 vitest，只跑相关文件；全量留到一批收口时跑一次。
- **金样本**：只在收口时由编排者重录（`bridge-record.ts --update`），代理不许自己重录。
- **提交**：
  - 用 Conventional Commits，描述写中文，末尾加 `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`；
  - 代码注释用英文；
  - 多个代理并行时按文件范围分开提交，用 `git commit -- <paths>`。
- **编排方式**：
  - 编排者自己不写业务代码，派给代理；简单任务用 sonnet，复杂任务用 opus；
  - 同时跑测试的代理不超过 2 个，同时在跑的代理不超过 3～4 个（旧机器 2 核、3.3 GB 内存；新机器可以按配置放宽）；
  - 代理交回后，编排者先复跑验证再提交；
  - 代理撞到额度上限时，用 SendMessage 让原代理续跑，并说明磁盘上已有哪些半成品。
- **公开仓库**：
  - 加密机的原始报告和机器信息不入库，只放脱敏摘要；
  - 仓库不改成私有，因为已装的 1.0.x 从公开 Release 自动更新。
- **路径**：worktree 里的操作用 `git -C`，不要裸 `cd`。
