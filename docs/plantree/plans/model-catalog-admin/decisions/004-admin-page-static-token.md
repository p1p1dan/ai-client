# D04 — 管理页用静态环境变量口令登录

- **日期**：2026-09-05
- **状态**：Active
- **拍板人**：用户（三选一里选「一个静态口令（环境变量）」）
- **答复**：[Q03](../open-questions.md)

## 背景

onboard 没有任何管理员鉴权：`ONBOARDING_SECRET` 是给遗留 `/register` 用的，
`CCH_ADMIN_TOKEN` 是调 cch 时的凭据，两者都不是管理员身份。

## 决定

**新增一个环境变量口令（如 `MODEL_ADMIN_TOKEN`），管理页与管理端点都用它鉴权。**

- 比较用 `timingSafeEqual`，复用 `src/auth.ts` 里 `verifyOnboardingSecret` 的写法。
- 未配置该变量时管理页与管理端点整体不可用（fail closed），不能退化成免鉴权。
- 客户端端点不受影响，它按 [D01](./001-authenticated-catalog-fetch.md) 用登录 key 做 Bearer。

被否掉的两条：复用邮箱验证码 + 管理员白名单（要多写会话）、独立管理员账号表（要多写一整套账号逻辑）。

## 已知代价：记不了「谁」

口令是共享的，没有个人身份。因此操作留痕只能记
**时间、改了哪个渠道/模型、改前改后值、来源 IP**，记不了操作人。
若日后需要追责到人，得换成带身份的登录方式，届时另立决策替代本条。

口令泄露后唯一的处置手段是改环境变量并重启，没有单条吊销。
