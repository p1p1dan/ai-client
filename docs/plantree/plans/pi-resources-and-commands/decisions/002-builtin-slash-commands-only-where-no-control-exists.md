# D02 — 内置斜杠命令只做「界面上没有控件」的那几条

**日期**：2026-09-06
**拍板人**：用户
**触发**：我提了五条内置命令（`new` / `model` / `settings` / `permission` / `archive`），
用户反问：「应该只用 new settings archive compact 吧？permission 不是有按钮么」。

## 决定

内置斜杠命令**四条**：`/new`、`/settings`、`/archive`、`/compact`。

砍掉 `/permission` 和 `/model`。

## 判据：有控件的不该有第二个入口

用户的反问点破了我列表的毛病——我是照着 pix 那 15 条抄的，
但 pix 没有权限档控件，而**我们的底栏两个控件都在**。

对这两件事，打命令还不如点按钮：选档位要看清选项和说明，
而命令行式的输入把「看清楚再选」变成了「记住名字再打」。

留下的四条都满足：**界面上没有等价控件，或者那个动作藏在菜单深处**。

## 反馈形式

用户同时问了「这个 settings 指令怎么反馈呢」。分两类：

| 命令 | 反馈 |
|---|---|
| `/new`、`/settings`、`/archive` | **界面变化本身就是反馈** |
| `/compact` | 时间线系统提示 |
| 命令不认识 | toast |

**打开面板/新建会话这类不在聊天流里留痕。** 输入框清空了、面板打开了、
新会话出现了——再写一条「已打开设置」是噪音，而且它会永久留在对话记录里。

**`/compact` 必须留痕**，因为它改变了对话历史，用户事后必须能看出哪里被压缩了。
而这条**不用新写显示端**：`src/agent-host/piSessionTimeline.ts:116` 已经把
`entry.type === 'compaction'` 转成系统提示，pi 压缩完自己会写那条记录。

## 不抢插件的命令名

拦截前先查目录里这个名字属于谁，照 pix 的 `resolveBuiltinSlash` 开头：

```ts
if (source && source !== 'builtin') return { type: 'runtime', command: name, args };
```

如果 pi 那边真有插件注册了 `new`，就不拦，原样交给 pi。
**没有这一行，客户端会悄无声息地抢掉插件的命令名**，而插件作者和用户都不会知道为什么。

## 不为凑齐命令表去补功能

pix 有 15 条，我们只接已有界面动作的。
`/fork`、`/export`、`/import`、`/share` 都没有对应功能——
为了让命令表好看去补功能，是让命令表决定产品范围，顺序反了。

`/compact` 是唯一一条需要新加接口的（一条 RPC 到 `session.compact()`），
用户明确要了它，而且 SDK 侧和显示端都现成。
