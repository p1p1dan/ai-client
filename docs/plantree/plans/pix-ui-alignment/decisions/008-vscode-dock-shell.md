# D08 — VSCode 式壳层：左栏是导航容器，中栏是会话 Tab，右栏只做文件

- **日期**：2026-09-05
- **状态**：Active
- **拍板人**：用户（三轮原型迭代后拍板：「就目前这样，很好。直接按照 html 这个样式开改」）
- **对齐基准**：[`docs/design/a11-vscode-shell-prototype.html`](../../../../design/a11-vscode-shell-prototype.html)
- **推翻**：[D02](./002-layout-cwd-and-evidence-scope.md) 决定一（残余）、[D05](./005-two-column-run-surface.md)（连带失效）、
  [D07](./007-two-column-is-two-columns-and-one-bar-per-column.md) 决定一与决定三

## 背景：左栏用得最少，却占着最贵的常驻位置

用户的原话是「左侧栏目用户在整个使用过程中不会频繁用到」。改前的三列分工是：

| 列 | 装了什么 | 用户使用频率 |
|---|---|---|
| 左 | 会话树（仓库 → 会话） | 低——选中一个会话之后整天不用再动 |
| 中 | 聊天 | 全程 |
| 右 | Git / 文件 / 上下文 / 运行 四个 tab | 中——看改动、翻文件、查占用 |

低频内容常驻一整列，中频内容挤在一列里靠 tab 轮换。VSCode 的解法是把**所有导航**收进
一个可切换的左侧容器，主区域只留正在做的事。本决定采用这个分工。

## 决定一：左栏 = 图标轨道 + 面板，五个入口

**采纳**：左栏变成 `44px 纯图标轨道 + 面板` 的容器。轨道从上到下是
`聊天 · Git · 文件 · 上下文 · 运行`，底部是 `插件 · 设置`。
面板顶部一行 h-9 标题说明当前在哪个区（VSCode 的 `EXPLORER` / `SOURCE CONTROL` 那一行）。

- **原右栏的四个 surface（`git` / `editor` / `context` / `run`）整体迁到左栏**，
  不再由右栏承载。
- **原左栏的全部内容（会话树 + 搜索 + 新建/添加仓库）收成 `chat` 一个 surface**，
  与其余四个平级。
- **`chat` 这个注册表 id 被复用**，语义从「分屏聊天会话（后置）」改为「会话列表」。
  不新开 id 是因为 `railOrder` / `lastSurfaceId` 已经持久化了这个字符串，新开一个
  等于既要迁移又要留个死 id。

**轨道用纯图标，不带文字。** 中间试过图标下挂中文标签（60px 轨道），用户看过后判定
「不行好丑」，退回原版 VSCode 形态。纯图标可读性由两件事兜底：悬停 tooltip，
以及面板顶部那行标题——**这也是标题行必须保留的原因**，它不是装饰。

**左栏的横条因此回来了。** D07 决定二当时留下左栏那条 h-9（只装一个折叠按钮）的理由是
「删掉会让左栏比中右起始位置更高，反而更不齐」。现在这条横条有了真实内容（区名 + 摘要），
三列齐平这一条继续成立。用户中途要求过去掉标题行，看到效果后自己退回。

## 决定二：右栏只做文件与编辑器

**采纳**：右栏不再是「上下文面板」，只承载文件浏览与文件编辑器，保留展开覆盖能力。

- `ContextPanel` 作为「装 surface 的右列」这一身份**退役**；它的三样能力
  （tab 条 / 多挂载保活栈 / 展开覆盖）分别转移：tab 条与保活栈跟着 surface 去左栏，
  展开覆盖跟着文件去右栏。
- 右栏没有文件打开时**不渲染**（沿用 D07 决定一对 0 宽盒子的判断：
  `visible={false}` 的盒子仍会用 `border-l` 画出一条 1px 的假列）。

## 决定三：一个已启动的会话 = 中栏一个 Tab

**采纳**：左栏「聊天」里点一行不再是「把中栏切到那个会话」，而是**启动**它；
可以同时启动多个，中栏顶部一条横向 Tab 负责切换。

- **打开态是新的一份 UI 状态**，与 `chatSessions` 的 `sessions`（认识哪些会话）
  和 `activeSessionId`（正在看哪个）都不是一回事。
- **单向依赖**：`activeSessionId` 变化时保证它在 Tab 列表里，反过来不成立
  （关掉一个 Tab 不等于关掉那个会话）。这样既有的 `selectSession` 调用点
  （新建会话、resume、侧栏点击）一处都不用改就能自动开 Tab。
- **关 Tab ≠ 归档/关闭会话**。会话仍在左栏列表里，重新点开即可。
  归档与关闭仍走 `chat:archiveSession` / `chat:closeSession` 两个既有入口。
- **左栏列表要标出打开态**，否则「点击=启动」的语义会让用户重复点。
  实心点 = 正在跑，空心圈 = 已启动，无标记 = 未启动。

## 决定四：删掉双栏/三栏模式

**采纳**：`shellColumnMode` 整个字段、它的开关按钮、以及「上下文面板」开关按钮全部删除。

**理由**：这个开关存在的意义是「要不要那第三列」。现在第三列的内容已经迁进左栏容器，
右栏是否出现由「有没有打开文件」决定，没有第二种布局形态可选了。
D07 决定三（GUI/TUI 与列数是两个独立控件）随之作废——列数控件不存在了，
只剩 GUI/TUI 一个，移到会话 Tab 条右端。

**明示代价**：
- U02（双栏/三栏模式开关）这一片**整体作废**，它落的 `shellColumnMode`、
  `reduceColumnModeChange`、`isSurfaceAvailableInColumnMode`、`columnModeHasPanel`
  一并删除。这是本计划第一次删掉一片已验收的功能，原因是上层布局形态被推翻，不是它做错了。
- 持久化过 `shellColumnMode` / 老 `railOrder` 的用户档需要一次 store 版本迁移
  （v2 → v3），否则老的 `railOrder` 会把 `chat` 排到最后一个。

## 决定五：上下文页要有图形，且默认不展开长列表

用户原话：「上下文页面不是应该有个上下文图形展示么。对话构成需要默认折叠，
不然用户超长上下文，我担心这个页面展开后会爆炸，或者限制展示条数」。

**采纳两条**：
1. 加占用图形——环形（总占比）+ 堆叠条（分项构成），不是纯数字表格。
2. 「对话构成」**默认折叠**，展开后**限制条数**（默认前若干条 + 「显示更多」）。
   两条同时做，因为折叠只挡第一眼，展开之后照样会爆。

**边界不变**：数据源仍是本窗口已加载的消息（U07 确立），措辞继续点明这一点。
真实 token 占用仍等 Pi 计划 T38，本片不因为「画了个环」就把字符数印成 token 数。
