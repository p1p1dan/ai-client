# D14 — 起始屏是一个能用的输入框，不是一组说明

**日期**：2026-09-06
**拍板人**：用户（对照 pix 截图后提出）
**触发**：两句话。一是「这个直接开聊按钮有啥用？」，二是
「你不觉得他这个页面很清爽么，我们现在的页面看起来太臃肿浮夸了」。
基准截图：`sharePic/20260906/pix-desktop.png`。

## 推翻了什么

**U22 的落地形态**（同一天早些时候落地）。U22 找到的根因是对的——
`canSend` 要求先有会话，而全新安装的用户四个入口全是死的。
但它的修法是**在欢迎卡上加一个「直接开聊」按钮**去补那个入口，
而不是去掉那道闸。

这个按钮还带着一个崩溃：`onClick={onStartTemporaryChat}` 把 React 的鼠标事件
对象当成了 `createUnboundChatSession(title)` 的标题参数，会话标题因此是一个对象，
渲染时抛 `Objects are not valid as a React child`。**用户点第一下就炸了。**

崩溃是表面。真正的问题是：**加按钮这件事本身就说明闸没拆干净。**

## pix 的答案

pix 的起始屏只有三样东西：一个标记、一行「开始对话」、一句
「直接输入即可，无需绑定项目」。下面是一个**可以直接打字的输入框**，
带完整的底栏（附件、权限档、模型、发送）。「选择项目」是输入框上方的一个小顶盖。

它没有「开始聊天」按钮，因为不需要——打字就是开始。

对照我们当时的屏幕：一个「选择工作目录」大按钮（功能与输入框顶盖重复）、
一段解释用户没问过的选择的说明文字、一个会崩溃的按钮，
外加一个**禁用的**输入框。指令写了三行，能用的东西一个没有。

## 决定

### 决定一 — 发送即创建会话

`runSend` 里 `const sessionId = activeSessionId ?? createUnboundChatSession()`。
没有选中会话时，这一次发送就是创建它的动作。

连带拆掉三处旧闸：`canSend` / `hasSendTarget` 不再要求 `activeSessionId`；
附件粘贴不再因无会话而锁定；`ChatWorkspace` 不再给 composer 传
`disabled={!activeSessionId}`。

### 决定二 — 「没有会话」不再是故障

`deriveChatEmptySurface` 删掉 `!hasSession → 'error-notice'` 分支，
`hasSession` 整个字段退出该函数的输入。
`composerPlaceholder` 删掉「Select a session in the left nav before sending…」。

这两处旧写法在「会话是发送的前提」时是诚实的。前提没了之后，
它们变成了**应用把自己的起始状态标成红色故障**——正是 T12-e 当初要修的那种
「一打开就像坏了」。

### 决定三 — 起始屏收敛为一行标题加一句话，并用于每一次开始

删掉卡片上的目录选择菜单与全部引导段落，只留标记、标题、一句副文案。
选目录交给 composer 自己的顶盖（`ComposerTargetBar`，U09-1 已经做成 pix 那种接合形态），
添加仓库交给左栏。

**适用范围从「没有仓库时」扩大到「每一次对话开始时」**（用户 2026-09-06 追加）：
一个已绑定目录、但还没发过消息的会话，和一个免绑定会话处在同一个时刻——
空的时间线，空的输入框。差别只在那句副文案：

- 有目录：**「AI 会在 <目录名> 里干活，直接说你想做什么。」**
- 无目录：**「直接输入即可，这次对话会在一个私有的临时目录里进行。」**

## 未采纳的两个写法

- **「Hey <用户名>，让我们开始吧」**（用户举的例子，他自己说了是随口示意）。
  未登录、或账号没有可显示的名字时，这句话要么退化成「Hey ,」，
  要么需要第二套文案——一句问候换两条分支不划算。标题固定「开始对话」，
  把会变的部分留在副文案里，那里本来就要变。
- **保留按钮但修掉崩溃**（`() => createUnboundChatSession()`）。
  这能让它不炸，但按钮存在的理由——输入框是禁用的——已经被决定一消掉了。
  修好一个不该存在的控件，是把这次反馈当成了 bug 报告而不是设计意见。

## 已知未对齐处

**底栏控件在没有会话时不渲染**：权限档 chip、模型/思考档、占用 chip 三个槽位
都以 `activeSessionId` 为条件，pix 的对应位置是有的。
这意味着第一条消息只能用默认模型发出，用户无法预选。

不在本决定范围内：这三个控件的读写都以 sessionId 为键，
让它们在无会话时可用，等于要决定「此时改的是全局默认，还是下一个会话的暂存值」——
那是一个独立的取舍。记为 open question。
