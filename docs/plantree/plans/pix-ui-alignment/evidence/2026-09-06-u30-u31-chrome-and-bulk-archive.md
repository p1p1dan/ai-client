## 一、U30-a 权限菜单选完不关

`MenuPrimitive.RadioItem` **按设计不关闭菜单**——radio 的语义是「在这几个之间反复切」，
这对筛选器是对的，对这里是错的：选档位是一次决定，菜单留在原地读起来像「没生效」。

`<Menu>` 原本是非受控的，所以没有程序化关闭的手柄。改为受控（`open` / `setOpen`），
**只在 `applyTier` 里关**——不是在 `handleSelect` 里。这个位置是承重的：
选「完全放开」时 `handleSelect` 只是进入确认态，此时菜单必须留着；
真正应用（普通档位直接、危险档位经确认）才关。两条都有断言。

## 二、U30-b 模型控件让底栏「动来动去」

触发器宽度就是它的内容（模型名 + 思考档后缀），而它在底栏的 `ms-auto` 尾部组里——
**右边缘被钉住，左边缘随标签浮动**。于是：

1. 菜单原本 `align="start"`，锚在那条会动的左边缘上，`Automatic` 与
   `GPT-5.6 Terra High` 之间切换时整个弹层横跳；菜单开着时改选一次，它在眼皮底下又跳一次。
2. 触发器自己也在左右伸缩。

两处都改：菜单改 `align="end"`（挂在被钉住的那条边上）；
触发器加 `max-w-56`，模型名加 `min-w-0 truncate`——
`min-w-0` 是让 `truncate` 在 flex 行里真正生效的那一半（flex item 默认
`min-width: auto`，不肯缩到内容以下）。思考档后缀**不截断**：它是短的那半，也是变得最勤的那半。

## 三、U30-c 权限审批卡的选项「重叠」

截图里第一个选项框和第二个叠在一起。**不是错位，是焦点光环吃掉了间距**：

`Button` 的焦点态是 `focus-visible:ring-2` + `ring-offset-1`，
用 box-shadow 画在盒子**外面 3px**，且**不占布局**。而选项列表是 `gap-1`（4px）。
第一项带 `autoFocus`，所以每次弹出必现——3px 的光环伸进 4px 的缝里，两者就贴上了。

`gap-1` → `gap-2`（8px）。没有动光环本身：那是全仓按钮的统一焦点语言。

## 四、U31 批量归档

**存储层**：`useSessionIndexMutations` 新增 `archiveMany(ids)`。
每条用 no-op refresh 翻转，**最后只 refetch 一次**——
在循环里调 `archive` 也能работать，但会话索引会被整份重取 N 遍，
而这个功能存在的场景正是「会话太多」，也就是逐行重取最糟的那一刻。
串行不用 `Promise.all`：Main 写的是同一个索引文件，避免两次写抢同一份文档比省这点延迟值钱。
返回真正翻转成功的条数，便于将来如实报告部分成功。

**界面层**：左栏顶栏加一个「选择」图标进入选择模式。

- 状态是**一个可空 Set**（`ReadonlySet<string> | null`），不是布尔加 Set——
  后者有第四种非法状态（「没在选，但有东西被选中」），每个读它的人都得决定怎么处理。
- **同一行横条服务两种模式**。只在选择时才出现的第二行会让列表在进入时下移、退出时弹回，
  而列表正是用户要操作的东西，不能在指针底下移动。
- 行进入选择模式的方式是**被交给回调**（`onToggleSelect`），不是收到一个 flag：
  一个 `selecting` 布尔放在旁边就是同一个事实的第二个来源。
- **复选框占的是运行点那个槽，不是新加一个**。两者都想要行首那 6px，
  而在挑要归档什么的时候，「选没选中」才是重要的那个事实；选择结束运行点就回来。行高不变。
- 归档前弹确认框并报数量。Archive 在本仓是「永久从导航移除」，与单行归档同等严肃。

**顺带修好一个既有缺陷**：`'Archive'` 在 i18n 里**从来没有中文条目**，
右键菜单里一直显示英文，还被 `Button` 基类的 `lowercase` 变成小写的 `archive`。
新按钮继承了这个毛病，一条词条同时修好两处。

## 六、改写的既有断言（一处）

**`sessionContextMenuWiring.test.ts`**「右键由 context-menu 承担，行上没有直接的归档处理器」——
断言 `onClick={onSelect}` 改为 `onToggleSelect(row.sessionId) : onSelect()`。
U31 让点击目标随模式变化；这条 pin 守的两件事（右键不自己接管、行上不直接调归档）没有变，
而且 `onSelect()` 仍然是唯一的激活路径、仍然只从这一个处理器到达。

## 八、欠项

- **没验「确认后真的归档掉」**。探针验到了选择模式与勾选，没点确认——
  那会真的改动本机会话索引。批量归档的执行路径由 `archiveMany` 的断言与
  既有的 `archiveSessionIndexEntry` 覆盖，但端到端没跑。
- **U30-a/b/c 都没在真机复看**。三条都是类串或属性层面的改动，由静态断言锁住；
  抖动是否「看着还动」需要肉眼，并入累计点验。
- **选择模式没有「全选」**。会话很多时逐个点仍然费事，但全选要先定清楚
  「全选的是当前可见的（受搜索/折叠影响）还是全部」——留到有人真的嫌慢再说。
