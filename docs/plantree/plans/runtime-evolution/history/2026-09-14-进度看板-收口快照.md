  互通的做法是「一个文件、两种格式」——会话文件头一行同时满足自有 v4 与 pi CLI 的 v3，读到 CLI 追加的行时在内存里补齐、**不回写也不重排**。
  值得记住的是**可行性探针漏掉的两处**，施工时才暴露：①「改名」「切分支」这类行在 v4 里不是对话条目、没有父子链，而 CLI 把文件最后一行当作对话末端，于是**整段对话在终端里显示为空**——导入的会话必中，因为转换出来的文件最后一行永远是这种行；②压缩在两种格式里的表达方式不同（一个指锚点、一个存整段保留消息），不互译则终端只看得见摘要。
  另外两个顺带结果：**旧的 native 会话在 app 里再打开一次就会自动升级**（否则互通只对新会话生效）；**legacy 后端现在也能打开 native 会话**，这让 P6-4 的回退不再意味着丢掉这期间的对话。
