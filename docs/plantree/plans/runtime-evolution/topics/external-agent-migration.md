# 从外部 Agent 迁移：默认迁移策略与 Claude Code / Codex

Role: topic-capsule。两项决策已于 2026-09-10 拍板，见下。日期：2026-09-10。依据：用户 2026-09-10 两条判断——「老用户应该默认迁移」「后续推广大部分是首次使用者，他们用的是 Claude 或 Codex 官方，所以要支持 Claude、Codex 的对话迁移」。

## 起因：两类用户，两个不同的问题

**老用户**（机器上有 `~/.pi`）。H/19 点验实测：U1 统一 agent 目录之后，迁移没跑之前，**每一条旧会话都以 `Pi model not found: <id>` resume 失败**，而错误文案不提迁移入口（[记录](../evidence/unified-agent-directory/README.md#点验查出的缺口迁移没跑之前旧会话一律-resume-失败)）。H/19 的迁移功能就是解药，但用户没有线索知道要去点它。

**新用户**（机器上没有 `~/.pi`）。他们的历史与配置在 `~/.claude` 或 `~/.codex` 里。对这批人，H/19 的迁移页面**一条都匹配不上**——它只认 pi 的目录形状。

两个问题共用一个界面（设置页的迁移段落），但数据来源、格式、风险完全不同，不该当成一件事做。

## 决策一（2026-09-10 已定）：老用户首启一键确认

**选项 B**。首启弹一次迁移对话框，五项默认全勾，一个「开始」按钮。三个选项与代价如下，留作理由记录。

| 选项 | 代价 / 风险 |
|---|---|
| A 完全静默：首启自动复制全部五项 | 无感，一次到位。但**把用户的 API key 静默吸进本应用的 vault**，是同意边界问题不是技术问题；另外 sessions 目录大小未知，首启同步复制会拖慢启动 |
| **B 首启弹一次一键迁移，默认全勾，一个「开始」按钮（已选）** | 只多一次点击，几乎不损失无感；把密钥这件事说明白；给用户取消勾选巨大 sessions 目录的机会 |
| C 维持现状（只在设置页里放着） | 最省事，但 H/19 点验已证明用户根本不会自己走过去 |

**无论选哪个，错误文案都必须改**。跳过、失败、部分迁移的用户仍会撞上 `Pi model not found`，让失败指向补救是独立的一条，不能被迁移策略吸收掉。

## 决策二（2026-09-10 已定）：只做对话导入，不做配置迁移

用户**推翻了**下面「先配置再对话」的建议，明确只做对话导入。理由记录在案：我的看法是配置迁移对新用户留存的杠杆更大且成本更低，用户不认同这个判断。施工计划见[对话导入](conversation-import.md)。

### 实测的格式事实（2026-09-10，本机）

**Claude Code** —— 可做：

- 落点 `~/.claude/projects/<编码后的cwd>/<uuid>.jsonl`，本机一条会话 **3338 行**。
- 记录类型分布（同一文件）：`attachment` 1120、`assistant` 896、`user` 570，外加每回合一组 Claude 专有元数据（`ai-title` / `agent-name` / `mode` / `permission-mode` / `atis-latch` / `last-prompt` 各 118）、`system` 21。
- 消息带 `uuid` 与 `parentUuid`——**是树不是线**。有分支（编辑重发、回退），拍平成 pi 的线性 transcript 必须选一条分支，会丢信息。
- `message.content` 既可能是字符串，也可能是内容块数组（tool_use / tool_result）。
- 还带 `cwd`、`timestamp`，因此能映射到工作区与排序。

**Codex** —— ~~贵得多，形状不同~~ **此处判断有误，已订正**：

- 原判断：「`~/.codex` 下还有 `thread_history_1.sqlite` 等一堆数据库，历史不是读一个 JSONL 能解决的形状」。
- **订正**：对话记录就在 `~/.codex/sessions/<年>/<月>/<日>/rollout-*.jsonl` 里，PI-Desktop 的 Codex 导入器读的正是它（本机实测 10 个文件）。那些 sqlite 是别的状态。**Codex 与 Claude 的成本基本同级**。详见[对话导入](conversation-import.md#实测的两边格式本机2026-09-10)。

### 关键区分：读出来 ≠ 能接着聊

- **只读导入**（历史能看、能搜、能复制，但不能继续）：中等成本，风险可控，格式差异最多表现为个别块渲染不佳。
- **可续聊**（pi 从 Claude 的历史往下接）：原评估是「贵且有损」。**用户 2026-09-10 要求可续聊，且明确工具调用不重要**——砍掉工具调用之后，这条评估的主要成本项（跨厂商工具调用格式映射）也随之消失。剩下的做法是把外来对话转写成 pi 自己的 v4 会话文件，「能续聊」就是写成原生格式的自然结果。PI-Desktop 也正是这么做的。见[对话导入](conversation-import.md)。

### 一条方向上的不同意见

用户的目标是「让从 Claude / Codex 过来的新用户留下」。按这个目标，**真正的杠杆更可能是「配置」而不是「历史对话」**：

- 从 Claude Code 过来的人，机器上有 `~/.claude/CLAUDE.md`、`commands/`、`settings.json`（权限、MCP）、`skills/`、`hooks/`。把这些搬过来，应用第一分钟就「像他自己的工具」——而这正好是 H/19 已经建好的那套迁移机制能吃下的形状（目录对目录的复制）。
- 历史对话满足的是「我想翻翻上次干了啥」，是查阅价值；它恰恰是最贵、最容易做砸的那部分。

所以建议**先做配置迁移、再做对话只读导入**，而不是反过来。这一条是判断不是事实，用户可以推翻。

### 连带要改的既有决策

`sessionIndexMerge.ts:111-117` 现在**主动隐藏** `claude-code` / `codex` 的会话行（「A persisted runtime outside this build's Pi-only vocabulary is hidden」）。做对话导入就要正面推翻这条，并决定导入后的会话算哪个 agent、能不能发送。

### 与既有节点 P5-4 的关系

任务树里已经有 **P5-4「会话导入适配」**，但和 P5-5 一样只有一行标题、没有范围定义（[任务树](../README.md#p5)）。对话导入很可能**就是**它，或与它大面积重叠。因此本文不把对话导入另立节点——开工前先补 P5-4 的范围，确认「会话导入」指的是 pi 自己不同版本之间的导入，还是本来就包含外部厂商。这与 [H/17 是否已覆盖 P5-5](../open-questions.md) 是同一类问题，处理方式保持一致。

## P0 落地记录（2026-09-10，`22da278c`）

判定与文案集中在新建的 `src/renderer/components/chat/modelMissingError.ts`，四个会撞上这个失败的界面都接到它上面，避免两处文案各自漂移：

| 界面 | 触发场景 | 文件 |
|---|---|---|
| 时间线的历史错误提示 | resume 失败 | `historyError.ts` 新增 `model_missing` 码 |
| 会话失败卡片 | 发送失败 | `MessageTimeline.tsx` |
| 错误气泡 | 发送失败落成 `role:'error'` | `MessageTimeline.tsx` |
| 内嵌 TUI 启动错误 | H/19 U3 统一目录后 TUI 同样中招 | `AgentTerminal.tsx` |

三条判断值得记下来：

- **判定认两个信号**。`piWorkerSession` 抛的 `PiWorkerSessionError('WORKER_MODEL_NOT_FOUND')` 带码；`piAgentSessionBootstrap:475` 抛的是裸 `Error`，码在 worker 的 `errorPayload` 里被压成 `WORKER_REQUEST_FAILED`，只剩 `Pi model not found` 这段文本可认。只认码会漏掉后者，而后者正是点验时实际撞到的那条。
- **不给重试按钮**。模型不会在两次点击之间自己出现，能按但必然失败的按钮比没有按钮更糟。`model_missing` 因此是 `retryable: false`，历史提示里的恢复按钮与 Retry 按钮各自独立渲染，不互相吞掉。
- **按钮落到设置的 Pi 页，文案同时说两条路**。迁移段落在没有 `~/.pi/agent` 时会把自己隐藏掉，只承诺「迁移」会把这部分用户送到一个没有该控件的页面；同一页始终有 AI 服务编辑器，所以文案写成「迁移或补上」。

错误气泡额外保留了原始诊断行——映射文案说清了原因，但丢掉了「是哪个模型」，而那是用户分辨哪些旧会话作废的唯一依据。

验证：`historyError.test.ts` 72 项、新增 `modelMissingWiring.test.ts` 11 项，chat 目录 93 文件 / 1964 项全绿；三套 tsc + Biome 通过。**尚未真机点验**——留到 P1 落地后与 H/19 剩余界面点验一次做完，避免重复启动应用。

## P1 落地记录（2026-09-10，`f147059b`）

`AgentMigrationPrompt.tsx` 挂在 App 层（不在设置里——整条的目的就是够到不开设置页的人），规则在 `agentMigrationPrompt.ts`。只对「有 `~/.pi/agent`、且里面有本应用没有的内容」的用户弹一次；其余人连目录扫描都不做。五项默认全勾，一个「复制选中项」，一个「以后再说」。

四条判断值得留档：

- **全是冲突的计划不弹**。按下去什么都不会复制却报成功，还白白用掉唯一一次提问机会。「有东西可搬」的判据是 `total > conflicts + blocked`，与设置页共用一份。
- **这个对话框从不覆盖**（`onConflict: 'skip'` 写死）。用户看到的是数量不是文件名，对冲突给不出知情的回答；`overwrite` 留在设置页，那里列了名字。
- **只在勾着「AI 服务」时显示 API key 的说明**，取消勾选会同时去掉复制和警告。这正是当初否掉完全静默方案的那条理由，做成了界面上可验证的行为。
- **关掉也算答过**（按钮、Esc、点背景一视同仁），否则下次启动又弹给刚说过不要的人；**复制失败则不算**，免得一次偶发故障悄悄吃掉整个迁移。

「首启」按「第一次有东西可提供的启动」实现。升级进这个版本的用户按任何别的定义都不算首启，而他们恰恰是 H/19 缺陷打中的人。

顺带把 `kindLabel` 与默认勾选规则从设置页抽到共用模块——同一种资源在两个界面叫两个名字是迟早的事。

验证：规则真值表 `agentMigrationPrompt.test.ts` 14 项；**真实挂载的交互测试** `agentMigrationPromptInteraction.test.ts` 14 项（happy-dom，跑通「谁看得到 / 提供什么 / 怎么答」三组）；静态接线 10 项。settings + App 两目录 15 文件 / 148 项全绿，三套 tsc + Biome 通过。**尚未真机点验**。
