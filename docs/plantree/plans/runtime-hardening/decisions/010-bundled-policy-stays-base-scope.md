# 决策 010：随包权限策略只保证「永远加载」，仍是最底层默认，合并顺序不变

日期：2026-09-15。状态：已采纳（用户拍板，回答 Q010；修订决策 008 第 3、4 条）。

## 背景

决策 008 第 3 条写「随包 fail-closed 权限策略相当于托管策略，无论开关如何始终加载、优先级最高」。但 D-Q9 决策 4 定的合并顺序是「随包默认 < 用户 / 受管 agentDir 配置 < 项目 `.pi` 配置」，`mergePermissionScopes` 是后加载覆盖先加载，且「用户永远赢」。把随包挪到最后压顶，用户自己写的规则会被出厂表整表覆盖。真正不可被配置覆盖的兜底是代码里的 `pathPolicy`，在所有 scope 之前判定。

## 决定

1. 维持现有合并规则：后加载覆盖先加载，顺序 **随包默认 → 用户配置 → 项目配置**（T035 加的 local 层紧随 project 之后）。
2. 随包策略无论 `settingSources` 如何都加载，但只是最底层默认，不压顶。
3. 决策 008 第 3 条收窄为「始终加载」；第 4 条的「托管（随包）>」一段作废，改为「编程选项 > local > project > user > 随包默认」。
4. 本产品目前没有「管理员下发、用户不可覆盖」的策略来源；若将来需要，另立托管层，不复用随包文件。

## 影响

- 无代码改动：T035 已按「永远加载、仍为 base」落地。
- open-questions 移除 Q010。
