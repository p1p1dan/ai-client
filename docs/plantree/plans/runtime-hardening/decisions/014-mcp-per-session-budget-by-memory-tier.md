# 决策 014：MCP 每会话进程上限从固定 16 改为按内存分档 4/6/12

日期：2026-09-15。状态：已采纳（编排者裁定，用户可推翻）。

## 背景

T046（容量与进程对账表的余项）落地 concurrency-04：MCP 服务器需要「跨会话的全局进程预算」，而不是此前每会话固定 16 个的写法。WorkerManager 早已按本机内存把并发会话槽位分成 3/6/10 三档，MCP 的每会话上限却没有随内存分档；全局预算必须随内存增长，而每会话能分到的份额 = 全局预算 ÷ 并发槽位数。按约 75 MiB/进程估算，MCP 服务器满载大约占用整机内存的五分之一。

## 决定

1. 在 `src/runtime/plugins/mcp/config.ts` 新增三个常量/函数：`workerSlotBudget`（镜像 WorkerManager 的 3/6/10 内存分档，注释里写明「那边改了这边要同步改」）、`sessionServerBudget`（每档 4/6/12）、`hostServerBudget`（= 槽位数 × 每会话上限，即全机 12/36/120）。
2. `loadMcpConfig` 默认按本机内存取 `sessionServerBudget()`；超出上限的服务器按声明顺序丢弃，诊断文案点名哪些服务器没有起，并说明「每个开着的会话都会各起一套，本机总共允许 N 个」。
3. 常量集中在 `mcp/config.ts` 一处，可一行调整。

## 影响

- 用户可见的行为变化：在 3.3 GB 一类低内存机器上，配置了 5 个以上 MCP 服务器的用户会被砍到 4 个；被丢弃的服务器会在诊断里点名。
- 分档镜像写在 `mcp/config.ts` 而不是去改 WorkerManager 的分档注释（落地当时 `WorkerManager.ts` 被并行的 T041 占用）；把两处分档互相指认的注释补全已转入批次 F。
- concurrency-04 结案。本决策不影响 [Q014](../open-questions.md)（32 MiB 会话预算 vs 渲染层 5 MiB 单图上限的算术冲突），两者是独立问题，Q014 仍待拍板。
