# 决策 015：Q014 以「附件旁路文件 + 引用」结案，立项 T058 排批次 F

日期：2026-09-16 · 拍板人：用户 · 状态：已决

## 问题（原 Q014）

32 MiB 会话预算（`SESSION_MAX_BYTES`，codec.ts:20）与渲染层 5 MiB 单张附件上限、8 MiB 单条落盘上限（`ATTACHMENT_TURN_STORED_BYTES` = 预算/4）在数学上不可兼得：正常使用满足「个位数消息顶不满」（一条带截图消息 1～2 MiB），但极端构造（每条塞满 8 MiB）4 条即打满预算，之后会话文件打不开。要把 4 推到 10 以上须把单条压到 3 MiB 以下，而单张 5 MiB 照片 base64 后就有 6.7 MiB——连渲染层自己承诺的一张照片都发不出去。完整算术见[容量对账表第八节](../evidence/capacity-reconciliation-2026-09-15.md)。

## 决定

三个候选（调大 `SESSION_MAX_BYTES` / 调小单张上限 / 附件旁路）中，用户拍板**附件旁路文件 + 引用**——唯一根治路径：附件字节不进会话 JSONL，另存旁路目录，JSONL 只存引用；会话文件从此回到文本量级。
