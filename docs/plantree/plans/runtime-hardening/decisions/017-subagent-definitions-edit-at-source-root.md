# 决策 017：兼容根子代理定义按来源文件编辑 / 删除

日期：2026-09-17 · 拍板人：编排者采纳，用户可推翻 · 状态：已决（待用户确认）· 任务：T063（批次 D4）

## 问题（D12）

设置页对子代理定义的「编辑」与「删除」此前走的不是同一份文件。目录合并规则是「主目录 `<agentDir>/subagents` > 兼容根 `~/.agents/subagents` > 内置」，同名先到者赢（`src/runtime/plugins/subagent/catalog.ts:78-89`、`src/shared/subagentDefinition.ts:566-586`），但写路径此前无条件写主目录（`subagentCatalog.ts` 改前 `:236/237`、`:408`）。后果：

- **编辑兼容根的定义 = 复制一份到主目录再改**，兼容根原件一字未动，界面上看不出「编的是副本」。
- **删除只删主目录那份影子副本**，副本一没，兼容根原件按合并规则重新浮上来、带着编辑前的旧内容，要再删一次才真的没有。

台账处置栏原写「需要产品决策再定修法（A/B/C 三选一）」，实现方在 T063 落地时先行选定了方案 A（`/tmp/t032/fixes/T063.md` §2）。只读审阅（`/tmp/t032/reviews/group2.md` T063 节 ④）指出这属于决策而非实现细节，应当登记成一条 decision 结掉 D12 的「待定」，否则下一任接手者读台账仍会以为没定——本决策补这道手续，追认并结案该选择。

## 候选与取舍

- **候选 A（选定）：编辑 / 删除按定义的来源文件操作**。编辑写回来源文件本身（主目录的写主目录、兼容根的写兼容根，`mkdir(dirname(target))` 取代固定 `mkdir(this.directory())`）；删除按名字清掉**两个根**里所有同名 `.md`（含被主目录遮住、界面上没有行的兼容根旧文件）；内置定义仍不可删。
- **候选 B：只写主目录 + 删除两根 + 提示副本**。编辑永远落主目录（继续制造/维持影子副本），删除仍清两根，但在编辑时弹一条「已复制到主目录」的提示，告知用户实际改的是副本。

取舍：B 需要一条提示去解释一个本可以不存在的副本，且「我编的文件到底是哪一个」这个问题永远还在；A 直接消灭副本这个概念本身，不需要额外提示。

## 决定

采用 **候选 A**：编辑 / 删除按定义的来源文件操作，兼容根 `~/.agents/subagents` 原地写回；删除清掉两个根里所有同名 `.md`；内置定义不可删的语义不变。

## 理由

- **兼容根没有「只读」的安全约束。** runtime 侧唯一的安全性论述是「**项目目录**永不扫描：仓库不能靠被打开就往用户目录塞一个可委派的子代理」（`src/runtime/plugins/subagent/catalog.ts:9-16`），说的是 project root，不是兼容根；`~/.agents/subagents` 在用户自己的 home 下、与 `~/.agents/skills` 同层，而本仓已经把 `~/.agents/skills` 当**写入目标**用（`src/agent-host/userResourcePaths.ts:26` 直接让模型把技能装到那里）。手册里所称的「兼容根（只读）」描述的是当时的实现行为，不是安全要求。
- **A 才是原设计意图。** main 侧 `roots()` 的原注释本就写着「用户应当看到定义**在哪**——所以一行带着它的文件路径，而不是被悄悄复制走」（`subagentCatalog.ts:83-90`），写路径此前无条件落主目录只是没跟上这条意图。
- **语义与用户心智一致**：用户编辑一份定义时期望改动的是「那一份文件」本身，而不是凭空多出一份自己不知道的副本。

## 后果与审阅备注

- 编辑 / 删除会动到 **跨工具共享的 `~/.agents` 目录**（该目录 pi TUI 等工具也读取）；写入内容格式未变、仅内容被覆盖，但别的工具可能正按自己的规则使用被主目录遮住的那份旧文件。
- **删除确认框仍是单数文案**（"This removes the definition file."），而一次删除可能同时清掉两个根的同名文件；审阅建议把文案改为列出将删除的路径/条数，本决策未连带处理该文案，留作后续 UI 微调（T063 记录 §2 已认下此代价）。
- **新建定义时若兼容根已有同名的「解析失败」坏文件，新定义会被写进兼容根**（覆盖那个坏文件）而不是落主目录——因为写路径挑选来源时，候选集合包含解析失败的同名文档。这与「新定义总是落主目录」的直觉印象不完全一致；审阅记录为待补用例的缺口，不构成对本决定的否决理由。
- 重命名同理按名字清两个根：旧名字的所有文件一起删，避免被影子盖住的旧定义在改名后的名字下重新出现。
- 已知未覆盖（非本次新增回归）：超过大小上限或读取失败的同名文件不会进入扫描结果，因此删不到、行还会回来；改前已有此盲区。
