# 决策 020：临时工作区根目录固定加一层应用专属子目录

日期：2026-09-17 · 拍板人：用户 · 状态：已决 · 任务：T071（批次 F）

## 问题（结 Q018）

T060 修好「保存位置」设置的 Main 侧读取问题后，`adoptTempWorkspace` 判断是否认领一个目录时，只看它是不是保存位置根的**直接子目录**（`isDirectChildOf`），不问该目录是否由本应用创建。若用户把保存位置设成某个真实项目的父目录，且该项目本身不是 git 仓库，应用会对它执行 `mkdir` + `git init` 并当作临时工作区处理——用户没做过这个动作，也没有任何提示。该问题此前登记为待拍板的 [Q018](../open-questions.md)，来源是 T060 只读审阅备注 `evidence/batch-d4-fixes-2026-09-17/reviews/group1.md` T060 节。

## 候选与取舍

- **候选 A**：标记文件——目录由本应用创建时写一个 marker 文件，认领判据只认带 marker 的目录。
- **候选 E（选定）**：在「保存位置」设置的目录下固定加一层应用专属子目录（例如 `<保存位置>/aiclient-temp/`），临时工作区只认领该层下的直接子目录，不再直接对用户设置的保存位置根做子目录扫描；默认值 `~/JYWAI/temporary` 本身就是这样一个专属目录，默认行为不变。
- **候选 F（否决）**：固定放 `~/.pilab/<profile>/tmp` 并去掉「保存位置」这个设置。否决理由：加密机需要把临时目录放进受策略管控的目录，去掉设置会让 ENC-10 场景无法满足。

取舍：候选 A 需要新增并维护一份 marker 文件的写入、读取与迁移逻辑，且目录创建成功、marker 落盘之前存在一段窗口期。候选 E 是结构性隔离——只要临时工作区永远建在应用自己的专属子目录里，用户的真实项目就不可能出现在这一层，不需要标记文件，也没有窗口期问题；同时不动「保存位置」这个设置本身，满足加密机需要把临时目录放进策略目录的场景。

## 决定

采用**候选 E**：保存位置目录下固定加一层应用专属子目录，临时工作区只在该子目录下创建与认领。

## 理由

- 结构性隔离：真实项目不可能出现在应用自建的专属子目录里，从根上避免误认领。
- 不需要标记文件，不存在「目录已建、marker 未写」的窗口期。
- 保留「保存位置」设置，满足加密机需要把临时目录放进受策略目录的需求（ENC-10）。
- 默认值 `~/JYWAI/temporary` 本身已经是专属目录，普通用户的默认行为不变。

## 后果与备注

- 待设计：用户显式把「保存位置」设成与默认值相同的路径时，是否还要在其下再加一层专属子目录（建议：与默认值相同则不加，避免出现 `~/JYWAI/temporary/aiclient-temp/` 这种多余嵌套）。
- 待设计：已存在的临时工作区（建在旧的「直接子目录」布局下）如何迁移，或是否需要一段双读过渡期（新旧两层都认）。
- `TempWorkspaceService` 与 `ScratchWorkspaceService` 两处目前各自解析「保存位置」根，需要收敛到同一个根解析函数——T060 已经把 Main 侧的设置读取统一到一个入口，这次要在此基础上把「专属子目录」这一层也并入同一个函数，不能让两处各自拼路径。
- 验收细节见 [roadmap.md](../roadmap.md) 批次 F T071。
