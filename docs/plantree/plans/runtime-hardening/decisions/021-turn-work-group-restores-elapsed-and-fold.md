# 决策 021：回合过程收进「工作组」，并恢复「已工作 xx 秒」

日期：2026-09-18 · 拍板人：用户 · 状态：已决 · 任务：T072 / T073（批次 G，已落地）

## 问题

用户直接提出：「各种调用、授权穿插在 agent 的输出中，严重影响我的观感。用户真实关注的其实只是模型输出，而不是那些什么思考和终端，这些只在用户需要看的时候手动展开看就行。」

聊天区当前的形态是：助手的每一段散文都永久可见（`turnItemPlacement` 把所有 `text` 项标为 `answer`），工具行、思考行与授权卡按块序穿插在它们中间。一个「说一句 → 调工具 → 再说一句 → 调工具 → 给结论」的回合，会把五段内容平铺出来，最终结论淹没在中间过程里。

这件事挡在两条已记录的旧裁定前面，必须先把它们推翻：

- **2026-08-29**：跟随 pi-app 删除回合底部的 meta 行。理由是「一个完成的回合对自己的耗时和工具数什么都不说」。落地后 `formatWorkedForRow` / `deriveTurnStats` / `turnHasThinkingOnlyProcess` 三个函数在 `src/` 里再无渲染方，成为保留但未接线的死代码。
- **2026-09-10**：对照 PI-Desktop 加回 segment 级折叠，摘要文案定为「已处理 N 个步骤」，**明确不带时长**。

## 候选与取舍

- **候选 A（选定）**：回合渲染成「用户气泡 → 工作组 → 最终输出」。工作组吞掉最后一段散文之前的全部内容；运行中展开、header 显示「工作中」，结束后 header 变「已工作 57 秒」并自动折叠。思考行与终端行沿用既有的默认折叠。
- **候选 B**：维持 09-10 的 segment 级折叠，只把摘要文案补上时长。不动散文的归属。
- **候选 C**：维持现状，只靠调整对比度拉开层次。

取舍：选候选 A。候选 B 解决不了用户提的那一半——中途散文仍然全部平铺，最终结论仍然被夹在中间；候选 C 只是把噪音调暗，噪音还在。

「最终输出」的判定取 `segments` 里**最后一个 `answer` 段**，而不是 FB4 废弃掉的旧规则「尾部连续的 text 项」：后者在回合以错误提示收尾时会把整段回复都折进去，那正是 FB4 修掉的缺陷。notice 完全不参与判定，且永远留在组外可见。

## 决定

采用**候选 A**。同时正式推翻 2026-08-29 与 2026-09-10 两条旧裁定：

- 完成的回合**要**报告自己的耗时（推翻 08-29）。
- 折叠摘要**要**带时长（推翻 09-10）。

## 理由

- 用户是这两条旧裁定的同一个拍板人，本次直接提出了相反诉求，并给了目标形态的参照截图。
- 旧裁定的依据是「跟随 pi-app」与「对照 PI-Desktop」，即外部参照，不是本产品自身被验证过的结论。外部参照与用户当下诉求冲突时，以用户诉求为准。
- 08-29 留下的三个格式化函数一直没删，接回来的成本很低。

## 后果与备注

- 时长未知时（例如回放的历史回合没有 T-06 元数据）回落到「已处理 N 个步骤」，**绝不编造秒数**——A07 的「never fabricate seconds」红线不受本决策影响，仍然成立。
- 折叠状态是纯派生（强制展开 > 用户点过的选择 > 未结束），不用 `useEffect`。这让「StrictMode 下触发两次」与「重渲染把读者展开的组重新关掉」在结构上不可达；历史回合从第一帧即已结束，因此天然挂载成折叠态。
- 工作组用原生 `<details>` 而非 `@coss/ui` 的 `Collapsible`：后者的 panel 带 `overflow-hidden`，会创建 containing block 并静默破坏置顶气泡的 `position: sticky`。这是对「组件优先」规范的一次有据偏离，理由写在 `turnProcessShellClass()` 注释里，并有用例正面断言被排除的那个组件确实带 `overflow-hidden`。
- 三档对比度全部用既有语义 token，未新增颜色：最终输出 `text-foreground`（18.78 / 11.38）、工作组 header `text-muted-foreground`（7.20 / 6.70）、思考与终端 `text-tool-arg`（5.09 / 5.02）。**这三组数字是按 `globals.css` 的 oklch 值算出来的，不是量出来的**；暗色下第二跳只有 1.33×，够不够看待 T033 上机复核。
- 为拉开第二跳，`ToolRow` 非失败态行色从 `text-muted-foreground` 降到 `text-tool-arg`，连带影响授权卡里的「已批准 / 已拒绝」行。这是本次唯一溢出聊天区的视觉变更。
- 同时移除「授权详情」折叠条（用户第 3 条诉求）。代价：被静默自动放行的授权在界面上没有出口了，数据与会话日志中仍在，`includeAllowed` 参数是回头路并有测试守着。
- `messageTimelineWiring.test.ts` 的 `[FB6-4]`「过程段无条件渲染」原断言其实自 09-10 加回 `<details>` 折叠起就已空转八天——它靠三个否定成立（无 `hidden=`、无条件分支、无 `<Collapsible`），而 `<details>` 三条都不命中。本次改写为钉住新红线，不是修补而是替换。
- 运行中会同时看到工作组 header 的「工作中」与底部状态行的「正在输出 · Ns」。本决策未处理这处重复，留作后续可选项。
