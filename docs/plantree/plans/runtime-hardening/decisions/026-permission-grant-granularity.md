# 决策 026：授权记忆的粒度——文件类精确匹配、bash 记前缀、按会话持久化不跨会话

日期：2026-09-18 · 拍板人：用户 · 状态：已决 · 任务：T081（批次 H）

## 问题

T081 落地的授权记忆放宽（[批次 H 证据](../evidence/batch-h-field-fixes-2026-09-18/README.md)）里，文件类工具记的是 `[工具, 父目录]`：命中该父目录下的任意子路径即放行。当第一次批准的文件恰好在工作区根目录下（例如根目录下的 `README.md`）时，「父目录」就是工作区根，这条记忆会覆盖整个工作区——远超用户批准那一个文件的本意。同时，bash 类记忆取命令前缀放行同类调用，但 `rm`/`mv`/`dd` 这类单词命令只取一个词做前缀，粒度是否也偏宽存疑。这两点登记为 [Q023](../open-questions.md)，需要用户拍板放行粒度的边界。

## 决定

- **文件类**：只记批准的那一个文件本身，不再记父目录、不放大到目录范围。对齐 Claude Code 客户端的做法。
- **bash 类**：维持记命令前缀不变，多子命令工具（`npm`/`pnpm`/`yarn`/`npx`/`git`/`cargo`/`dotnet`/`go`/`make`/`cmake`/`docker`/`kubectl`/`python`/`python3`/`node`）取前两个词；其余（含 `rm`/`mv`/`dd` 这类单词命令）取第一个词。这一粒度比 pi-desktop「只记工具名」窄，与 Claude Code 的 `Bash(npm test *)` 前缀写法同形。
- **存活期**：维持现状——随会话持久化（写入会话 JSONL，重开会话仍读得到），不跨会话、不永久保留。

用户原话：「命令我觉得参考 claude 或者就 pi-desktop，文件参考 claude，不要放大，记多久保持现状」。

## 理由

用户直接点名参照对象：文件类参照 Claude Code（精确到文件，不放大），命令类在 Claude Code 与 pi-desktop 两种现成做法之间选择，存活期不改动现状。三家可比对象的实际做法（落地时核实）：

| 产品 | 命令类记忆粒度 | 文件类记忆粒度 | 存活期 |
|---|---|---|---|
| Claude Code | 前缀匹配（如 `Bash(npm test *)`） | 只记字面路径，不放大到目录 | 命令类永久写仓库 `.claude/settings.local.json`；文件类只到当前会话结束 |
| Codex | 会话内精确匹配；前缀规则单独配置 | — | 精确匹配存活于会话内；前缀规则永久写 `~/.codex/rules` |
| pi-desktop | 只记工具名（不区分命令/路径） | 只记工具名 | 纯内存，不落盘 |

本应用最终选择：文件类粒度对齐 Claude Code（精确到文件）；命令类粒度维持 T081 已实现的前缀匹配（比 pi-desktop 窄、与 Claude Code 前缀写法同形）；存活期不学 Claude Code 命令类的「永久写仓库配置」，也不学 pi-desktop 的「纯内存不留痕」，维持 T081 已定的「随会话持久化、不跨会话」。

## 后果与备注

- 文件类授权记忆从 `[工具, 父目录]` 改为 `[工具, 文件路径]`；同一目录下批准过的另一个文件仍需单独授权。
- bash 类前缀规则不改动，`rm`/`mv`/`dd` 等单词命令维持取第一个词的现状，不额外收紧。
