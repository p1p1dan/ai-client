# 决策 034：过程行向 zcode 形制对齐（退休聚合行，头改报时长）

日期：2026-09-22 · 拍板人：用户 · 状态：已落地 · 任务：待排（本决策为落地依据）

## 问题

[决策 033](033-process-group-expanded-and-visual-hierarchy.md) 当日落地后，用户在实机上连续三轮反馈同一件事：

1. 「我感觉这每句输出之间还是一团乱麻，太多东西了」
2. 「已运行那一行，总是特别长，而且我也看不全指令」
3. 「你看看 zcode 的，为什么它的看起来这么简洁清爽呢」

第 3 条附了 zcode 的截图，是本决策的依据。

## 一个读法修正（关键）

zcode 截图顶部那行 `已工作 6 分 41 秒 ⌄` **就是折叠头**——默认展开、带 chevron、一个回合一个。所以它**并非「全平铺」**，它和我们的过程折叠头是同一个东西，只是文案不同、位置在回合顶部。

这一条必须记在案上：不写下来，下一个人对着同一张截图会得出「zcode 没有折叠」的结论，然后把折叠头删掉。

**zcode 真正没有的是：聚合行、每行的 chevron。** 它清爽不是因为藏得多——它在这一层什么都不藏——而是因为**每一行都短、都淡、都没有控件**。

## 逐项比对（对着截图）

| | zcode | 033 落地后的我们 |
|---|---|---|
| 回合级折叠 | 有，顶部一个，报时长 | 有，报步数 + 调用数 |
| 聚合行 | **无** | 有（031 D1–D5） |
| 每行控件 | **0 个** | 1 个 chevron |
| 动词 | 图标 + 两字类型（编辑/终端/思考） | 过去时三字（已编辑/已运行/已思考） |
| 编辑行 | 文件名 + 弱化目录 + `+9` / `+4 -3` | 一条 `目录/文件名` |
| 过程行明度 | 几乎沉进背景 | `muted-foreground` 85% 混背景 |

## 决定

### D1 · 退休聚合行（推翻 031 的 D1–D5）

`toolCard.ts` 的 `deriveToolGroupRows` 退化成**一个 entry 一行**。`deriveAggregateRow()`、分段循环、`breaksSegment`、`applyThinkingDurations()`、`buildEntryRow()`、`ToolRowView.toolCallCount` 全部删除。

031 的聚合是对「过程条目太碎」的回答，它确实减少了**行数**，但没有减少**噪音**——代价是多了一层展开：回合有折叠头，头里有聚合行，聚合行里每条还有 chevron。三层里只有第一层是用户要的。

⚠️ `body: 'detail'` **不删**：委派面板（`subagentActivityModel.ts`）是另一个生产者。

**FB7 红线的去向**：「带授权记录的 run 不参与聚合」曾是为了让待决策不被折进「12 次工具调用」后面。没有聚合行之后，该性质**由构造保证**。守卫测试改从另一侧断言——「决定必须在行上可见」，而不是「该行被排除在某个已不存在的分组之外」。

### D2 · 折叠头改报时长（修订 033 的 D1/D4）

用户原话：「折叠头就不要那个 73 次工具调用了。也不要显示什么已处理 xxx 个步骤。」

- 头的内容 = **回合的钟**：流式 `✻ 工作中 6 分 41 秒 · <当前动作>` + spinner，结束 `已工作 6 分 41 秒`。
- 复用既有词条族 `Working …` / `Worked for …`，**不新增词条**；033 D1 当天新增的 `{{count}} steps processed` 同批退休。
- **底部工作区行改为只在结束后渲染**，且不再报时长，只剩 `完成于 17:05 · 73 次调用 · 思考 24 秒`。流式态整条退役——证据已搬到头上。

> ⚠️ **本条已被 [决策 036](036-turn-clock-always-has-a-home.md) 修订。** 「钟在头上」只是大多数情况：T112 规定不足两步的分组不折叠，所以「思考+输出」「单工具+输出」「纯文本」三种形状**根本没有头**，时长无处安放（用户报告「有的时候，直接显示：思考+输出，没有已工作 xx 秒」）。[决策 037](037-turn-clock-always-on-top.md) 的落地形式是：**时长永远是回合的第一行**——分组会折叠时这一行就是折叠头，不会折叠时是同款的平铺行（`TurnClockRow`），两者读同一份措辞推导。036 曾把它兜底到尾栏，被用户驳回（「那样展示出来的风格都不统一」）。另外本条落地时把 `✻` 当成了 `joinTurnProgressLine` 的 head，渲染出「✻ · 完成于 17:06」，一并修正。

⚠️ **一个回合只有一个头能拿到钟**。回合中间出现 notice 时会长出第二个过程组，两个头都印时长就是 T107 的老毛病。实现用 `ChatTurn` 里的闩锁而非 `index === 0`，因为 `turnProcessGroupFolds` 可能让首个分组根本不渲染头——那样按下标发钟会让整个回合没有可见的钟。

> ⚠️ **本段末句已被 [决策 035](035-replayed-turn-clock-and-never-blank-head.md) D2 推翻。** 原文写的是「没拿到钟的头只剩一个 chevron，这是诚实的」——它不诚实，它是空行。闩锁当时扣留的是整个 `zone`，于是那个头连状态都说不出。035 把闩锁改为只管**数字**：`zone` 永远给，`clock` 只给第一个。同时，本 D2 删掉头上无条件存在的那行文字之后，**无钟的回合（几乎所有历史回合）头也是空的**——见 035 的根因一节。

### D3 · 每行去掉 chevron

整行本来就是触发器，chevron 只是在广告这件事。一行一个，它是这个界面上密度最高的东西。

⚠️ **代价记录在案**：可展开的行现在和不可展开的行长得一模一样，只能点了才知道。这是用户在 `docs/examples/process-rows-zcode-style.html` 里看过两种形态后选的。

### D4 · 图标 + 两字类型标签

- 新增 `toolIconKind(toolName)`（`toolCard.ts`）返回图标种类，`ToolRows.tsx` 里映射到 Lucide 组件。**返回种类而不是组件**：`toolCard.ts` 按文件头的契约是 React-free 的。
- 比 `classifyTool()` 更细，且是刻意的：那个函数回答「计入哪个桶」，终端/编辑/委派对它都是同一个 `action`——而这正是图标存在的意义。
- 中文词条改两字类型：`Ran`→「终端」、`Edited`→「编辑」、`Grepped`/`Searched files`→「搜索」、`Thought`→「思考」、`Listed`→「列目录」。

⚠️ **英文 key 一个不改**：它是词表主键，三套覆盖扫描按名字枚举它。
⚠️ **`Running` / `Thinking` 的值不改**：两者与 Run 面板、左栏共用（`runPanelModel.ts`、`LeftNav.tsx`），在那里是会话状态而不是工具行动词。这正是 T101 的缺陷形状——一个 key 两个界面——也是现在时那一侧没跟着动的原因。

### D5 · 编辑行：文件名在前，目录弱化在后，带差异统计

- `chat/ToolRows.tsx` → `ToolRows.tsx  chat/`。**重排是重点，不是变淡**：文件名才是区分相邻两条编辑行的东西，放前面意味着读者在固定的左偏移找到它，而不是在目录碰巧结束的地方。
- 差异统计**本来就有**（`toolDiff.ts` 的 `added` / `removed`，`countRows()` 已算好），本次只是去掉冗余标签并上色：普通已结算的编辑只印 `+4 −38`（`text-success` / `text-destructive`）。预览态、失败态、整文件写入**保留各自的标签**——那三个说的是动词没说的事。
- 实现放在渲染层（按最后一个 `/` 切分已成形的 `arg`），而不是给 `deriveToolRowView` 穿第二个字段：缩短规则（`shortPath`）已经跑过，链接的 `title` 仍带全路径，而非路径形状的 arg（命令、模式、时长）必须原样通过——这就是 `includes('/')` 那道闸的作用。

### D6 · 过程行明度再压一档

`--tool-arg` 从 `muted-foreground 85%` 调到 **62%** 混背景（`globals.css`）。过程行本来就是用来**略过**的，85% 时它还在跟被它打断的正文抢注意力。

## 影响

**推翻/修订的既有决策**：

- **031 的 D1–D5**（两层聚合）→ 整体退休。
- **031 的 D4**（思考打断聚合）→ 已于本日早些时候单独推翻过一次，现在连同聚合本身一起消失。
- **033 的 D1/D4**（头报步数 + 调用数徽标）→ 改为报时长。
- **T113** 的工作区行四个数字 → 时长上移，剩三个。

**不动的**：`turnWorkGroupAwaitsUser` 授权红线（折叠组还在）、终稿分隔线（033 D1）、旁白与终稿同字号只差颜色（033 D8）、F10 吸顶红线。

**设计依据**：`docs/examples/process-rows-zcode-style.html`（五项开关逐项对照，全开 ≈ zcode）。按惯例不入库。

## 未决

1. **长回合的可读性**：用户自己的会话动辄 155 步，去掉聚合后就是 155 行。头能一键收起，但展开态下没有中间层级。需要实机验证滚动体验。
2. **无 chevron 后的可发现性**：可展开与不可展开的行在视觉上不可区分，需实机确认是否需要一个更轻的提示（hover 态？）。
