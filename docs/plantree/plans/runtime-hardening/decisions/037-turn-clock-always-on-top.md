# 决策 037：时长永远在回合顶部（推翻 036 的尾栏兜底）

日期：2026-09-22 · 拍板人：用户 · 状态：已落地 · 任务：待排（本决策为落地依据）

## 问题

[决策 036](036-turn-clock-always-has-a-home.md) 落地后不到一小时，用户驳回：

> 错。不要擅自做主，改变方案，方案要统一。什么情况都让 已工作 x 分 xx 秒落在顶部。不要什么一个折叠头都没有时，落到尾栏，那样展示出来的风格都不统一

## 我错在哪里

036 把问题读成了「钟要有个落脚处」，于是找了个现成的空位——尾栏——填进去。**问题本身没读错，方案换了。** 034 D2 的形制是「时长在回合顶部第一行」，036 交付的是「大多数回合在顶部、少数在底部」。规则听起来只差一个兜底，屏幕上是两种回合长得不一样。

记在案上的教训：**缺陷报告说的是「这里少了个东西」，不等于授权「把它放到任何有空的地方」。** 形制是方案的一部分；换落点就是换方案，要先问。

## 决定

### D1 · 时长是回合的第一行，无条件

不变式从 036 的「恰好一行带时长」收紧为：

> **时长是回合的第一行。** 分组会折叠时，这一行就是折叠头；不会折叠时，这一行是 `TurnClockRow`——同样的字、同样的样式、没有 chevron。

T112 的阈值仍然不动：一步的分组就地平铺，它下面本来就没有东西可展开，挂个 chevron 是撒谎。

渲染位置在 `workSections` **之上**而不是织进去：「第一」就是全部要求，而分组未必是回合的首个 section（回合开头有 notice 时就不是）。

### D2 · 两个载体读同一份推导，谁都不许自己组词

`useTurnClockLine(zone, clock, items)` 是唯一的措辞来源，折叠头的 `<summary>` 与 `TurnClockRow` 都读它。

⚠️ **这是 D1 的落地形式，不是顺手的重构。** 两个调用点各自用同一批词条拼「已工作 N 秒」，就是「风格都不统一」在没人拍板的情况下重新长出来的方式。守卫断言两个元素都不含 `workedHeadText` / `workingHeadText` / `joinTurnProgressLine`。

样式同理：`TURN_CLOCK_ROW_BASE` 是唯一的类来源，`turnWorkGroupSummaryClass` 与 `turnClockRowClass` 都由它派生。

### D3 · 平铺那行不上 sticky，而这不破坏「统一」

T096 规定时间线上**有且仅有一个** sticky 面（F10 高度振荡，见 `chatTimelineLayout.ts` 文件头）。平铺行头的是至多一步的分组，没有长内容要滚过去，pin 一无所得。

`sticky` / `top-0` / `z-10` 在未吸顶时**不改变这行的任何视觉**，所以外观仍然是同一条线。守卫把两者的类差断言成一个**封闭清单**（三个 `<summary>` 专属 + 三个 pin），而不是截图比对。

### D4 · 尾栏退回纯账单行

036 给尾栏加的时长槽、流式态、`clock` prop 全部撤销。尾栏只剩「✻ 完成于 17:06 · N 次调用 · 思考 N 秒」，流式期间不渲染。

**保留** 036 D4 的 `✻` 前缀修正——那是独立缺陷（`joinTurnProgressLine('✻', …)` 渲染出「✻ · 完成于」，左边什么都没有的分隔符），与落点之争无关。
