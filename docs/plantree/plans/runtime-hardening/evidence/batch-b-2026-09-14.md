## 与 roadmap 字面不同的做法（已认可）

- T012：tools-04 的修复点在 `accept()` 而非审计定位的那一行（60 KiB 单行实际走的是另一条分支，两条分支共用同一语义）；grep 超预算给截断说明并在 details 标 `timedOut`，不抛错，保住已搜到的命中；read 可见预算固定减 128 字节留给续读尾巴；read 空结果分「(empty file)」与「(no lines at offset N)」两种措辞；顺带把「不含 `/` 按任意深度」写进 glob / grep 的 description。**残余风险**：JS 正则同步执行不可中断，单独一行灾难性回溯仍可能卡住 worker，需独立线程才能根治。
- T015：`close()` 用 allSettled 之外加了 `writeFailure` 取值器作为失败观测点（不进 contracts）；抢占陈旧锁的归属校验用原始字节比对而非 token（撕裂的锁解析不出 token）；输掉竞争时把误取的锁原样写回，避免删掉赢家的锁；无效 label 行丢弃而不是让整次导入失败。派单时把 session-09/10/12 三条的描述轮换了，代理按审计原文编号落到代码与用例里，工作项集合不变。
- T018：skills-mcp-04 用字节缓冲（遇 0x0A 整帧解码）而非 `StringDecoder`，一处同时修好跨块解码与按字节计帧长；工具注册失败记进新字段 `connection.toolErrors` 而非 `connection.error`（后者有 `mcp_failed` 计数与 `close()` 两个消费者，一个工具撞名不该把整台服务器标失败）；工具名点号替换而非拒绝，`config.ts` 服务器名校验保持 `[\w.-]`；额外加了图片 8 张上限、文本块永不为空（否则 projector 会把 base64 JSON 化进 transcript）、`fail()` 经 `onFailure` 回填 `connection.error`。
- T019：派单时 skills-mcp-17/18/19 的描述也轮换了，代理按审计原文实现。悬空 symlink 留 `read_failed` 诊断（pi 上游静默跳过）；块标量视为未声明并记 `invalid_metadata`；模板描述回退先折叠空白再截 60 字；`SkillsPlugin.refresh()` 按已解析根重扫但无自动调用方；项目 `.agents/skills` 从 cwd 向上找 `.git`（上限 64 层），仓库根先入栈、cwd 后入栈，靠 last-wins 实现近者优先，`.pi/skills` 不受影响。
