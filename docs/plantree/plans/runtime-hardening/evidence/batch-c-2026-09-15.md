- `createRuntimeApprovalBridge` 的 approve 臂（permissions-15，状态 uncertain）保留，但把硬编码的 `120_000` 超时改为可配置：`createRuntimeApprovalBridge(options, timeoutMs = PERMISSION_TIMEOUT_MS)`，经 `bootstrap.ts` 的 `options.permissions?.timeoutMs` 透传。

### 批次 E GUI 点验清单（来自 T026）

三处界面都需要先真发一轮消息把 worker 拉起来（数据来自 bootstrap 结果，冷会话只显示「未报告」态）：

1. **侧栏「能力」面板**（原「插件」面板）：触发左侧导轨最底部方块图标（Blocks）。期望弹窗标题「能力」，四行摘要（MCP 服务 / 技能 / 提示词模板 / 子智能体），MCP 行显示「就绪数/总数」徽标，连不上的服务器显示红色 Failed 徽标加错误原因，底部提示「你安装的 pi 扩展只会被内嵌终端加载」。反例：任何一行显示裸的「0」而不是「未报告」；配了真实 MCP 服务器却看不到徽标（需项目里放一份能连上的 mcp.json）。
2. **设置 → Pi → 插件分区**：期望分区说明「装在你账户下的扩展。只有内嵌的 Pi 终端会加载它们」，永远有一条蓝色提示「本应用的每个对话，都由它自带的权限系统审批工具调用」；只有确实装过 `@gotgenes/pi-permission-system` 时才额外出现橙色提示「你自己安装的 pi 权限系统只对内嵌终端生效」。反例：出现「本应用主动让路」「审批设置不再生效」字样。
