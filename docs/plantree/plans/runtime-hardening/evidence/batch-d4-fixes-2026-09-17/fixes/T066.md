## 一、electron-log 接线结论（先查清的那个根因）

**结论：electron-log 没有吞任何东西，是本仓自己把门槛设成了 `error`。而且不止一处。**

### 根因 1：日志开关关着时，两个 transport 的级别都被钉在 `error`

`src/main/utils/logger.ts` 的 `initLogger(enabled, level)`：

- `log.initialize()` 之后执行 `Object.assign(console, log.functions)` —— **主进程里的 `console.warn` 就是 `log.warn`**，`console.log` 就是 `log.info`。仓库里 `WorkerManager.ts:2381`、`MainWindow.ts:255` 那两条「electron-log silences lower levels」的注释，描述的是现象，归因错了。
- `enabled` 为真时两个 transport 用用户选的级别；为假时（改动前）**file 与 console 都设成 `error`**。
- `src/main/index.ts:391` 读设置：`loggingEnabled` 默认 **false**，渲染层 store 的默认值（`stores/settings/index.ts:207`）也是 false。也就是说**出厂状态下主进程的每一条 warn / info 都在进文件之前被丢掉**。

实测佐证（开发机现有日志，未改任何设置）：

```
logs/aiclient-2026-09-17.log  级别直方图： 335 × [error]，warn/info 零条
logs/main.log                 级别直方图： 157 × [info]，且全部是 'Shared state paths'
~/.pilab/jyw-ai-client-dev/settings.json → loggingEnabled=false, logLevel='info'
```

顺带澄清一条点验里的困惑：**`main.log` 不是主日志**。`resolvePathFn` 把文件改成了按天日志，`main.log` 里只剩 `initLogger` 执行**之前**那几行（每次启动一条 `Shared state paths`）。「main.log 全程 0 行」是正常的，要看的是 `logs/aiclient-YYYY-MM-DD.log`。本记录下文说「落 main.log」都指这份按天日志。

### 根因 2：两个可注入 log sink 在生产里根本没接

- `ScratchWorkspaceService` 的 `this.log` 默认 `() => undefined`，而生产单例 `new ScratchWorkspaceService()` 不传 —— 所以 D14 引用的 `[scratch] failed to remove` 在真机上**连 electron-log 都到不了**，不只是级别问题。
- `WorkerManager` 的 `this.log` 同样默认 no-op，生产单例（`WorkerManager.ts:3111` 一带）也不传。这就是 `dumpWorkerStderr` 要用 `console.error` 的原因。

### 选型：`warn` 还是 `error`？两个都不选，选「把 file 门槛降到 info、console 降到 warn」

任务给的两个候选是「关键路径改 `log.warn` + file 调到 warn」或「改 `log.error`」。实测后两个都不够：

| 方案 | 新增落盘的既有调用点 | D4 | D10 成功 42 次 | D14 三步 |
|---|---|---|---|---|
| 维持 `error` | 0 | ✗ | ✗ | ✗ |
| file 调到 `warn` | 80 处 `console.warn` | ✓ | 只有失败那 2 条 | ✗ |
| **file 调到 `info`（采用）** | 上面 80 处 + 22 处 info | ✓ | ✓ | ✓ |
| 一律改 `error` | 0 | ✓ | ✓ | ✓（但把成功当错误记） |

选 `info` 的理由，按「既有日志量影响」实测：主进程（`src/main` + `src/agent-host` + `src/shared`，去掉测试）共 **80 个 `console.warn`、22 个 info 级调用点**。22 个里 20 个一次启动最多打一次；唯一会连打的是 `index.ts:485/500/525/526` 的 `[local-image]`（每渲染一张图 2～4 行）。按天日志有 10 MB 轮转 + 7 天清理，增量按数十 KB/天估。

不选「把成功路径记成 warn 去够门槛」：那是靠谎报严重程度换行数，warn 通道一旦塞满例行成功就没人看了。console 留在 `warn`，是为了不让 `[local-image]` 这类噪声灌进开发者终端和 dev.js 抓的 stdout；**文件是运维记录，终端是开发视图**，两条门槛不同是有意的。

用户把开关打开后的行为**完全没变**（仍是两个 transport 都用用户选的级别，含 debug）。

### ① `CredentialVault.ts` — JSON.parse 报错回显文件原文

`markInvalidated` 里 `console.warn(…, error)` 把 `SyntaxError` 整个交给 electron-log。V8 在这类报错里会引用**出错位置附近约 10 个字符的原文**，而保险库存在 `enc:'none'` 明文形态，三者叠加就是明文凭据片段落盘。实测确认这条路是通的（反向验证那次判红的 received 行就是证据）：

```
[CredentialVault] markInvalidated: existing vault is not valid JSON SyntaxError: Unexpected token 's', "sk-ant-pla"... is not valid JSON
```

改法：新增本地 `parseFailureNote(error, bytes)`（+17 行），只记**错误类型 + 读到多少字节**，改成单参数模板串。截断文件与乱码文件仍然分得开，而这两个量都带不出秘密。

### ② `src/main/index.ts:525-526` — `[local-image]` 每图两行裸路径

（任务书写的是 `services/piModelConfig/index.ts:525-526`，该文件只有 327 行；按审阅原文与「每图两行」的特征定位到 `src/main/index.ts` 的 `local-image` 协议处理器，即审阅建议③那两行。）

两行都是 `console.log` = `info`，门槛降下来之后每渲染一张图就往按天日志里写两条绝对路径。改成 `console.debug`：低于 `DISABLED_FILE_LEVEL`，开关关着时一行不落盘；用户把日志开到 `debug` 时照旧可见。没有选「过 T042 脱敏」，因为这里的问题一半是量（准热路径），脱敏解决不了。

### ③ `ScratchWorkspaceService.ts:271` — 第二参数绕过脱敏

`console.warn(\`… ${redactStderrLine(target)}:\`, error)` 第一个参数脱敏了，第二个 `error` 原样；electron-log 把每个参数都序列化写盘，而 `rm` 抛出的 fs 错误自己就带未折叠的绝对路径。改成单参数：新增 `describeError()`（把 Error 压成一句），整句过 `sanitizeStderrLine`。

### ④ 预算拒绝那行日志补码前缀（D4 复验的毛边）

真机上那行是 `turn failed: session exceeds the configured size budget`，**没有码**，而 T066 的日志点表格写的是 `turn failed: <code: message>`。根因：带码的那条走 `agent-loop/index.ts` run() 的 catch（T062 的 `thrownRunErrorText` 在正文前加了码），预算拒绝走的是 `RunProjection.finish`，它只取 `result.error.message`，把手边现成的 `result.error.code` 丢了。

改法**没有**把码拼进正文：`payload.error` 是渲染层 `session.runtimeError` / `lastError` 直接显示的那句（`MessageTimeline.tsx:251`、`ChatComposer.tsx:520`），给 provider 的 503 前面加个 `stop_error:` 是更坏的交易。改成码**并排**：

- `src/shared/types/runtimeEvents.ts`：`SessionTerminalEvent.payload` 加可选 `errorCode`；
- `src/runtime/events/projector.ts` `finish()`：有 error 就同时发 `error` 与 `errorCode`；
- `src/main/services/agent-host/WorkerManager.ts` 日志行：有码且正文没以该码开头时才前缀，所以抛出路径（正文已带码）不会印成 `model_not_in_catalog: model_not_in_catalog: …`。
