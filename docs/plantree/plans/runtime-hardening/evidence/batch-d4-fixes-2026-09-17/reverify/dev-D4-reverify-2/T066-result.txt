[② 保险库解析错误不回显内容]
  造法：把 vault.json 换成 `{sk-ant-plaintext-9f3aSECRET, "version": 2}`（44 字节，
  第一个 token 就是一段像密钥的明文），再用 dev-only 的 `auth:devMarkInvalidated` 走
  AuthStateService.markRejected() → CredentialVault.markInvalidated()。

    [2026-09-17 15:26:46.218] [warn]  [CredentialVault] markInvalidated: existing vault is not valid JSON (SyntaxError, 44 bytes read)

  只有错误类型与读到的字节数。整段日志里 grep 'sk-ant' / 'SECRET' / 'plaintext' = **0 次**。
  （V8 在这类 SyntaxError 里会引用出错位置附近约 10 个字符的原文，正是回炉要堵的那条。）
  vault 随后按字节还原。

[③ scratch 删除失败行脱敏]
  造法：建出 ~/JYWAI/temporary/unbound-sessions/ 并把它的父目录 chmod 500，
  于是 wipeAll() 的 rm 会 EACCES；启动时的 sweepScratchWorkspacesOnStartup 触发。

    [2026-09-17 15:35:01.222] [warn]  [scratch] Failed to remove ~/JYWAI/temporary/unbound-sessions: Error: EACCES: permission denied, rmdir '~/JYWAI/temporary/unbound-sessions'

  一条 warn、**一个参数**（没有第二个被 electron-log 单独序列化的 Error 对象），
  路径与 fs 错误里那份路径**都**折成了 `~`：整行 grep '/home/ai' = **0 次**，
  而失败原因（EACCES / rmdir）仍然读得出来。目录与权限随后还原。

  ⚠️ 顺带一条观察：dev.js 收到 SIGTERM 后走的退出路径**没有**跑到 wipeAll（退出那一侧一条 scratch 日志都没有），
  这条 warn 是下一次启动的 sweep 打的。不影响判据，但说明「退出时清 scratch」在 SIGTERM 下不生效。
