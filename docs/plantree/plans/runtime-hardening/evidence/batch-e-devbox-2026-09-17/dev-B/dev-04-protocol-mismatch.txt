--- 怎么做到「只改一侧」（dev 模式的关键事实）
PiWorkerProcess.ts:30-34 resolvePiWorkerEntryPath()：
  打包态  -> <resourcesPath>/agent-host/worker.js
  未打包  -> <appPath>/src/agent-host/worker.ts        ← dev 模式走这条
PiWorkerProcess.ts:94-99：utilityProcess.fork(entryPath, [], { execArgv: ['--experimental-strip-types'] })
=> dev 模式下 worker 每次 fork 都从磁盘现读 TypeScript 源码，out-agent-host/worker.js 根本不参与。
   worker.ts:8-13 用相对路径 import '../shared/types/workerRpc.ts'，也就是现读 src/shared/types/workerRpc.ts。
Main 侧则是 electron-vite 在 dev 启动时把同一常量打进 out/main/index.js，之后不再读源码。

实测确认 electron-vite dev 不会因为改 src/ 下的文件重建 main 或重启 Electron：
  改常量后等 25 s，out/main/index.js 的 mtime 仍是 07:17，Electron pid 385303 未重启，dev 日志零新增。
所以制造不匹配只要一步：**应用先起好，再把源码常量 1 改成 2**。
