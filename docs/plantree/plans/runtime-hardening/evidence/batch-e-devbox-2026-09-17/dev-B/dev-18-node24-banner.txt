--- 为什么造不出来（读码确认，两层都断了）
第一层：**没有任何生产代码调用 resolveNode24Runtime。**
  grep -ran 'resolveNode24Runtime|REQUIRED_NODE_MAJOR' src/ 的命中只有三处：
    NodeRuntimeResolver.ts（定义本身）
    agent-host/index.ts（只是 re-export）
    __tests__/NodeRuntimeResolver.test.ts（单测）
  也就是说 NodeRuntimeResolver.ts:123 那句
    "No Node 24 runtime found. Set AICLIENT_NODE24_PATH or install Node 24."
  在产品运行时永远不会被生成。原因合理：P6 之后 worker 跑在 Electron 自己的 utilityProcess 里
  （PiWorkerProcess.ts:94），根本不需要外部 Node 24。
第二层：**就算这条错误真的冒出来，渲染层也不会把它变成「可操作提示」。**
  hostStatus.ts:264 的 isNode24ResolutionFailure 同样只被自己的单测引用；
  真正决定横幅长什么样的 describeHostStatus（hostStatus.ts:92-122）压根没调它——
  state=error 时它只给「lastFatalError 原文 + 'Press Retry to reinitialise the Pi session service' + Retry 按钮」。
  而 HostStatusBanner.tsx:8-12 的文档注释仍写着自己「覆盖 Node 24 missing actionable guidance（AICLIENT_NODE24_PATH）」。

--- 结论
判据问的「用户能否看到可操作的提示」在本机得到的答案是：**造不出这个失败，也就没有提示**。
AICLIENT_NODE24_PATH 现在是一个没人读的环境变量（只有 NodeRuntimeResolver.ts:70 读它，而那个函数没人调），
dev.env 里还留着它和一段解释注释；HostStatusBanner 的注释也还在承诺一个已经不存在的分支。
