== (2') the piLeaf trap (first attempt, recorded because it changes how this row must be built) ==
The first fixture had NO piLeaf. Selecting it produced NO error card at all: the timeline said
"No messages yet." and the worker came up bound. Cause is by design, not a fault:
src/main/ipc/chat.ts:449 calls isUnwrittenPiSession(row) (chat.ts:67-74), which returns true when
the row has a runtimeIdentity, NO piLeaf, and the file does not stat — i.e. "a phantom identity
for a session pi never wrote". That branch takes the "repair, not resume" path: it clears the
runtimeIdentity and calls createSession, and because the worker names a new file
<agentDir>/sessions/<logicalSessionId>.jsonl (nativeWorkerRuntime.ts:994-996) the brand-new file
lands on exactly the same path. Observed: a fresh 188-byte header with a NEW session uuid
(83ca5185-…), created at the moment of the click.
=> a fixture for jsonl_not_found MUST carry piLeaf, otherwise it exercises the repair path.
