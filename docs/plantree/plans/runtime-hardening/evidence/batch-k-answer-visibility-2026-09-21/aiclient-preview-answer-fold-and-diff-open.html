二、点文件后在哪儿看 diff —— 三种方案

A1 · 复用现有 diff 页（你选的）

中列 成本低

点条目 → 中列开一个 git-diff:// 页签（和 Git 面板里点文件是同一页）。看的是文件此刻相对 git HEAD 的全部差异，包含 agent 之后的所有编辑。代价：中列被占用，聊天区让位（就是 diffTabActive 的现有行为）。

我的建议（你可以不采纳）：
  1. 正文规则那条优先做，它是你唯一报的「内容不见了」，与另外两件互不干扰。
  2. diff 落点选 A0 + A1 的组合：点条目在面板里就地展开（A0，你要的即时反馈），条目右侧那个「打开文件」图标走 A1 开中列 diff 页（要全貌时用）。两者不冲突，因为它们回答的是不同问题。
  3. A2 建议不做：它是唯一需要新组件的方案，而它能回答的问题（那一次改了什么）在 A0 展开的 diff 里已经能看个大概。
