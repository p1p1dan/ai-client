## 2. F3 根因的回填模板

在 [bash-carrier-decision.md](../../../../../plans/2026-09-09-bash-carrier-decision.md) 第 6 节表的「现场结果」列逐行填，然后在第 7 节下面补一段：

```
## 9. 现场拍板（<日期>，加密 Windows，包 <SHA256 前 8 位>）

- R0：实际选中的 bash 映像 = <绝对路径>；父进程链 = <链>。（证据 win-16-*）
- R1/E5：GUI read 与 bash 读同一受策略文件 → <明文 / 密文 / Bad file descriptor>。（enc-20-*）
- R2：bash 里调随包 node 读同一文件 → <明文 / 密文>，SHA256 <…>。（enc-07-r2-*）
- R3：随包 node 改名副本再读 → <明文 / 密文>，SHA256 <…>。（enc-07-r3-*）
- 容器头存证：非白名单进程读到 %TSD-Header-###%，<是 / 否>。（enc-07-sha256.txt）

**结论：选 <A / B / C>。** 理由：<一句，按第 5 节的映射>。
```

**不能签的三种情形**（照 test.12 的教训，宁可记 ⛔ 也不要凑一个结论）：

1. R0 只拿到 shell 自报并经 `cygpath` 转换的 MSYS 路径，没有独立的进程映像 / 父进程证据 → **前提不成立，整组不能签**；
2. 目标文件本来就没有 TSD 头 → 分不清「本来就是明文」和「透明解密」，R2/R3 **不能据此拍板放行维度**；
3. R3 的复制改名同时改变了目录与文件名 → 没有单独隔离「改名」这一个变量，要么补一次「同目录仅改名」的对照，要么在结论里写明这一点。
