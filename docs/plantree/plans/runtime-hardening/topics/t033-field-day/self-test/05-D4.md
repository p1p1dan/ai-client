## T060 临时根设置读不到 + 未绑定会话运行中消失 【绿】

**这一项是什么**：修的是两个缺陷——① 设置页的「保存位置」以前**根本读不到**（主进程读的是 `settings.json` 的顶层，用户改的字段其实在下一层 `aiclient-settings.state` 里），于是临时对话的目录永远落在默认根；② 跑过一轮的临时对话，只要工作区树一变（加/删仓库）就被当孤儿从侧栏丢出去。开发机已验过：改设置后新建的临时对话落在新根、重启后索引行指向新根、工作区树变化后 16 条未绑定会话一条没少。**上机补的是落盘那一步和界面那一步**，共八格。

**准备**

```powershell
Get-Content "$stateRoot\settings.json" | Select-String 'defaultTemporaryPath'   # 记下改之前的值
New-Item -ItemType Directory -Force -Path 'C:\t033\temp-new' | Out-Null
dir "$env:USERPROFILE\JYWAI\temporary" -ErrorAction SilentlyContinue           # 旧（默认）根
```

**操作**

1. **DEV-2-a**：起应用，设置 → 通用 → 临时会话 → 「保存位置」填 `C:\t033\temp-new`，保存。**保持应用开着**，新建一条临时对话并发一句话。然后两个根各看一眼：

## T061 预算拒绝后 store 中毒 + 附件名不落盘 【绿】

**这一项是什么**：以前只要一条消息撞上会话文件的 32 MiB 总预算被拒，**整个会话的写队列就永远卡住**——之后打一句纯文本点发送，输入框被清空、时间线什么都不出、网关收不到请求，看起来就是「点了没反应」。另一半是落盘的图片块里从来不存文件名，重开会话后附件只显示 `image/png`。开发机两轮都已验过。**上机要看的是打包态下这两件事是不是同样成立**，外加一条开发机做不了的：真 `pi-messages` provider 上剥键之后仍然正常。

**准备**

1. 造两张图（用真实 PNG 打底、尾部补随机字节顶体积，PNG 解码器会忽略 IEND 之后的数据）：

```powershell
New-Item -ItemType Directory -Force -Path C:\t033\images | Out-Null
$seed = 'C:\t033\field-samples\enc12\enc12-tiny.png'      # 样本包里的 1×1 真 PNG
function New-PaddedPng([string]$out, [int]$size) {
  $head = [IO.File]::ReadAllBytes($seed)
  $pad  = New-Object byte[] ($size - $head.Length)
  (New-Object Random 42).NextBytes($pad)
  $fs = [IO.File]::Create($out); $fs.Write($head,0,$head.Length); $fs.Write($pad,0,$pad.Length); $fs.Close()
}
New-PaddedPng 'C:\t033\images\big-5mib.png'   5240000     # 略小于 5 MiB 的单图上限
New-PaddedPng 'C:\t033\images\small-1mib.png' 1050000
Get-ChildItem C:\t033\images | Select-Object Name, Length
```

2. **新建一个专用会话**做这一项（会把它顶到 32 MiB，别拿有用的会话做）。

**操作**

1. **①** 连发 4 条消息，每条挂 `big-5mib.png` + `small-1mib.png` 两张图（⊕ 按钮走原生文件对话框，手点即可）。每发一条之后看一次会话文件体积：

```powershell
Get-ChildItem "$agentDir\sessions" -Recurse -Filter *.jsonl |
  Sort-Object LastWriteTime -Descending | Select-Object -First 1 FullName, Length
```

顶到 ≈31.9 MiB 之后发第 5 条（同样两张图），它应当被拒。**然后把附件清掉、打一句纯文本、点发送。**
2. **②** 第 5 条被拒时，composer 上方的红块截图。
3. **③** 发一条带这两张图的消息，**退出应用、重新打开、点回同一条会话**，看时间线上那两个附件片显示的是什么。
4. **④** 如果你配置的 provider 里有一个 **API 风格是 `pi-messages`** 的服务，用它发一张图，看网关正常不正常。没有这种服务就跳过这一格并记 🚫。

**看什么**

- **① 通过**：那句纯文本**正常出现在时间线上**，会话文件跟着长了几百字节（再看一次 `Length`），模型那边也真的收到了。**不通过**：输入框被清空但时间线什么都不出、文件不长——**静默丢弃判负**，这正是这次修的东西。
  - 判据来自 checklist 5.1 对 DEV-33 的更正：「4 条『1 张 ≈5 MiB + 1 张 ≈1 MiB』后文件停在 32 MiB 内、第 5 条被拒、重开正常」，并且「被拒后能否继续发纯文本」已从「另记」升格为判据分句。
  - **模型侧报错不影响这一格**：要的是会话文件被顶到预算上限、第 5 条被落盘那一步拒掉。开发机还记过一条：预算拒绝这条路上**模型其实先被调用了一次**才在落盘那步被拒，看到网关计数增加不用当缺陷。
- **② 通过**：红块 `Error: session exceeds the configured size budget`（或其中文/等价形态）**仍在**——确认 ① 没有把它顺手抹掉。
- **③ 通过**：重开后两个附件片**显示文件名** `big-5mib.png` / `small-1mib.png`，不是 `image/png`。**注意**：只对修复之后新写入的消息有效；老会话文件里的块上没有文件名字段，回放退回 media type 是预期，别当没修好。
- **④ 通过**：网关在**没有**未知键的情况下正常返回（这格验的不是「会不会 400」，而是「剥干净之后仍然正常」）。

**记录**：`d4-T061-01-fifth-rejected.png`、`d4-T061-02-plaintext-after-reject.png`、`d4-T061-03-attachment-names-after-restart.png`、`d4-T061-session-bytes.txt`（每一步的文件体积）、`d4-T061-04-pi-messages.png`（做了才有）。

## T062 模型目录两侧口径 + 模型缺失中文覆盖层 【绿】

**这一项是什么**：以前模型选择器读的是磁盘上的 `models.json`，而 worker 拿的是主进程用凭据库现组的内存目录——**两边看的根本不是同一份文档**，于是出现「列得出、发不出」。另一半是会话记录的模型已经不在目录里时，用户看到的是一行英文 `Error: no model "…" in the catalog`，而不是设计好的中文卡。开发机第二轮已验过中文卡出得来。**上机要看的是打包态下这张卡还在不在、诊断行落没落进按天日志、以及凭据库读不出来时两侧会不会一起回落读盘。**

**准备**：起应用，界面语言中文，随便打开一个已有的会话。

**操作**

1. **①（造模型缺失）**。开 DevTools（`Ctrl+Alt+I`）→ Console，先拿到当前会话的 id：

```js
JSON.parse(localStorage.getItem('aiclient-agent-sessions')).sessions.map(s => ({ id: s.id, title: s.title }))
```

挑出你正打开那条的 `id`，然后给它钉一个不存在的模型：

```js
const k = 'aiclient:chat:session-models';
const m = JSON.parse(localStorage.getItem(k) || '{}');
m['<上面那个 id>'] = 'vllmproxy-old/claude-does-not-exist';
localStorage.setItem(k, JSON.stringify(m));
```

回到界面，在这个会话里**发一句话**。截 composer 上方那块，存 `d4-T062-overlay.png`；composer 底下那条状态条也截进去。
2. **②（诊断行）**：

```powershell
Select-String -Path $today, "$logDir\main.log" -Pattern 'pi-models|dropped' |
  Out-File "$ev\d4-T062-dropped-log.txt" -Encoding UTF8
```

3. **③（凭据库读不出来）**：Windows 上没有「锁钥匙串」这个动作，用**把保险库文件读不了**代替：

```powershell
Copy-Item "$stateRoot\credentials\vault.json" "$ev\vault.json.bak"
icacls "$stateRoot\credentials\vault.json" /deny "$env:USERNAME:(R)"
# 起应用 → 打开模型选择器截图 → 关掉应用
icacls "$stateRoot\credentials\vault.json" /remove:d "$env:USERNAME"
Get-FileHash -Algorithm SHA256 "$stateRoot\credentials\vault.json", "$ev\vault.json.bak"   # 两个哈希必须一致
```

**看什么**

- **① 通过**：出的是 H/21 那张**中文卡**——标题「本应用没有这个模型」、正文「这个会话记录的模型不在本应用的模型目录里…」、按钮「去 Pi 设置补上模型」，卡里还保留一行等宽的原始诊断（里面点名那个模型）。composer 底下的状态条**也应当是中文提示**。点那个按钮应当跳到「设置 · Pi」。
  **不通过**：出的是英文 `Error: no model "vllmproxy-old/claude-does-not-exist" in the catalog (1 available)` 这种裸文本，或者状态条是英文词典键。
  判据用 checklist 5.1 对 DEV-32 的更正版，两句都要满足：「GUI 侧出 H/21 中文覆盖层」+「TUI 侧出 pi 可读提示」。TUI 那半句顺手验一下（同一会话点 TUI 开关，看 pi 自己给的提示是不是能读懂）。
- **② 通过**：`d4-T062-dropped-log.txt` 里有 `[pi-models] models.json holds providers no session can use { dropped: … }` 这样一行。**注意这条走 `console.info`**，在 `main.log` 里可能看不见，要去按天日志里找。**两个文件都找不到就记「未找到」并写明查了哪两个文件**——别当成没记，也别当成不通过（这条要并进可观测性小修包）。
- **③ 通过**：模型选择器**两侧都回落读盘**、内容与改之前一致，日志里没有新的 `dropped` 行。**不通过**：选择器变空、或应用报错起不来。**做不成**：`icacls` 拒绝不生效（管理员账户常见），记 🚫 并写明「Windows 上无等价的『钥匙串锁定』动作，`icacls /deny` 对本账户无效」。

**记录**：`d4-T062-overlay.png`、`d4-T062-dropped-log.txt`、`d4-T062-vault-locked-selector.png`。

## T063 兼容根子代理定义「编辑后删不掉」 【绿】

**这一项是什么**：子代理定义按「主目录 > 兼容根 > 内置」合并读，**但写一律落主目录**——于是「编辑」等于在主目录复制一份副本再改，「删除」只删得掉那份副本，兼容根里的原件带着**编辑前的旧内容**又浮回列表。这次改成编辑写回来源文件、删除把两个根里的同名文件一起清掉。开发机已验过四个时点全对。**界面侧一行代码都没改，所以必须真的走一遍 GUI 才算收口**，而且 Windows 上兼容根路径不一样：`%USERPROFILE%\.agents\subagents`。

**准备**

```powershell
New-Item -ItemType Directory -Force -Path $compat | Out-Null
$md = @'
---
name: probe-compat
description: ORIGINAL
tools: read, grep
permission: ask
maxTurns: 3
---
T033 用的一次性探针子代理，别真派它干活。
'@
[System.IO.File]::WriteAllText("$compat\probe-compat.md", $md, (New-Object System.Text.UTF8Encoding($false)))
Test-Path "$agentDir\subagents\probe-compat.md"     # 必须是 False：主目录不能有同名文件
Get-FileHash -Algorithm SHA256 "$compat\probe-compat.md" | Out-File "$ev\d4-T063-hashes.txt" -Encoding UTF8
```

**操作**

1. 起应用 → 设置页 → 子代理列表，找到 `probe-compat` 这一行，点「在文件夹中显示」。

## T064 bootstrap 失败后的用户输入与空壳索引行 【绿】

**这一项是什么**：worker 起不来（bootstrap 失败）时，用户那条消息其实没丢——它躺在「重试」按钮的快照里，但输入框是空的、时间线是空的，用户看不出来。另一半是索引里会留下一行 `title=""` 的空壳。这次改成：失败后把原文和附件**搬回输入框**；如果用户在等待期间又打了字（此时不能覆盖他的输入），就改成**武装 ↺ 重试按钮**。开发机两轮正反都验过。**上机要看的是打包态下这两条臂**——审阅明确说过**不能只做一条**：只看一条会把回落误判成「↺ 又回来了 = 修坏了」。

**准备（打包态怎么制造 bootstrap 失败）**

开发机的造法是改源码常量，**打包态做不到**（代码在 asar 里）。改用这条只用产品功能的路：给会话配一个**握手很慢的 MCP 服务器**把 bootstrap 拖长到几十秒，在这个窗口里**强杀 worker 进程**，bootstrap 就会失败。

```powershell
# 样本包里现成的慢启动 MCP 服务器
$mcp = @'
{
  "mcpServers": {
    "slow-probe": {
      "command": "REPLACE_NODE",
      "args": ["C:\\t033\\field-samples\\slow-mcp-server.mjs", "--delay-ms", "40000"],
      "env": {}
    }
  }
}
'@
$mcp = $mcp.Replace('REPLACE_NODE', $node.Replace('\','\\'))
[System.IO.File]::WriteAllText("$agentDir\mcp.json", $mcp, (New-Object System.Text.UTF8Encoding($false)))
(Get-Content $idx -Raw | ConvertFrom-Json).Count | Out-File "$ev\d4-T064-index-count.txt" -Encoding UTF8
```

**操作**

1. **正臂**：起应用 → **新建**一个对话 → 打一句话、挂一张图 → 点发送 → **全程不碰输入框**。发送后 5～10 秒，找到并强杀这个会话的 worker：

```powershell
Get-CimInstance Win32_Process -Filter "Name='node.exe'" | Select-Object ProcessId, CommandLine | Format-List
taskkill /PID <那个 worker 的 pid> /F
```

等界面报失败，截 `d4-T064-legA-draft-restored.png`。

2. **反臂**：同样再来一次，但这次**在等待期间往输入框再打一个字**，然后再强杀 worker。等失败，截 `d4-T064-legB-retry-armed.png`；把鼠标停在右下角那个 ↺ 上，把它的悬停文字也截进去。如果 ↺ 能点，点一次看看能不能把原文和那张图一起重发成功。
3. 两臂都做完后再数一次索引条目：

```powershell
(Get-Content $idx -Raw | ConvertFrom-Json).Count >> "$ev\d4-T064-index-count.txt"
(Get-Content $idx -Raw | ConvertFrom-Json) | Where-Object { -not $_.title } |
  Select-Object sessionId, title, workspacePath >> "$ev\d4-T064-index-count.txt"
```

**看什么**

- **正臂通过**：那句话**回到输入框**、附件也回到附件条、错误卡可见、右下角**没有** ↺、索引条目数**不增**。
- **反臂通过**：用户自己打的那个字**没被覆盖**；↺ **出现**，它的 `aria-label` / 悬停文字里**带附件计数**（形如 `Retry last message (1 file)`——这串仍是英文，是**已知未改**的一条，不算新缺陷）；点 ↺ 能端到端把原文和图重发成功。
- **不通过**：正臂里 ↺ 出现了（说明没走「搬回草稿」那条）、或输入框是空的（说明消息真的丢了）；反臂里用户打的字被覆盖、或者 ↺ 没出现（那意味着文本和附件在任何地方都不存在了——这正是一审判 blocking 的那个形态）。
- **索引那一半**：条目数不增、没有新的 `title` 为空的行。上次开发机留在机器上的那行历史空壳**不会**被这次修复自动清掉，看到别当没修好（这台 Windows 机上大概率没有那行）。
- **造法失败怎么办**：如果强杀 worker 之后应用只是静静重连、没有出现失败态，说明这条造法在打包态没打中同一条分支——记 ⛔ 并写明「未能制造出 bootstrap 失败，实际现象是 X」，**不要拿别的失败（例如模型报错）冒充**。

**记录**：`d4-T064-legA-draft-restored.png`、`d4-T064-legB-retry-armed.png`、`d4-T064-index-count.txt`。

**收尾**：`Remove-Item "$agentDir\mcp.json"`。

## T065 跨窗口同会话互斥 / 挂起恢复重绘 【绿】

**这一项是什么**：三件事。① D18：两个窗口能同时把**同一个会话**开进内嵌终端，两个 pi 各写各的，一份会话文件静默分叉成两支，界面全程零提示——这次加了按会话归属窗口的互斥 + 中文拒绝提示。② D17：TUI 挂起再恢复时整屏空白，要手工 resize 才救得回来——这次改成恢复时让 PTY 走两次真实尺寸跃迁逼 pi 重绘；开发机第二轮是 **27 次切换里 26 次整屏重绘、1 次仍空白（约 4%）**。③ 关窗文案：一个主窗 + 一个预览窗时关主窗，以前会说「应用会在你其他的窗口里继续运行」，可实际上应用真的退了。**上机要看的是 Windows / ConPTY 上 D17 的概率是多少**，以及 D18 的两条路在打包态还拒不拒。

- **已知未改、看到别记成新缺陷**：`Wait for this turn to finish` / `Could not start the Pi TUI` / `Could not reload this chat` 这三条 toast、以及 composer 上 `Error: <原文>` 那条兜底，中文界面下仍是英文。

## T068 字重 / header chip 【绿】

**这一项是什么**：两张卡（权限卡、问答卡）的标题层级以前全靠字重 500（`font-medium`），**而 Win10 常见的 Segoe UI 静态字族没有 500 这一档，CSS 会回落到 400**——于是在 Windows 上标题和正文一样粗，层级消失。这次把段头与标题改成 600。**这条判据只有在 Win10 上才成立**，开发机 Linux 只能给对照口径，所以这一格是**必须在这台机器上做的那一格**。另外问答卡新增了 header chip（以前声明了字段但全链路没人渲染）。

**准备**：界面语言中文；起应用；开 DevTools（`Ctrl+Alt+I`）。

```js
copy(JSON.stringify([...document.querySelectorAll('[class*="border-destructive"], [class*="border-destructive"] *')]
```

## 附录 A · 假 503 网关（T066 ② 与 T067 DEV-24 共用）

用你自己的真 provider 造不出稳定的 503，所以起一个本地只回 503 的小网关，把它配成应用里的一个自定义 AI 服务。

**第一步：起网关**（另开一个 PowerShell 窗口，跑完别关）

```powershell
$js = @'
import { createServer } from 'node:http';
createServer((req, res) => {
  let body = '';
  req.on('data', (c) => { body += c; });
  req.on('end', () => {
    process.stderr.write('[fake503] ' + req.method + ' ' + req.url + '\n');
    res.writeHead(503, { 'content-type': 'application/json' });
    res.end(JSON.stringify({ type: 'error', error: { type: 'overloaded_error', message: 'No available accounts' } }));
  });
}).listen(18080, '127.0.0.1', () => process.stderr.write('[fake503] listening on 127.0.0.1:18080\n'));
'@
[System.IO.File]::WriteAllText('C:\t033\fake503.mjs', $js, (New-Object System.Text.UTF8Encoding($false)))
& $node C:\t033\fake503.mjs
```

**第二步：配成一个自定义服务**。先试**界面路**：设置 → AI services → 新增，Service 选 Custom、Name 随便、Service URL 填 `http://127.0.0.1:18080`、API style 选 `anthropic-messages`、API key 填 `fake-key`，保存。**「Fetch models」会失败**（网关只会回 503），所以模型列表是空的，选不到模型——这时改走**文件路**：
