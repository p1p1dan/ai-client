# 废案 — 试过、废掉、以及为什么

> 2026-08-27 单日批（S2 · S0' codex 侧 · S0'-b · S3+D64 · settingSources）里被否掉的方案。
> 只记「废了什么 + 为什么废 + 详细取证在哪」，不复制细节。
>
> 存在的理由：这些方案里有一半**看起来完全合理**，下一个人很可能再想一遍。
> 记下来是为了让他直接跳到「已经试过，是这么死的」。

## 一、设计层面被否掉的

### 1. 给 codex 用「扩大投影范围」或「直写用户目录」修配置树丢失

**废因**：[E1](../../../../plans/2026-08-26-s0-spikes/e1-codex-no-home.md) 实测 `codex app-server`
支持 `-c` 覆盖，凭据 / provider / 安全档位三样**都能不落文件**注入 ⇒ 隔离目录根本不必要，
两个退化方案一起作废。**根因是定位错了**：投影方案的成本随 agent 家数线性增长。

### 2. 逐条压制用户的 codex MCP 配置

**废因**：`-c mcp_servers={}` 整表清空**无效**（E1 R9），只有
`-c mcp_servers.<name>.enabled=false` 逐条有效（R10）—— 而逐条需要**先读用户配置枚举名字**，
等于把刚拿掉的「读写用户配置」语义换个形式请回来。拍板改为全部继承（D61）。

### 3. 给应用内终端补回公司网关（codex）

**废因**：终端原先靠「`CODEX_HOME` 指向托管目录 + key」两件套，而**这两半拆不开** ——
key 单独给毫无意义（用户自己的配置不会用我们那个变量名），而 **codex 没有任何环境变量能改
`base_url`**，provider 表只存在于配置文件里。与 Claude 侧的不对称不是疏漏：
`ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN` 是 Claude CLI 直接读的名字，codex 没有对应物。
拍板接受（D66）。

### 4. 用 `managedSettings: { permissions: { ask: ['*'] } }` 把所有工具摁回权限卡

**曾经实现过并测通**（[取证 §D4](../../../../plans/2026-08-27-settingsources-spike/README.md)），
被用户当场推翻：**「配置文件里那份是什么就是什么样，我们为什么要去干涉它？」**

**废因**：那版实现**分不清两个来源** —— `~/.claude/settings.json` 是**用户自己写的**，
`<项目>/.claude/settings.json` 才是跟 git 来的。防后者的代价是推翻前者，
与 D60/D61「用户环境原样生效」直接冲突。
**支撑废弃的关键事实**：用户同一轮已接受**更大**的风险（仓库提交的 hooks 能跑任意命令，
连工具调用都不需要，取证 §F 实测），为**更小**的那个去覆盖用户自己的文件站不住。

**同时废掉的还有丙案**（用 `resolveSettings` 的 provenance 只挡仓库那份）——
技术上可行且已确认接口存在，但拍板取甲，未采纳。

### 5. 按工具名单收窄权限卡范围（`ask: ['Bash','Write','Edit']`）

**废因**：实测工具共 **29 个**，这个随口举的三个名单**会漏**——「访问网页」这类就漏在外面
（[取证 §H](../../../../plans/2026-08-27-settingsources-spike/README.md)）。
更根本的是：**手工名单会随 CLI 升级腐烂，且失效方向是「放行」** ——
新增的工具不在名单里就静默不弹卡。这是放弃它的直接原因，不是嫌麻烦。

### 6. `chmodSync` 保权限位（S2 迁移）

**废因**：变异杀不掉 —— `copyFileSync` **本身就带过权限位**。
已删除并留 `[实测]` 注释（换成 read+write 会红成 0o664 vs 0o600）。

## 二、探针本身翻过的车（方法论，比结论更容易重犯）

### A. 用一条**根本没匹配上**的规则，去证明「规则不起作用」

E2 B 组用 `rm` 做实验，得到「有免问规则和没有一样」，**差点写成「当初的理由不成立」**。
真相：报文写的是 `requested permissions to **edit**` —— `rm` 被归类成**按路径的文件编辑权限**，
`Bash(rm:*)` 从头到尾没参与。换成 `curl` 才拿到正确的相反结论。
**这是本轮最容易犯的错**，探针已删除，教训写进取证档 §B。

### B. 用一个**本来就自动放行**的命令做判别项

同一轮的第二个候选 `echo` —— 它在内置安全清单里，**没有免问规则也会跑**，分辨不了任何东西。

### C. 断言测的是**默认值**，不是**写入**

S3 的变异 Q7 一开始**存活**：「登录后 `getCredentialMode()` 返回 managed」看着对，
但键不存在时解析器本来就答 `managed` —— **默认值把写入盖住了**。改成直接读文件里的键才咬得住。

### D. 探针环境与生产不一致，失败点跑到被测点前面

三次：① E2 第一版把 provider 写进用户 `config.toml`，配置被拒后 provider 一起消失，
四个用例全超时，**测出来的什么都不是**；② settingSources 探针用系统 Node 22，
cli.js 的 `using` 声明直接 `SyntaxError`（必须 Node 24）；
③ 漏设 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`，第一发请求被后台调用吃掉，
真回合落到第二发，整组结果看起来像「工具从没被请求过」。

### E. 注释归因写错，被「杀不掉的变异」连揪两次

S0'-b 的位置正则：先归因给贪婪匹配、再归因给末尾锚点，两次都被变异证伪。
真相是 `:(\d+):(\d+): ` 这个**数字要求**本身在挡 Windows 盘符；
真正承重的是**惰性**路径组；末尾锚点确实冗余，注释里如实写明而不是给它编一个理由。

## 三、连带修掉的既有缺陷（不是本批引入的）

- **S1 的静态扫描有洞** —— 只匹配单引号开头，漏掉模板字面量里的
  `` `${homeDir}/.aiclient` ``。S1 自称「五处全部转常量」，实为六处。新扫描改为先剥注释再扫。
- **测试污染真实 home** —— 凭据离开 `<userData>` 后，只改 `<userData>` 不改 `$HOME` 的测试
  开始往开发者真实 home 写 vault，全量跑完留下 **96 个**临时目录。
  改为在边界上堵（`hermeticHome.ts` 给每个测试进程一次性 `$HOME`），而不是逐个打补丁。
