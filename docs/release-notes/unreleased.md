# PiLab Ai 1.0.3

本版主要改进运行中的可控性：回合进行中可以随时插话，Stop 一定能停下，长命令能看到进度；
同时修复读图、图片预览崩溃、子代理死循环等现场问题。

## 新功能

- **运行中插话（Ctrl+Enter）。** 回合进行中在输入框按 `Ctrl+Enter`，消息排在普通排队消息之前；
  当前这一步（模型这一轮输出及其工具调用）完成后回合收尾，插话随即作为下一条消息发出。
  正在执行的命令不会被中断；后台子代理仍在运行时插话也能及时送达。
- **分支栏。** 输入框上方的目标栏分为仓库、分支、运行位置三栏。分支栏列出仓库的全部分支，
  选中即执行真实的 `git checkout`；本对话正在运行、或同一目录下有其他对话在运行时锁定；
  切换失败时直接显示 git 的原始报错。
- **运行中的命令可展开查看。** 运行中的工具行可以点开查看完整命令，行尾显示「已耗时 / 超时上限」。
  计时从命令真正开始执行时算起，等待审批的时间不计入。
- **读取图片。** 模型的 read 工具支持 PNG / JPEG / GIF / WebP 图片。当前模型未声明支持图片输入时，
  粘贴图片后输入框会提示「模型看不到这张图」，不阻断发送。

## 问题修复

- **Stop 一定能停下。** 点 Stop 后回合在有限时间内收尾，停不下来时 10 秒内强制重启后台进程；
  停止过程中 Stop 按钮与 `Esc` 仍可用（强制停止）；发送中的请求可被 Stop 打断；
  结束对话后排队消息不再卡死；排队条上禁用的按钮不再误触发「取回编辑」。
- **失败卡「继续」改为重试上一轮。** 不再把上一条消息重复发送一次，失败的回复保留在旁支。
- **子代理工具死循环防护。** 模型在单条回复里反复调用同一子代理工具时，会在输出过程中被中断，
  被中断部分的调用一个都不执行，并显示「模型输出出现重复调用，已中断」，之后可直接继续发消息。
  如怀疑正常工作被误拦，可设置环境变量 `AICLIENT_RUNTIME_LOOP_GUARD=0` 后重启应用临时关闭。
- **图片 / PDF 预览。** 修复打开任意图片或 PDF 预览即整屏报错「Failed to construct 'URL'」的问题。
- **工作目录。** 系统提示词写明工作目录、平台与 shell，模型不再到 C 盘根目录寻找 `@` 引用的文件。
- 被 Stop 中止的命令显示「已停止」，不再显示为成功。
- 被中止或失败的回复，用量显示「本次消耗未知」，不再显示 0。
- 运行中发送 `/compact` 会提示等本轮结束后再压缩，不再没有任何反应。
- 回合输出过程中点开思考块或工具行，页面不再被自动滚走。
- 被拒绝或未执行的工具调用以灰色标注「已拒绝」「未执行」，不再显示为已完成。
- 被插话打断的回合重新打开后，「已工作」时长正确。
- 数据迁移的完成标记改为读回确认后才写入，避免迁移中途崩溃后仓库列表永远不再迁移。

## 体验调整

- 全站字号整体上调一档；已保存过的对话字号设置保持不变，不随之上调。
- 思考块默认折叠；被插话或 Stop 打断的回合，过程区默认展开，可手动收起。
- 分支列表不再为已合并分支查询 PR 状态，避免 `gh pr list` 超时。
